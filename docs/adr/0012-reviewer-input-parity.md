# ADR-0012：審查者輸入等價——把上下文可見性變成機器強制的性質

- **狀態**：已採用（Adopted）
- **日期**：2026-07-30
- **決策者**：專案維護者（依 doctor 8,196 則紅隊實跑事故）
- **相關**：ADR-0007（紅隊全抽）、ADR-0008（三層防錯）、
  [`references/reviewer-input-parity.md`](../../references/reviewer-input-parity.md)

## 背景（Context）

同一個失效模式已發生三次不同化身：

1. **圖題**：撰寫者附圖、純文字紅隊只有 `has_figure` 旗標 → 圖衍生內容被報成
   「無據增添／圖缺失」，**fix 率從真實約 18% 虛高到 43%**。
2. **承上題**：生成站切塊器帶了 `prev`（同卷前題），紅隊站切塊器沒帶。
   **對照實驗**（同一批題、同一個模型、只差一個欄位）：同 39 則各審一次，
   **判決翻轉 10 則＝26%，全部 `fix`→`pass`、零反向**——翻轉率即誤報率，不需估算；
   單向性證明機制的價值是移除系統性偏誤，不是讓紅隊變寬鬆。
3. **題幹說有圖但圖檔不存在**：兩邊都瞎 → 詳解成為**包裝成推理的猜測**，
   而結構 lint、答案錨、紅隊**全部通過**（紅隊也看不到那張不存在的圖）。

正名：**「審查者拿到的資訊少於撰寫者，於是把『我看不到』誤報成『內容錯』。」**
下游修復站會照著改，**把正確內容刪掉**——所以這類誤報比漏報更糟。

**根因不是 prompt 沒交代**，而是各站切塊器各自手寫、欄位對齊靠人記得。
先前兩次都是加一條 prompt 鐵則止血（「圖題鐵則」「承上題鐵則」），
但那意味著**每個新化身都要再加一條**，且都要先出事才會加。

## 決策（Decision）

把「上下文可見性」從隱性約定改為**宣告式、機器強制、發包前驗證**，四個零 token 機制：

1. **欄位可見性註冊表**（擋設計期）：單一 `FIELDS` 註冊表宣告每個欄位誰看得到；
   **鐵則——`kind="evidence"` 且撰寫者可見者，審查者必須可見，或同時宣告
   `degraded`（降階表示）＋`blind_policy`（盲區協議），否則 import／CI 即 raise。**
   各站 payload 由單一函式導出，紅隊 payload 結構上為生成 payload 的超集。
2. **源頭可審性 lint**（擋資料期，也擋「撰寫者自己也瞎」）：發包前檢查
   承上題無 `prev`／表格引用無表／題幹說有圖但無圖檔／圖檔未掛欄。
   🔴 **regex 調成高精確度低召回**——會誤報的預檢比沒有預檢更糟。
3. **物化 payload parity 斷言**（擋兩站不對齊）：比對**落盤後實際 payload** 的
   evidence hash，不信程式碼看起來對；fail-closed，失敗率過閾值中止整批。
4. **熔斷器**（擋未知化身）：首波批次回來即跑 finding lint，`gap_rate` 異常則暫停。

**圖片的盲區協議**（本質上給不了時）：生成站順手產 `figure_desc`（圖面客觀描述，
邊際成本約 2%）；紅隊視其為**前提非真相**，審「前提→結論」的推論鏈，
對前提本身有疑則記 `figure_desc_conflict` 路由視覺哨兵、**永不進 fix 站**。
**視覺哨兵仍是圖面正確性的唯一權威。**

**finding schema 加 `basis` ＋ `evidence_field`**：`content_error` 必填
`evidence_field` 且該欄位必須真的存在於該題 payload；引用不存在欄位者**自動降級為
`input_gap`**。分流確定性化，`gap_rate` 與 `fix_rate` 分帳（前者目標恆為 0，
>0 是工程 bug 警報而非品質訊號）。**fix 站的濾網裝在程式碼裡，不在 prompt 裡。**

## 考慮過的替代方案（Alternatives）

- **A. 每出一個化身就加一條 prompt 鐵則**：前兩次的做法。缺點是永遠落後一個事故，
  且鐵則本身會累積成沒人讀得完的清單。已被註冊表取代。
- **B. 叫紅隊「假設看不到的資料支持詳解」**：圖題現行止血。**等於放棄審查**——
  它把一個結構性盲區寫成規則。改為 `figure_desc` ＋ 前提／推論分離。
- **C. 出事後開一條重審批覆蓋**（本次對 83 則承上題的做法）：有效但是**止血不是根治**，
  且每次重審都是再付一次全批級代價（紅隊全批約 27M token）。
- **D. 只在紅隊 prompt 要求它回報 `input_gap` 而不做發包前預檢**：仍要跑完
  27M token 才發現，且回報品質取決於模型是否守 schema。預檢是零 token、秒級、確定性的，
  **抓到一題就回本**。

## 後果（Consequences）

- 新增 evidence 欄位時，「審查者看不看得到」成為必答題，漏了就 raise。
- `gap_rate` 成為管線健康指標；它不為 0 代表前三層有漏，是工程告警。
- 需要一次性重寫各站切塊器改用單一 payload 導出函式；跑批中途不宜施行
  （會讓新舊批次不一致），**排在批次收斂後**。
- `severity` 與 `c` 撞字面值（前者 `high` 是壞消息、後者 `high` 是好消息，掃 log 極易
  讀反）：正解是 `severity` 改 `blocker|major|minor`。同樣**排在批次收斂後**；
  新建管線直接採用新字面值。

## 如何重啟討論／修改（How to revisit）

- 若 `figure_desc` 的 pilot 顯示它虛增誤報，退回「只審非圖部分」，
  並把圖題的紅隊職責整批移交視覺哨兵。
- 若某站的 evidence 欄位變成本質上可完整傳遞（例如紅隊也換成視覺模型），
  該欄位的 `degraded`／`blind_policy` 應移除，回到單純 parity。
- `gap_rate` 長期為 0 之後，可評估把源頭 lint 的 regex 往高召回方向放寬，
  代價是誤報上升——放寬前先確認不會導致「狼來了」而被忽略。
