# ADR-0011：消除工具往返（第八槓桿），批次大小改為算出來＋兩個上限封頂

- **狀態**：已採用（Adopted）
- **日期**：2026-07-30
- **決策者**：專案維護者（依 doctor 圖題站 394 題實測數據）
- **相關**：ADR-0005（token 七槓桿，本篇補其第八槓桿）、ADR-0007（紅隊全抽）、
  [`references/batching-and-measurement.md`](../../references/batching-and-measurement.md)

## 背景（Context）

ADR-0005 的七槓桿處理「prompt 裡放什麼」，其中槓桿 1／2 已指出「別叫模型去 Read
操作卡與金樣」。但那只涵蓋**靜態素材**；**逐題的輸入／輸出檔案 I/O** 沒被涵蓋，
而它藏在「腳本把輸入檔名寫進 prompt、叫模型把結果寫進輸出檔」這個看起來完全正常的
做法裡。

doctor 圖題站（394 題、一題一圖）實測暴露了規模：**26,370 token／題**，比 20 題純
文字的整塊（40,698／塊）還貴。拆開看是 **7 次 `exec` 工具往返**——讀輸入、寫輸出、
再自驗一次，而每一輪都把 prompt 連同圖片重送一遍。

同時，ADR-0005 沒有訂「一批放幾題」的推導方式；`explanations-redteam.md` §6 的
「圖題每 12 題一檔」是經驗值，在一題一圖的科目上會引入一類**不可偵測**的錯誤。

## 決策（Decision）

**一、立第八槓桿：模型不碰檔案系統。**
輸入內嵌進 prompt，輸出用 `--output-schema` ＋ `-o` 直接收結構化最終回覆，
沙箱降為 `read-only`。實測 26,370 → 9,130 token／題（**1/2.9**）。

附帶收益三項：`read-only` 根除代理亂改鄰批檔案（實測發生過）；字面 `\n` 序列化 bug
消失（8,227 則中曾有 93 則，且**偽裝成內容缺陷**，誤判會導致重寫正確內容）；
輸出契約由 API 強制。

**二、批次大小改為算出來，再用兩個上限封頂。**
取 `N` 使 `N·d ≈ 4P`（`P`＝恆定前綴、`d`＝每題變動尾），此時前綴只佔變動成本兩成。
兩個上限：

- **上限 A：重試波及範圍**——一塊失敗要整批重跑。
- **上限 B（🔴 硬上限）：逐題錯配是否可偵測**——若「模型把第 3 題的素材寫進第 5 題」
  沒有零 token 關卡抓得到，`N` **必須是 1**，不管算式算出多少。

圖題是上限 B 的案例：錯配後結構 lint 通過、答案錨通過、文字紅隊被明文禁止提圖類
finding，產物是一則格式合規、答案正確、圖像描述張冠李戴的詳解，直接上線給考生。
故圖題 `N=1`，取代 §6 的「12 題一檔」（後者僅適用於多題共用一圖、可整批對照的情形）。

**三、量測紀律入規範。**
`codex exec` 只報總 token、無 cached／reasoning 拆解。故：不從 prompt 大小推總成本；
一次只改一個變數；**`n ≥ 12–15` 且用中位數**（分佈右偏，實測同批三題 7.7k／28k／28k）；
前置實測不可省。

## 考慮過的替代方案（Alternatives）

- **A. 維持一題一次但接受 26k／題**：先前的判斷，依據是「前綴重複稅只值 1–3 美元」。
  錯在從 prompt 大小推總量——真實成本的大半是往返，不是前綴。
- **B. 改成批次以攤平前綴**：能省的是前綴（約 2.17M → 0.27M），但**省不掉往返**，
  且引入上限 B 的不可偵測錯配。砍往返省 6.8M，遠大於批次能省的部分。**兩件事別混為一談。**
- **C. 圖號燒印圖上 ＋ 批次 ＋ lint 驗回報編號**：技術上成立，是唯一能讓錯配從
  「不可偵測」變「零 token 可偵測」的設計。但幾百題規模投報率為負；
  **四千題以上量級再建置**，屆時一次建置多次攤提。
- **D. 降 effort 省推理**：未實測。醫學影像判讀降 effort 有品質風險，
  且中途降檔會產出品質異質的語料。須先 A/B。

## 後果（Consequences）

- 圖題站每題成本降至 1/2.9；沙箱權限收緊；一類序列化 bug 絕跡。
- `--output-schema` 的 schema 必須讓 `required` 涵蓋所有 `properties`（含巢狀），
  選填欄位改為可 null 並列入 `required`——**先用 1 題實測 schema**，否則 400 會在整批重複。
- 既有 `make_*_expl_batches.py` 類腳本的「圖題 12 題一檔」需按上限 B 重新判斷。
- 中途改 prompt 會打破 byte-identical 前綴、並讓語料分成兩版；
  **要改就在開跑前改完**，跑到一半才改是純虧。

## 如何重啟討論／修改（How to revisit）

- 若某站的逐題錯配變成可偵測（例如上述方案 C 落地），上限 B 解除，`N` 回到算式決定。
- 若 `codex exec` 之後開始輸出 cached／reasoning 拆解，量測紀律第 1、3 條可放寬——
  屆時能直接歸因，不必靠「改一個變數、量足夠樣本」。
- 若 effort A/B 實測顯示低 effort 在圖題不損品質，優先序表第 4 項要改寫。
