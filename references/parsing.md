## 1. 為什麼用 markitdown 先轉 md

直接用 pymupdf 抽字，拿到的是「座標散落的文字行」，閱讀順序常常壞掉——尤其題組共用的引文（passage）會跟題目交錯、雙欄選項會左右串行。所以第一步一律先用 markitdown 把 PDF 轉成 markdown：

```bash
markitdown data/raw/{年}_{科}_試題.pdf -o data/raw/{年}_{科}_試題.md
```

markitdown 的好處是它有版面理解，散文段落（題幹、題組引文）的閱讀順序大致正確，題組的「甲乙丙」引文會排在標頭之後，這是 raw pymupdf 做不到的。

**但 markitdown 不是萬靈丹**，它會在幾種情況翻車，這時改用 pymupdf 的座標序（`get_text("dict")` 依 `(page, y, x)` 排序）當輔助或主力。判斷哪邊可靠，正是 judgment 的一部分：

- **散文（passage、題幹）** → 信 markitdown，閱讀順序乾淨。
- **多欄並排的選項**（cloze 選項格、會考雙欄 A|B / C|D）→ markitdown 線性化順序各年不一致，**改用 pymupdf 座標 band 分群**才對得齊。
- **複雜統計表**（社會卷）→ markitdown 會把表格塞進 markdown table，需攤平還原；嚴重破碎時用 pymupdf 座標重抓題幹與選項。
- **整批以座標序重建**（會考英語）→ 該卷「題號獨立成行、題幹/選項後移」的版面 markitdown 會張冠李戴，乾脆全卷以 pymupdf `get_text` dict 依 `(page, y, x)` 忠實重建，逐字不漏。

換句話說：markitdown 解決「閱讀序與題組綁定」，pymupdf 補「markitdown 線性化失敗的版面」。兩者互補，由解析器當下判斷用哪個。

## 2. judgment 式：先偵測實況，再選策略

寫解析器前（其實是寫的過程中反覆驗證），先回答這幾個關於「這卷長怎樣」的問題，答案決定策略：

| 偵測項 | 學測（GSAT） | 會考（CAP） |
| --- | --- | --- |
| 有沒有題組？ | 有，且大量（社會幾乎全題組） | 有，後半段固定為題組 |
| 題組標頭長怎樣？ | 「N 至 M 為題組」「第 N 至 M 題為題組」 | 「請閱讀以下…回答 A～B 題：」「閱讀…回答第 a 至 b 題：」、英語用「(N-M)」 |
| 選項是 4 選 1 還 5 選項？ | 國綜/社會 (A)–(E) 五選項、英文 (A)–(D)，詞庫到 (J) | 全部 (A)–(D) 四選一 |
| 有沒有多選題？ | 有（社會、英文混合題；答案多字母） | 沒有，全單選 |
| 有沒有非選/混合題？ | 有（國綜混合題、英文中譯英+作文、社會非選） | 沒有 |
| 答案鍵格式？ | 各科獨立答案 PDF，橫排「題號/答案」表 | 一份多科一覽表 PDF，要定位該科欄位 |
| 圖多不多？ | 社會、數理多；國綜/英文閱讀少 | 社會多；國文少 |

**結論：學測較複雜（5 選項、多選、非選、混合題並存，且每科結構差很多），會考較單純（全 4 選一單選）。** 所以學測幾乎每科一個 parser，會考也每科一個，但會考的判定邏輯相對乾淨。

### 偵測落實到程式的幾個具體手法

- **題型由答案推斷，不靠版面猜**：拿到該題官方答案後，`len(answer) > 1` → 多選；單字母 → 單選；答案是「／」或空且無選項 → 非選。這比從題幹文字猜「這題是不是多選」可靠得多。
- **答案表是權威題號清單**：官方答案 PDF 列出的題號就是這卷的合法題號。用它過濾掉卷末附錄、評分參考表裡被誤判成題號的孤立數字（社會、會考都靠這招）。
- **題組跨度合理性檢查**：題組標頭抓到的 `(a, b)` 要求 `a <= b`、跨度不過大（如會考國文限 `b-a <= 5`、英語 `<= 9`），擋掉誤判。
- **選項殘缺 → 觸發 fallback**：答案明明是 A–E 某字母，但 markitdown 只解析到 < 4 個選項 → 判定版面被打碎，改用 pymupdf 座標重抓該題。

## 3. 忠實原則（紅線）

- **逐字忠實擷取原文**，絕不改寫、摘要、翻譯、抄出版商的編排或詳解。英文題保留英文原文。
- **跳過卷首測驗說明**（約 1.5 頁的注意事項/作答方式/計分說明）。學測從「第壹部分」起算；會考從「一、單題」標頭起算，其前全部丟棄。
- **去頁眉頁腳裝飾行**：頁碼、「第 N 頁/共 N 頁」、「請翻頁繼續作答」、「背面尚有試題」、科目標題、財團法人字樣等，逐行用 `DROP` 正則過濾。
- **題組 group_id / passage 綁定**：同一題組的所有子題共用 `group_id` 與 `passage`（題組共用素材）。passage = 題組標頭之後、到第一個子題題號之前的文字。**題組絕不拆散**（自驗會檢查同 gid 題號連續且符合標頭範圍）。
- **答案表用 find_tables 對應**：答案一律從官方答案 PDF 解析，`pymupdf find_tables` 抓表、逐列對「題號 / 答案」。學測各科一張獨立答案表；會考是多科一覽表，要先定位該科欄位（依表頭含「國文」「社會」「英語/閱讀」字樣動態抓欄 index）。

## 4. 每科一個 parser，但共用 schema 與冪等 merge

各卷結構差太多，硬寫成一支通用 parser 只會變成滿是 `if 科目 == …` 的巨獸。所以**每科各自一個 parser**：

| 腳本 | 對象 | 主要策略特點 |
| --- | --- | --- |
| `parse_gsat.py` | 學測國綜 | markitdown 散文閱讀序 + find_tables 答案；題組「N-M 為題組」 |
| `parse_eng.py` | 學測英文 | 七大 section（詞彙/綜合測驗/文意選填/篇章結構/閱讀/混合/非選）各自切法；cloze 與詞彙選項用 pymupdf 座標 band；詞庫（A–J / A–E）自動偵測尾端連續選項列，不硬編 max |
| `parse_soc.py` | 學測社會 | 攤平 markdown 表格 + 題組標頭三形態容錯（同行/顛倒兩行/正常兩行）；破碎統計表用座標 fallback；領域（歷史/地理/公民）關鍵詞推斷 |
| `parse_cap_國文.py` | 會考國文 | 全 42 題四選一；題組標頭錨定「回答 A～B 題：」；選項容許括號內空白「(  B  )」；清 `(cid:NN)` 與 PUA 殘碼 |
| `parse_cap_社會.py` | 會考社會 | 約 54 題四選一；攤平表格；雙欄選項座標 fallback；千分位大數判定為圖表座標軸殘留 → 視為空選項 |
| `parse_cap_英語.py` | 會考英語（閱讀） | **整卷以 pymupdf 座標序重建**；字彙註解（英文+中文釋義）整組剝除；頁碼洩漏（選項尾端裸數字）清除 |

它們**共用同一份題目 schema**（見 §6）與**冪等的 qid-keyed merge**：

```python
def merge_bank(new_subject):
    obj = json.load(open(BANK)) if exists else {"meta": {}, "questions": []}
    kept = [q for q in obj["questions"] if q.get("subject") != SUBJECT]  # 只移除本科舊題
    merged = kept + new_subject                                          # 換上本科新題
    obj["questions"] = merged
    json.dump(obj, open(BANK, "w"), ensure_ascii=False, indent=1)
```

關鍵：merge 以 `subject`（或更細到 `qid`）為鍵，**重跑某科只覆蓋該科、不動其他科**。所以 `parse_eng.py` 重跑不會破壞 `parse_gsat.py` 的成果。學測各科直接 merge 進 `data/bank.json`；會考各科先各自輸出到 `data/_stage/cap_{科}.json`，合併由上游（`merge_stage3.py`）負責，同樣 qid-keyed 冪等。

`qid` 命名保證跨年跨科唯一：
- 學測：`{year}_{科}_{no}`（如 `114_社會_31`）；英文非選用 `{year}_英文_trans1`、`_essay` 避免與選擇題 no 衝突。
- 會考：`{exam}_{year}_{科}_{no}`（如 `會考_114_社會_31`）。

## §4′ 題組作答政策分類：`standalone` 要在**解析時**一次標好

「題目分類」裡最容易被推遲、推遲後就再也補不回來的一項。讀每個子題 `stem` 判斷
它能否「單獨出現」：

- 引用同組兄弟題者（`承上題`／`依前題`／`根據第 N 小題`／`同上題條件`／
  `利用前小題的結果`）→ 標 `standalone=false`，平臺須整組一起出（≥2 題同時作答）。
- 其餘 → `standalone=true`，可單獨出，但**自帶共用 passage／圖**。

🔴 **關鍵分辨**：「上述／如圖」指的是**共用材料**（passage／圖 → 仍可單獨），
還是**前一子題的內容或答案**（→ 不可單獨）。這是判斷式，不是字串比對能定的。

為什麼非得在解析時做：這時 `group_id` 與卷內順序都在手上；等進了題庫再回頭補，
就只剩題幹文字可看，而「上述」指的是材料還是前題，離開原卷版面常常判不出來。
欄位落地與前端行為見 `data-sources.md` §5「題組欄位與作答政策」。

## 5. 圖片：只存檔名，build 時才內嵌（絕不在題庫存影像）

圖無法以文字忠實重建，所以解析階段**只標旗標、不存影像**：

1. **解析器標 `needs_figure`**：題幹/passage 出現「圖/表/地圖/附圖/照片/示意圖/統計圖…」等指涉詞，或選項數 < 4（圖被吃掉）、或選項全空（純圖選項）→ `True`。社會卷圖多，原則「寧可多標」。
2. **`extract_figures.py` 把需要圖的題 render 成獨立 PNG**：對 `needs_figure==True` 的題，定位其 stem 在原卷 PDF 的版面位置，取「該題頂端到下一題頂端」的版面區塊（band），`page.get_pixmap(clip=...)` render 成乾淨 PNG 存進 `data/figures/`。命名：獨立題 `{簡碼}{year}_q{no}.png`、題組 `{簡碼}{year}_g{首題}_{末題}.png`（一組共用一張）。**bank.json 只寫入 `figure` 欄的檔名字串，永不寫影像。**
3. **`build_app.py` 在 build 時才內嵌**：`figures_block` 讀 `data/figures/` 下 PNG，編成 `window.__FIGS__ = {檔名: dataURI}` 注入單檔 HTML，前端據 `figure` 欄查表顯示。

這條資料流是刻意設計的：

```
原卷 PDF → render → data/figures/*.png（二進位）
                         │
bank.json.figure = "S114_q24.png"（只有檔名，純文字、可 lint、可進 git diff）
                         │
build 時 build_app.py 讀 PNG → 內嵌進 window.__FIGS__ → 單檔離線 HTML
```

**鐵則：題庫（bank.json）永遠是純文字。** 影像只在 `data/figures/` 與最終 HTML 裡存在；編碼字串只在 build 函式內部與輸出 HTML 中流動，**任何階段都不得把編碼字串 print 出來或寫進題庫**（會觸發內容過濾器、也讓 bank.json 無法被人讀與 lint）。

## 6. bank.json 題目 schema（每題）

```jsonc
{
  "qid":          "114_社會_31",   // 跨年跨科唯一鍵；merge 與 figure 對應都靠它
  "exam":         "學測",          // 學測 / 會考
  "year":         114,
  "subject":      "社會",
  "no":           31,              // 卷內題號（非選用 null，qid 帶 trans1/essay）
  "group_id":     "114_社會_g31_32", // 題組鍵；獨立題為 null
  "passage":      "……題組共用素材……", // 題組共用引文/選文/材料；獨立題為 ""
  "stem":         "……題幹……",
  "options":      { "A": "…", "B": "…", "C": "…", "D": "…" }, // 詞庫題存共用詞庫；純圖選項可空
  "answer":       "A",            // 可多選（多字母如 "AC"）；非選為 ""
  "type":         "單選",          // 單選 / 多選 / 題組 / 非選
  "needs_figure": false,          // 是否需對照圖
  "figure":       null            // extract_figures 寫入的 PNG 檔名；無圖為 null
}
```

各科另可帶選用欄位（不影響共用流程）：學測社會的 `domain`（歷史/地理/公民推斷）、英文的 `section`（詞彙/綜合測驗/…）。`meta` 區塊記來源、年度、parser 說明與題數，供稽核。

## 7. 自驗：把「忠實」變成可檢查的條件

每個 parser（尤其會考三科）跑完都做逐年自驗，只回報**真正的異常**，不把圖片題的合理空缺當錯：

- 題數對不對（會考國文 42、社會 54；英語各年不一但題號要連續）。
- 題號連續、無重複、無缺漏；答案皆在合法集合（A–D / A–E）。
- 選項齊全：**非圖片題**才要求 4 個選項齊全；`needs_figure` 的圖片題容許選項殘缺（選項本身是圖）。
- 無選項洩漏：某選項內容不應殘留其他選項標記 `(X)` 或下一題題號。
- 題組未拆散：同 `group_id` 題號連續且與標頭宣告的 `a..b` 一致；文字選文題組 passage 須非空且組內一致，圖片選文題組容許空 passage。

自驗的精神跟整份方法論一致：**規則要分情況（圖片題 vs 文字題、題組 vs 獨立題），不一刀切**——這正是 judgment 式解析的縮影。

## 8. 選項標記是 PUA 造字 → 洗壞掉的選項（國考實戰，2026-06）

考選部測驗式 PDF 的選項標記不是 `(A)`／`①`，而是**造字字型的 PUA 碼**（國考實測 `U+E18C–E190` ＝ ①②③④⑤）。不認得它的解析器會壞三種：(a) 中文選項被吸進題幹（`options=[]`）、(b) 組合題掉最後一個選項、(c) 英文題標記混進字中（`mas[③]s defect`）。

**洗法（bbox 重排重切，非純文字）**：

- spans 依「列叢集」重排（y 間距 < ~8 視為同列，避免標記與其文字被四捨五入拆到不同帶）→ 列內按 x。標記常在其文字左側、同列。
- 依序走 ①②③④⑤ 標記當邊界切 stem／選項；**題幹內的引用標記（如「承①選項」）不是邊界**——只認「下一個該出現的」標記。
- 題號欄判定：x < 頁寬 ~10%（排除頁碼、題內數字、會計金額等假題號）。
- 尾段汙染截掉：代號／頁次／座號／「二、複選題」段首；但**不可切掉會計金額尾數**（`$417,500` 的 `,500`）。
- 採用門檻（沒過就**保留 `parse:review`、不寫猜測**）：4 或 5 選項、無空、無重複、無殘留 PUA、原正解字母在範圍。
- **ToUnicode 塌成 ① 仍救得回——用 glyph-id（2026-06 更新，推翻舊「救不回」結論）**：若該卷字型 ToUnicode 把 ②③④⑤ 全塌成 `U+2460`（選項變 `①①⑤`），`get_text` 救不回 identity，但 **`page.get_texttrace()` 給的是真 glyph-id，圈號 glyph 連續**（①=base、②=base+1…⑤=base+4），`號碼 = gid − base + 1`，base 取整頁圈號最小 gid（stem 必含①保證）。實測 MingLiU `33627=①…33631=⑤`，重建直接服務 Q10 步驟排序 → `②①③⑤④` 與正解吻合。
- **glyph-id 也會偶爾漏字 → 混合法 + 讀圖雙驗**：`get_text` 的 **count 正確/identity 錯**、`texttrace` 的 **identity 正確/偶漏一個 glyph**。逐選項比長度：相符→用 texttrace；不符（texttrace 漏字）→ **render 該選項列高解析 PNG 直接讀圖**（唯一 100% 可信源；別在 get_text 與 texttrace 間二選一，兩者都可能錯）。塌陷不改 count，故「重建選項數 = 原選項數」是強不變量可當閘。
- **先量爆炸半徑再決定**：塌陷常**只發生在特定 PDF 的特定字型子集**（國考實測僅 social-worker 12/377 組合題受影響、其他 6 庫 0%，非系統性）；同卷甚至混字型（某些題正確、某些塌陷），別假設整卷一致。
- **真救不回才標 review**：glyph-id 連續性不成立／render 也模糊時，標 review；PDF 視覺 render 正確者另可走 option-visual 裁圖救（圖表側見 `exam-pdf-asset-extractor`）。
- 偵測「靜默壞選項」：除了空／重複，還要抓「**單一選項內重複同一圈號**」（`(①-⑩)\1`，真組合題不會重複）——否則塌陷後字串各異會躲過重複偵測。**警告**：此偵測只抓「塌成完全相同」者；塌成「不同但錯」的躲得過，故發現一卷有塌陷就該整卷重抽組合題、別只修被旗標的。

> 工具參考：國考用選項重排工具（bbox 重排＋依序走標記）。其他考試若標記字型不同，先用 `grep PUA 範圍` 驗出該卷的標記碼再套。

### 8.1 壞選項缺陷分類 → 對應修法（2026-06 升學+國考全站實戰，最重要的一張表）

**核心教訓：先用 audit 分桶，再「對症下藥」——不同缺陷型的正確工具完全不同，硬套一種法（尤其純文字抽取）會灌錯資料。每型都要 verify-real-data（回 PDF 實看/讀圖）再動手。**

| 缺陷型 | 偵測訊號 | ✅ 正確修法 | ❌ 不可用 |
|---|---|---|---|
| 文字選項被併/吃進 stem | PDF 有 `(A)…(D)` 文字、bank 空或擠一格 | 重抽文字回填，**雙層保守閘**（含中文 或 帶單位符號 % () ＜＞ ° ： 萬 元 才填）；選項烤進 stem 者順手裁 stem | 盲填全部（會把下一型也灌錯） |
| 純整數/百分比選項漏抽 | `1000/1500/2000`、`6%/50%` 無歧義 | 讀圖確認後直接填 | — |
| 圈號 ToUnicode 塌成 ① | `①①①`、單卷字型壞、`(①-⑩)\1` | `get_texttrace` glyph-id 重建（連續：①=base..⑤=base+4）+ count 比對 + 讀圖雙驗 | `get_text`（identity 全錯）、texttrace 單用（偶漏字） |
| 數學分數/次方/根號塌陷 | `19/28→1928`、`10⁵→105`、`2√5→2 5` | 讀圖→ KaTeX `\(…\)` 轉寫（`\dfrac`/`^{}`/`\sqrt{}`，本站慣例） | 純文字抽取（數字看似有效但全錯） |
| 物理公式下標塌陷（**最棘手**） | `ΔT內/外→ΔT`、`f_s` 丟失→**假重複**（中文存活、數學消失） | **option-visual 裁圖**最忠實；或讀圖逐式 KaTeX（5 選項×N 題、下標/`<=>` 易讀錯，物理題錯=有害，慎用） | `get_text`、低解析讀圖 |
| 選項本身就是圖 | 印章/座標/地圖/折線/向量圖、PDF 只有 `(A)(B)(C)(D)` 後接圖 | **option-visual 裁圖**（裁時務必含 `(A)(B)(C)(D)` 標籤列，否則學生看得到圖卻對不到答案）；空選項語意正確、非殘缺，audit 應分流不誤報 | 任何文字抽取 |
| 多選引用段落 `(A)-(H)` | 英文閱讀多選、`opts=[]`、答案是子集如 `BDF` | 特殊題型：options 設 A-H 標籤、靠 passage 內 `(A)…(H)` 標記作答 | 4 選項假設 |
| Symbol/MT-Extra 字型符號 | `U+F0xx`（stem/選項造字亂碼） | **先回原卷取字型歸屬，再照該字型的編碼還原（→ §8.10，不可用全域對照表）**；每條用上下文實證（F02B=+、F0B4=×、F044=Δ、F0BB=≈…）；延伸括號碎片與查不到字圖名者不猜、留原樣 | — |
| **數字選項輪位**（2026-07 新增） | 題幹**尾巴掛著一串數字**、每個選項是「單位＋數字」且**最後一個只有單位**（`stem 尾='800'` ＋ `['人1000','人1200','人1400','人']`） | 就地輪位還原：題幹尾數字＝(A) 的數字，選項 i 的數字往後挪一格 → `['800人','1000人','1200人','1400人']`。**零 token、不必開 PDF**，但一定要拿 PDF 的數字集合核對 | 直接把選項當文字修（單位會黏錯格）；重抽（有些卷的文字層本身就是輪位的，重抽拿到一樣的錯） |

**分流原則**：audit 先把 `<2 選項` 分成「真殘缺（無圖）」vs「圖片選項（有圖/needs_figure）」，後者不算殘缺。**option-visual 裁圖是公式/圖表/向量/部分圈號選項的統一忠實解**（與圖片選項同機制），建議優先把它做進平臺 `run.js`，比逐題手轉文字可靠且可規模化。

### 8.2 清理 `parse:review` 殘餘：先分路，再核對，一題不過就整支不寫（2026-07 實戰）

清一科最後那批 `parse:review`（社工 19 題）時最容易犯的錯，是**把它們當成同一種病**寫一支腳本掃過去。實測那 19 題是**四種**病，共用的只有 `parse:review` 這個標籤：

| 路徑 | 症狀 | 處置 | 題數 |
| --- | --- | --- | --- |
| P1 數字輪位 | 見上表新增列 | 就地輪位還原＋PDF 數字集合核對 | 7 |
| P2 圈號組合 | **入庫文字本來就對**，是 PDF 文字層塌號才被降級 | **只升 `parse`，一個字都不改** | 10 |
| P3 題幹斷行遺失 | 題幹只剩續行（`⑤生態系統` 5 個字），首行被前一題吃掉 | 回源 PDF 重建題幹 | 1 |
| P4 官方原卷自身瑕疵 | (A)(C) **官方 PDF 原文即相同** | 忠實呈現、升 ok、記 `dup_faithful` ＋ `note` | 1 |

四條可一般化的教訓：

- **🔴 回源 PDF 之前先問：入庫和 PDF，哪一個才是壞的？** §8 的預設是「入庫壞、PDF 是 ground truth」，但 P2 剛好相反——那幾卷的 PDF 文字層把 ②③④ 塌成 ①（`['①①⑤','①①①①']`），而**入庫版本是完整的** `['①③⑤','①②③④']`。若照直覺「以 PDF 為準」重抽，會把已經正確的資料改壞。判準：把兩邊的圈號都遮成 `○` 再比（**塌號容忍比對**），長度與非圈號字元全等 → 入庫是對的，只升 `parse`。定案前渲染成像素逐字看過三題確認。
- **每條路要有自己的核對，而且核對必須來自另一個來源。** P1 的核對是「PDF 文字層的數字集合 ＝ 輪位還原的數字集合」（不比順序，因為部分卷的文字層本身就輪位）；額外的獨立驗證是**官方答案落在法規的法定數字**（學生輔導法 1200 人、身障權保法 34 人、家暴法 2 年、兒少性剝削防制條例 45 日）——四個都對上，才敢說輪位規則是對的而不是巧合。
- **fail-closed：任一題核對不過就整支不寫檔。** 不要「其他 18 題先寫、1 題留著」——那會讓下次跑的人搞不清哪些已處理。寧可全部留 `review` 也不寫進一個錯字。
- **官方原卷自身的瑕疵不是你的 bug，別「修」它。** (A)(C) 原文相同、官方答案是 (D) → 題目仍可作答，忠實呈現＋`dup_faithful: true` ＋ `note` 說明。**但 `note` 要真的顯示給學生看**（本站 `run.js` 的 `sourceNoteEl()`：「原卷校勘：…」），否則學生看到兩個一樣的選項只會認定是本站抄錯並回報，等於白記。

**順帶一個工具設計坑**：分兩階段寫檔的工具（先落地資料、後升級狀態），`.bak` 檔名要**帶階段**。實測 `fix_sw_official_notes.py` 的第二次 `--write` 把第一次的 `.bak_official_notes` 蓋掉了，原始檔的回溯點只剩 git commit。

### 8.3 閘門本身的三個踩坑：參考來源、判準粒度、以及「證明了什麼」（2026-07-30 實戰）

修 `parse:review` 殘餘時，**壞掉的往往不是修復邏輯，是把關的那道閘門**。三次實測：

#### (1) 🔴 參考跟輸入壞在同一個地方 → 子字串測試只會放行錯的那個

「重建的題幹必須是原卷 `get_text()` 的逐字子串」看起來是最強的忠實性閘門。
但當病灶正是**排序**（下標被排到句子後面），`get_text()` 的輸出**帶著一模一樣的錯**。
於是：

- 正確重建的題幹（下標回到原位）→ **不是**那份參考的子串 → 被擋
- 重現了同一個排序錯誤的輸出 → **是**子串 → 放行

實測 `111_自然_8`、`113_自然_17` 兩題正確的重建被自己的閘門擋掉。
**修法：換成與順序無關的性質**——重建結果的**字元多重集必須被原帶包含**
（證明沒有無中生有），順序的正確性另外交給位置性閘門與人眼。

> 一般化：**閘門的參考來源必須獨立於它要抓的病。** 拿被汙染的來源當基準，
> 閘門就只會獎勵重現汙染的輸出。

#### (2) 🔴 判準的寬窄要跟證據的粒度對齊

「**數字夾在兩個漢字之間**」是上下標插錯位的好指紋（`敘₂述`、`體₂增`）。
但直接這樣寫會把合法的「（應選 **2** 項）」也殺掉——實測三題全被擋，等於沒有閘門。

**補上字級這一維**：只抓「**下標尺寸的**數字夾在正文漢字之間」（span `size <
主字級 × 0.82`）。三題全擋立刻變成兩擋一放，剛好對。
**判準用的維度不夠，就只能在誤殺與漏放之間滑動；補一個維度才推得動曲線。**

#### (3) 🔴 「是抄的」不等於「抄完了」——兩個性質要兩道閘門

`V2 題幹必須是原卷文字的子串` 證明的是**來源**。但**截斷後的字串當然仍是子串**，
所以它對「抄了一半」完全無感。實測 `115_自然_55` 過了 V2 卻停在句子中間。

**最便宜的完整性訊號：題幹必須以問號／句號／全形右括號收尾。**
截斷的句子幾乎不可能剛好停在標點上。零成本、幾乎零誤報。

#### 順帶：頁尾殘影要單獨擋

`- 5 -` 這種頁碼由原帶就有的字元組成，**多重集閘門看不到**（沒有無中生有，
只是多抄了）。加一條 `-\s*\d{1,3}\s*-\s*$` 的尾端檢查即可，實測抓到
`113_自然_17` 的選項 (E)。

#### 還有一種「不是缺陷」要認得出來

`115_社會_5` 被旗標的原因是稽核器把**表格的字**算進「原卷字數」，而 `ingested`
只算 `stem+options`——表明明完整地存在 `q.table` 裡，比值卻天生偏高。
**放行的依據要是「逐項驗完整」（題幹／每個選項／表的每一格都是原卷逐字子串），
不是「比值降到門檻以下」。** 用比值放行等於承認自己不知道那題到底缺了什麼。

### 8.4 版面讀取器：一個錯的模型會長出好幾個看似無關的病（2026-07-31 實戰）

清最後幾題 `parse:review` 時，桌上擺著三個症狀，看起來是三種病：

| 症狀 | 表面看起來的病因 |
|---|---|
| `111_自然_8` 題幹開頭冒出「CO」 | 上下標處理沒做好 |
| `113_自然_17`「（應選 2 項）」的 2 跑到上一行 | 小字級合併的邏輯錯了 |
| `112_自然_58` 題幹在化學式前被截斷 | 題帶抓太短 |

**三個都是同一個根因：把「分行」寫成了「格線分桶」。**

#### (1) 🔴 `round(cy / 5)` 這種格線分行必然會在某一行的中間切一刀

格線的邊界落在哪裡跟行在哪裡**毫無關係**。所以同一行的 span 只要垂直中心差 0.6pt，
就可能被分到相鄰兩桶。實測 `111_自然_8`：主文 cy 132.76 → 桶 27，
同一行的「CO」cy 132.12 → 桶 **26**，於是 CO 排到了整句的**最前面**。

**修法：行的錨點只由「正文字級」的 span 決定**（上下標不得自己開一行），
其餘 span 一律歸給**垂直中心最近的錨點行**，行內再依 x 排序。
沒有格線，就沒有格線邊界問題。

順帶把第二個症狀一起解掉：舊版「小字級的行併進前一行」是把它接在**行尾**，
位置就丟了；錨點模型直接把它放回 x 該在的位置。**不是多修一次，是同一個修法。**

#### (2) 🔴 排序的原子必須是「字元」，不是 span

`112_自然_58` 的「O S」在 PDF 裡是**一個** span（x 422–441），而下標「6」的 x=430
落在**它的框裡面**。以 span 為單位排 x，6 無論如何都排不進 O 與 S 之間，
只能得到 `O S₆`（正解是 `O₆S`）。

`get_text("rawdict")` 直接給每個字元的真 bbox，**不必內插估算**。
換成字元原子之後，interleave 自然就對了。
（要注意：換原子之後，凡是「用 span 文字做前綴比對」的地方都會失效——
`OPT.match(span.text)` 變成拿單一字元去比 `(A)`，選項全部消失。
改成在該行的**串接字串**上 `finditer`，再依索引切回字元串列。）

#### (3) 🔴 「一行一個選項」是巧合，不是規律

選項可以排成 **2D 網格**：`(A)(B)(C)` 同一列、`(D)(E)` 下一列。
以行為單位切，就會把三個選項黏成一個、然後少掉兩個。

**這是本輪最嚴重的一個缺陷，而且所有既有閘門都放行了它。**
`115_自然_36` 入庫時只有 4 個選項，順序是 **④②③①**，官方答案 (A) 於是指到 ④，
而原卷的 (A) 是 ①——**這是在對學生顯示錯的答案**，不是版面難看而已。
題文逐字正確、選項數合法、字元多重集守恆，每一條規則都通過。

**修法：切點是「選項標記」，不是「行」。** 掃出該行所有 `(A)`–`(E)` 的位置，
依位置切開；一行有幾個標記就切出幾個選項。

**並補一道位置性閘門（W8）：標記序列必須是 A 起、連號、不重複。**
多重集閘門對**排列**天生無感（`④②③①` 與 `①②③④` 的字元集合完全相同），
只有順序性的斷言看得見它。

#### (4) 🔴 「圖旁邊的字」不等於「圖上的字」

為了處理「文字左欄、圖右欄」的版型，很自然會寫成「以圖的左緣當右界，右邊的字全丟」。
**這條規則一離開它被發明的那個版型，就變成靜默截斷器**：
`112_社會_62` 的答題卷地圖與題幹同高，於是題幹被砍成「…的統計地圖」，
「，並繪製圖例。（4 分）」整段消失——而**多重集閘門只驗「沒有多字」，看不到少字**。

**判準要回到「這個字屬不屬於那張圖」：只丟掉落在圖框『裡面』的字。**
而且「在框內」要用**字元中心點**判定，不能用外框相交——
字形的 bbox 比看得見的字高一截，用相交會讓下方 6pt 的圖攔截上面那一行
（實測那張地圖 y0=530.9 攔掉了 y≈511 的題幹行）。

#### (5) 🔴 述詞要正面刻畫對象，不能靠「缺少某個標記」

`references/figures.md` 的「塗白冒字」講過一次：判準是「屬不屬於這張圖」，
不是「是不是文字」。本輪在**另一個地方**又踩到同一個坑，值得記下它的兩種變形：

- **第一版寫成「尾巴不含問號 ⇒ 是答題卷版面，可刪」。**
  而 `113_國綜_33` 的尾巴其實是丙文〈浪淘沙〉與丁文〈破陣子〉——
  兩首詞當然沒有問號，整段題組材料差點被當家具刪掉。
- **第二版改成「以乙丙丁開頭 ⇒ 是材料」。** 仍然不對：那個「丙」字印在小框裡，
  讀取時當成圖上標籤丟掉了，於是偵測不到，詞又要被刪。
  **述詞不能綁在一個「可能根本不存在」的標記上。**
- **最終版直接問資料本身：這一行是否已經在題組 `passage` 裡？**
  是 → 材料（而且既然已在 passage，從題幹移除必然無損，順帶證明了安全性）；
  否 → 才輪到「短、無句讀的孤立標籤 ＝ 答案欄」這條正面刻畫。

> 一般化：**「A 缺少 B 的特徵，所以 A 是 C」是最容易寫、也最容易誤殺的述詞。**
> 能直接驗證「A 是不是 C」就別繞道；繞不開時，正面刻畫 C 長什麼樣，
> 而不是列舉 C 不長什麼樣。

#### 這一輪的收束

改完之後 `parse:review` 從 7 → 0，而**四支修復腳本共用同一個讀取器**。
症狀愈多支、愈像是要各修各的，愈值得先問一句：**是不是同一個模型錯了？**

### 8.5 表格被當本文讀進題敘：修字串修不好，要回版面（2026-07-31 實戰）

`get_text(sort=True)` 不認得表格是獨立物件，會把儲存格當成一般文字流讀進 `passage`／`stem`。
讀者看到的是「表9 偵測到X 未偵測到X 偵測到Y 17 15 未偵測到Y 96 16」黏在題敘後面——
而表格明明已經抽成結構化欄位、前端會渲染成 `<table>`，等於**同一份資料出現兩次，其中一份亂序**。

全站掃描的偵測器很簡單：**題目有結構化表格，而表格的儲存格值又出現在題敘裡**。
但這個訊號會誤報——題幹本來就常用白話說明表格（「例如第一天…銷售量分別為 60 杯、80 杯」），
所以偵測只用來**產生候選**，不能直接拿來刪。

#### (1) 刪除的述詞要可驗證，而且要有一條會擋住自己的閘門

一段文字要被刪，三條同時成立：**是後綴** ＋ **每個字都能由結構化表格的儲存格拼出來** ＋
**刪完剩下的正文必須以句末標點收尾**。

第三條是關鍵防呆：表格若是「附加」在文末，刪完自然停在句號；若是**與正文交錯**，
刪完會停在句子中間——那代表切點錯了，此時**寧可不動並列進待人工清單**。
實測它擋下 7 題，全部是真的不該用刪除法處理的版型。

兩個必須具名、不能用來放寬述詞的例外：標題存成「表2（隘勇人數）」但版面上只印「表2」；
結構化表格的 `headers` 是攤平的一維陣列，**裝不下跨欄的上層表頭**。
逐題列名會留下紀錄，放寬述詞則是把保證整個拆掉。

#### (2) 🔴 單獨一個「）」不算句末

表格的每一格常以「（克）」「（％）」收尾。把「）」當句末標點，切點就會停在表格中間，
而收尾閘門還誤判通過——結果是**刪一半**：比不刪更糟，因為它看起來像修好了。
只有「。）」「？）」這種**句子被括號收尾**的情形才算。

#### (2b) 直接證據勝過間接證據——閘門太嚴會誤殺，補證據比放寬門檻好

「正文以句末標點收尾」只是**間接**證據：它推論「切點大概對」，但題敘本來就常以括號註記收尾
（「（各項連結不合理則該項不計分）」「（4 分）」），這種**正確**的切點會被誤殺。

處理方式不是把「）」放回句末集合（那會讓表格中間的切點又混過去），
而是補一條**直接**證據：**被刪掉的那一段，是否正好從表格的第一個表頭開始**。
從表頭開始就證明切點壓在表格邊界上，不必再靠標點猜。

規則因此變成「直接證據在，間接證據就不必成立；兩者皆無才擋下」。
這比調鬆門檻好，因為它**增加**了判斷所依據的事實，而不是降低標準。

#### (3) 順序敏感的比對要留一條多重集後備

欄與欄交錯時，同一列的儲存格在文字流裡會被拆開重排：儲存格存成
`["透過…當選席次（占…百分比）", "31 （17.6）", "32 （14.2）"]`，
壓平卻是「透過…當選席次3132（占…百分比）（17.6）（14.2）」——**字一個沒少，順序全亂**。
子字串消去法因此失敗。後備判準是**字元多重集含入**，但它比較弱，所以只對夠長的段落開放，
且仍要通過收尾閘門。正文只要有一個表格沒有的字就會被擋下。

#### (4) 交錯型只能回版面重讀，不能在壓平字串上動刀

資訊在壓平那一步就永久遺失了，之後怎麼修補都是猜。回到版面層：
**表格的每一列在版面上本來就是自己的一行**，壓平時才被拆散——用錨點式分行（§8.4）
還原「哪些字同一行」，表格與正文就自動分開，不必猜。

兩條配套述詞：

- **表格列怎麼認**：不要拿它跟結構化表格比對——那張表本身就是從同一份壞掉的字串抽出來的
  （裡面的下標一樣是散的），兩邊對不起來。改用版面事實：**題組敘述是散文，散文以句末標點收尾**，
  切點＝最後一個以句末標點結尾的行。表格夾在題幹**中間**時另用一條：一行用水平間隙分群，
  **群數等於表格欄數（±1）就是表格列**——門檻取自資料本身，不是調出來的；散文行是連續的一大群。
- **欄界由表頭那一列決定，整張表共用**。逐列各自量間隙會把一格切成十格
  （`CO₂(g) + 6H⁺ + 6e⁻ → …` 自己內部就有九個空白）。這跟分行要用錨點是同一個道理：
  **全域結構要用全域證據定，不要每筆各憑各的局部訊號。**

#### (5) 上標與下標分不出來，是科學上的錯誤而不是難看

只用「字級比正文小」判定，會把 `10⁻²` 寫成 `10₋₂`、`6H⁺` 寫成 `6H₊`——**那是兩個不同的東西**。
差別不在大小而在**相對於該行正文中線的高低**，所以要逐行取正文中線再比。
另外 Symbol 字型的 `×` 是 `U+F0B4`，沿用「PUA = U+F000 + 原碼位」那條規則即可，不是特例。

修完務必實測渲染引擎吃不吃得下新式子（含 `→`、`\times`、以及 U+2212 的負號）——
產生得出來不等於顯示得出來。

### 8.6 作答用的表格被壓平＝這題不能作答（不是呈現問題，是功能缺陷）

非選題常見「左欄一排 `□` 勾選、右欄寫理由」的作答表。壓平成一維字串後長這樣：

    …（4 分）（於答題卷作答）絕對不適合的放射性元素（勾選）說明原因（20字以內） □ 鈾238 □ 銣87 □ 碳14

欄標題與選項黏成一行、勾選框沒有可點的對象。**判準是「學生能不能作答」，不是「看不看得懂」**
——到這個狀態這題等於廢掉，所以它的優先級是缺陷等級，不是排版優化。同一個判準也適用於
：圖上的刻度滲進題幹、選項圖沒有 (A)(B)(C)(D) 標籤、表格變成一行數字。

#### 抽取：讀原卷的**框線網格**，不要從壓平後的文字猜結構

`page.get_drawings()` 的細長矩形就是框線：扁而寬＝橫線、細而高＝直線。三條述詞全是
**直接證據**——表格的結構本來就畫在紙上，去猜它是自找的：

1. **欄界**：跨過該列中線的**直線**＝這一列的欄界。跨欄表頭自然掉出來（表頭列少一條
   線），`colspan` 直接可得；內文的真欄數取「切最細的那一列」。
2. **列界／`rowspan`**：橫線的 **x 範圍**決定它是不是這一欄的列界；橫線沒跨過的欄
   ＝合併儲存格。實例：左欄三個選項各自一列、右邊說明欄**一格跨三列**，分隔線只畫到
   中間那條直線。不看 x 範圍就會切成三個說明欄，等於要學生把同一個理由寫三遍。
3. **這一格要不要給輸入框**：`格高 −（已印行數 × 行距中位數）≥ 半行` ⇒ 還有空位可寫。
   **逐格判、不是逐欄判**：同一欄常常上面那格是待填空白、下面那格印滿把句子收尾的字
   （「所以…先設在該都市。」），原卷根本沒留空位。行距取**表內相鄰文字行 y 距的中位數**，
   別用字級推——疏排推不出來。

兩個一定會踩到的坑：

- **格子內容要逐字元分配**。`（1 分）` 會騎在直線上，整組分配會被切成 `（1` 與 `分）`
  落到相鄰兩欄。
- **選項會折行**。勾選欄裡不含 `□` 的行只可能是上一個選項的續行；當成新選項會多切
  一個，當成說明文字會把半句話丟進說明欄。

> **被推翻的前一版（留著別再走一次）**：原本靠文字猜結構——由少到多試 k 行標題，
> 取第一個「切完之後題幹仍以句末標點收尾」的 k。24 題裡 9 題失敗，兩類根因：
> (a) `（）` 在同一批卷裡**句末與欄標題兩邊都出現**，標點形狀是間接證據，分不出來；
> (b) 跨欄表頭壓平後**字不連續**，在整行上 `find` 一定找不到。改讀框線後 24/24 全過。

#### 切點：用字元多重集，不是句末標點

題幹尾端剛好 `len(表格文字)` 個字，且**字元多重集與表格內文字相等** ⇒ 同時證明了
「切在表格邊界上」與「表格的字一個沒漏、正文的字一個沒被吃掉」。作法是由題幹尾端往前吃，
只要那個字還在表格的字池裡就繼續吃；池空或遇到表格沒有的字就停——停下來的那個字就是
直接證據。池的總量就是表格字數，所以最多只吃得下一張表，不會啃穿整段正文。
容許個位數的落差（上游壓平時本來就會掉字），但要把掉的字印出來。

#### 閘門

表內 `□` 數必須等於題幹裡的 `□` 數（少抓＝學生選不到）；至少 2 欄且至少 1 格含 `□`；
切完的題幹至少 15 字；多重集落差不超過個位數。任一不過就整題不動並列出來。

#### 呈現端要一起改，否則等於沒修

資料結構化之後，前端要真的畫成可勾選、可輸入的表；並且**原本那個「整體作答」大輸入框要移除**
——同時出現兩個作答區，學生不知道該寫哪一個。連帶「這題作答了沒」的判定也要改成
「任一作答元件有內容（勾了任一項或填了任一格）」，否則進度永遠算它沒作答。

### 8.7 圖上的刻度滲進題幹：有圖才可以刪，而且不能只刪一半

圖裁成 PNG 之後，圖上的刻度與軸標籤仍留在文字流裡，題幹變成
「…說明該災害發生的原因。（4 分）甲乙丙（℃）（mm） 30 250 30 250 …（月）」。

**三條述詞同時成立才刪**：這題有圖（內容在圖上看得到，刪字不掉資訊——**沒有圖就不刪**）／
尾段扣掉數字、單位、括號、標號之後幾乎沒有實質中文／刪完以句末標點收尾。

三個實戰細節：

1. **配分註記「（4 分）」整串都由家具字元組成**（數字＋括號，殘留只有「分」一字），
   會被最早的切點一起吞掉。那是題目的一部分，要特別讓過。
2. **軸標籤會被刻度數字打散**（「25 累 20 積高 15 程（公 10 尺）」），單看殘留中文會判失敗。
   放寬殘留上限的同時要**加一條「尾段至少 N 個數字」**——一條刻畫「像軸標籤」、
   一條刻畫「像刻度」，兩條一起才成立。單獨放寬會誤傷正常補述。
3. **完整性閘門**：切完之後題幹尾巴若還堆著數字，代表家具不只在最後一段，這次只清掉一半 →
   **不要寫入**。半清比不清更糟，因為它看起來像修好了，沒有人會再回來看。

## 9. 完整性複查要掃「所有題型」，不只選擇題

混合式考試的選擇題與**申論題分開存**（`bank.json` vs `essays.json`），有些考試還有題組／填空／實作等。洗選項與圖表完整性複查**每種題型的 store 都要掃**，動態適應；別假設只有選擇題。**教訓**：國考第一輪只掃選擇題、漏了申論 store 裡的圖表（cpa 申論有股權結構圖＋資料表）。圖表側的逐步流程見 `exam-pdf-asset-extractor` 的 Completeness Re-check（Step 0 已寫入此規則）。

### 8.8 選項標記是**向量圖形**（連 PUA 都沒有）→ 題幹尾行洩漏成選項 A，四選項整體位移（2026-08-01 實戰）

§8 講的是標記變成 PUA 造字碼。**還有更糟的一種：標記根本不在文字層裡。**
考選部某些年度的卷把 `(A)(B)(C)(D)` 畫成向量圖形，`get_text` 拿到的是
`'     定向型認同（identity achievement）            迷失型認同（identity diffusion）'`
——只有選項內容、沒有任何標記，`grep` PUA 範圍也是零命中。

line-based 解析器於是拿**題幹的最後一行**當作選項 (A) 的內容，真正的四個選項各往後
推一格、**最後一個直接掉了**。

#### 為什麼這個洞活得比其他都久

**現有的每一個不變式都成立**：洩漏之後剛好還是 4 個選項（四選一不變式過）、
每個選項都非空且互異（空選項／重複偵測過）、`parse` 判為 `ok`（正在供題）。

而它**正在誤判學生**：官方答案是字母、與選項解析無關，所以答案欄一直是對的，
但字母指到的位置整個錯位。實例 `105_105030_基礎_12`（Marcia 自我認同）原卷四選項為
定向／迷失／早閉／未定，「未定型」整個不見；官方答案 C＝早閉型（聽從父母、從未懷疑、
無危機探索＝foreclosure），站上把 (C) 顯示成「迷失型」並標為正解——**選對的學生被判錯**。

> 一般化：**能攔住它的不變式其實存在**——「題幹必須以終止標點收尾」——只是沒有人
> 寫過，因為那看起來像格式潔癖而不像正確性條件。一個資料缺陷能不能被機器發現，
> 取決於有沒有人想到把它寫成不變式。

#### 判準要指向損壞的**機制**，不是**表徵**

第一版判準寫「選項 A 以問號結尾」，全站命中 67 題，**精度只有兩成**——諮商、教檢、
學測有大量**合法**的問句選項（治療師的回應、教師的布題、
`What question does the passage answer?` 的四個選項本來就都是問句）。

改成指向機制——**題幹斷在句中（無終止標點）＋選項 A 是題幹問句的後半**——精度 **20/20**。
與 §8.7、§8.5 是同一條：判準要刻畫損壞怎麼發生的，不是刻畫壞掉之後長什麼樣。

#### 這條判準有召回洞，要靠**另一種模態**補

上面那條抓不到**組合題**（①②③④）：洩漏出去的是敘述句不是問句，整類從判準底下漏過去。
它們是被**詳解生成站與紅隊的 `data_defect` 回報**挖出來的（同一批卷再 +6 題）。

> 文字啟發式與語意審查是兩種**盲區不重疊**的偵測器，任一種單獨用都會漏，而漏掉的
> 部分彼此看不見。掃描器抓不到的不代表沒有——把 `data_defect` 回報當成第二個偵測器。

#### 回源修復：七道 fail-closed 閘，其中四道是被自己的實測打出來的

還原方法是回官方試題 PDF 重建（題幹／選項的分界**不用猜**：拿入庫已有的第二個選項
當錨，它出現的那一行就是選項區起點）。四道被實測打出來的閘：

1. **去題號只能在原始首行做，且剝掉的數字必須等於 qid 的題號。**
   盲剝「開頭 1–3 位數」會吃掉題幹本身的數字——實測題幹是「7 個月的嬰兒⋯」，
   首行長「11 7 個月的嬰兒⋯」，盲剝變成「個月的嬰兒」。
2. **題塊終止符必須是「本題號＋1」，不能只認「行首有數字」。**
   數值型選項行首就長那樣：`60 秒  73 秒  91 秒  118 秒` 會被當成第 60 題，整行選項被切掉。
3. **舊選項的覆蓋判準要允許「黏欄」但只允許相鄰且依序。**
   同一批卷有第二種病：第二欄沒被切開，庫裡最後兩個選項黏成一格。硬要求
   「恰多出一個新選項」會把正確的重建擋在門外。
4. **選項的引號必須配平。** 有一題通過了前六道閘但重建是錯的：它的兩個「選項」其實是
   同一個被折行切成兩半（`「小芬，⋯妳繼` 開了引號沒收、`續保持沉默⋯」` 收了沒開），
   而真正的選項 A 被吞進題幹。**被切半的兩段對「依序覆蓋」剛好成立**，只有引號配平看得出來。

#### 修完不要動 `answer`

20 題逐題對過官方標準答案 PDF，**20/20 與庫裡一致**。答案欄一直是對的，錯的是選項順序
——還原順序就等於修好判分。任何「順便改答案」的念頭都是在製造第二種錯。
還原不了的（重建出 6–7 段、引號配不平）**降 `parse:'review'`，不硬修**：
半修比不修更難發現，因為 `parse` 已是 `ok`，沒有人會回頭看。

### 8.9 找出 §8.8 那種位移的**第三種偵測器**：全卷回源重抽，拿去對「已經相信是好的」那批（2026-08-07 實戰）

§8.8 說那個洞活得久，是因為現有不變式全都成立。它列了兩種偵測器（文字啟發式、
紅隊的 `data_defect` 回報）。**還有第三種，而且產率最高：把整卷從官方 PDF 重抽一次，
逐題和題庫比對。**

關鍵在**比對的對象要包含 `parse:ok` 那批**，不是只比你已經懷疑的那批。實測：某卷 216 題
`parse=ok`，重抽後 215 題逐字一致、**1 題不一致**——那 1 題就是位移題，`parse=ok`、
正在供題、還有一則 `high` 把握度的詳解。它不在任何工單、任何 review 清單、任何啟發式的
命中裡。

> **不一致要往兩個方向讀。** 直覺會把每一筆不一致當成「我的抽取器壞了」，於是一路調
> 抽取器直到不一致歸零——那正好會把唯一的真缺陷一起調掉。實測 16 筆不一致裡 15 筆是
> 抽取器的頁碼頁眉沒清（修抽取器），1 筆是題庫真的壞了（修資料）。**先把抽取器修到只剩
> 少數不一致，然後逐筆親眼看那幾筆是誰錯。**

#### 這個偵測器自己的兩個陷阱（不處理會反過來製造假案）

**(a) 標記碼與內容碼撞號。** §8 說標記是 PUA `U+E18C–E190`。**同一批碼在很多卷裡
同時是選項內文的 ①②③④**（組合題「僅①④」）。拿 `re.split` 切標記，會把選項內文的
圈號一起吃掉：`僅①④` 抽出來變成 `僅①①`。後果是**整批組合題被誤報成缺陷**——實測全站
掃描第一版報「33 題隱形損壞」，逐筆看完只有 1 題是真的，其餘 32 題是切壞的假案。
> 對策：**每一卷先驗這卷的圈號是真 `U+2460–2463` 還是 PUA**，兩者不能共用同一支切法。
> 驗法就是上面的校準：切完拿去對 `parse=ok` 那批，一致率低就是切法不適用這卷。

**(b) 相容表意文字讓覆蓋率靜默歸零。** 科目名裡的「理」在官方 PDF 是相容表意文字
`U+F9E4`，題庫是 `U+7406`；**畫出來一模一樣，比較不相等**。用它組 qid 去查題庫，
查無、`continue`、不報錯——實測 99 卷只對上 24 卷，而報告照樣印出「比對 912 題、
不一致 13」，看起來很像好消息。（§13 講兩類造字的判準；這裡補的是**它的後果會偽裝成
少量發現**。）
> 對策：**比對前一律 NFKC**；而且**報告第一行永遠先印覆蓋率**（比對了幾題／全卷幾題），
> findings 印在覆蓋率後面。先看見 75% 才有資格看見 13 筆。

#### 修的時候，答案字母的錨在外部，不在題庫自己

位移題的選項與答案字母是同一件事的兩半，**只修一半就是靜默改分**。直覺做法是「保留
現行正解的**文字**，在新選項裡找它的位置，據此重算字母」——**這是錯的**，它預設題庫
自洽，等於在兩個都可能壞掉的欄位之間猜一個。

正確的錨是**外部的官方答案鍵**（門 §A 已經逐題驗過的那份）。官方字母是**對著原卷的選項
順序**講的，而回源重抽正好重建了原卷順序 → 所以正解是**保留字母、整組換選項**。
實測那題若照「文字錨定」做，會把官方的 D 改成 C，**與官方答案鍵相反**。

> 一般化：**兩個內部欄位打架時，先找有沒有第三個外部來源**，再決定要不要立規則。
> 立規則是最後手段，不是第一直覺。

#### 修完的順序不能反：先修資料、生詳解、過紅隊，**最後才升 `ok`**

`parse:review` 的實質作用是「排除在預設題池外」。所以修好題目就把 `parse` 升 `ok`，
會讓那題**帶著空詳解進題池**。升 `ok` 是最後一步，不是修好的慶祝。

### 8.10 造字還原**不可以用一張全域對照表**：同一碼位在不同字型是不同的字（2026-08-13 實戰）

§8.1 那張表寫「Adobe Symbol 編碼 + 逐題上下文建對照表還原」，**隱含了一張全站通用的
碼位→字元表。那個隱含前提是錯的**，而且錯法是靜默的。

升學 ast 實測 132 題、1,472 個造字，全部是 `0xF000 + 原始字碼`。但那個「原始字碼」是
**該字型自己的編碼**，不是 Latin-1：

| 碼位 | 在哪一卷 | 字型 | 真正的字 |
| --- | --- | --- | --- |
| `U+F0A3` | 數學／物理／化學 | SymbolMT | `≤` |
| `U+F0A3` | **公民與社會**（13 次） | **Wingdings2** | 另一個圖形，**不是 `≤`** |

全域 find-replace 會把公民題裡的圖形悄悄換成「≤」。**這比造字更糟：亂碼看得出壞掉，
錯字看起來是對的。** 同樣情形還有 `U+F02D`／`U+F06C`／`U+F06D` 各自跨 CIDFont／Wingdings。

**做法：回原卷取字型歸屬。** `bank.json` 是純文字，字型在入庫時就丟了，所以：

```python
# page.get_text("rawdict") → span["font"] 就是該字的字型
per[(卷名, 碼位)] = span["font"].split("+")[-1]   # 去掉 ABCDEE+ 子集前綴
```

實測 263 個（卷、碼位）組合中，**同卷同碼位跨字型者 0 個**——所以「卷＋碼位」足以
唯一決定字型，替換才是機械且安全的。**這個前提要當場驗，不要假設**：本站的
`fix_ast_pua.py` 在發現同卷同碼位有兩種字型時直接 `SystemExit`，不自己挑一個。

#### 三件配套的事

1. **每一條對照都用題目上下文實證，不要憑記憶。** 憑記憶 `0xBB` 會寫成 `↔`；
   實際上下文是「參考數值：√2 ◆ 1.414」→ 是 `≈`。（`↔` 在 Adobe Symbol 是 `0xAB`。）
   一條錯的對照會產出**看起來正常的錯字**，比空白難發現得多。
2. **延伸括號碎片（Symbol `0xE6-0xF1`、`0xF3-0xFB`）不是字元，不可替換。**
   那是 Word 把 `[`／`{` 拉高時用的上／中／下切片，用來畫矩陣外框與聯立方程式大括號，
   沒有對應的 Unicode 語意。硬換成 `⎡⎢⎣` 只是把看不見的壞換成看得懂卻是錯的排版，
   **而且新的壞法看起來像我們修好了**。這些題要的是重建（同 §8.5／§8.6），不是替換。
   實測 190 個，佔 ast 造字的 13%。
   ⚠️ `0xF2` 夾在這個區間裡但**是真字元 `∫`**（上下文：「試求 ◆₋₃ f(x) dx」），別一起排除。
3. **子集化字型的字圖名可能只剩佔位名**：內嵌的 SymbolMT 連 `cmap` 都被剝掉，
   MT-Extra 的 `(3,0)` cmap 還在但名字全是 `uniF086` 這種——**看得到表不等於查得到答案**。
   查不到就不動、只回報（實測 108 個），別用相鄰碼位去推。

#### 🔴 修好上游，會讓下游靠「舊形狀」比對的偵測器**安靜失效**

這一條是本次最貴的副作用，而且它不會報錯。`md_table_to_struct.py` 有個
`looks_like_data()` 用來提醒「表頭其實是資料列」，判準是 regex `[\d\s.×^+-]+`。
把造字還原成真正的 `−`(U+2212) 之後，**這個 regex 再也配不到數值格**——
偵測器沒有壞掉的樣子，它只是不再示警。

> **通則：修好一層資料，等於改變了下游所有「以字元形狀為判準」的偵測器的輸入。
> 改完要回頭確認它們還會叫**，做法是拿一筆 known-bad 餵進去看它是否仍示警
> （同 skill `cjk-responsive-text-layout` 的「新判定式要在 known-good 與 known-bad
> 各跑一次」）。

補好 regex 之後它立刻示警，而**它抓到的其實是比缺表頭更嚴重的缺陷**：
`111_分科化學_3`／`_4` 掛著的表根本屬於 5-6 題組（原卷的「表2」），而第 5、6 題是空的。
照原樣轉會在兩題不相干的題目底下畫出一張化學平衡表。**一個為 A 缺陷設計的啟發式，
示警時抓到的可能是 B 缺陷——不要只看它有沒有叫，要看它叫的那一題到底怎麼了。**

重建後用**兩把獨立的尺**反驗（值來自文字座標重排，答案來自官方答案鍵）：
第 5 題答案 B（乙讓 Ar 進得去、丙全為 0 → 乙＞丙）與第 6 題答案 C（K·P=1 → x=0.5）
同時成立。**一張湊錯的表不可能同時湊出兩個官方答案**——這比「我對過原卷了」強得多。


## 10. 題組共用案例段被整段丟掉（國考實戰，2026-08）

### 症狀：模型抱怨「無法從現有資料」

nursing A′ 生成 8,976 則後 lint，3 則被判 `data-complaint`：

```
102_102110_…_77  「請問小英的 BMI 為何？」        ← 沒有身高體重
106_106030_…_12  「當給予孫小姐 Gentamycin oint. 時，護理師該如何執行？」  ← 沒有醫囑
```

回官方 PDF 一看，這兩題前面各有一段**題組共用案例**：

```
情況：小英 14 歲女生，身高 150 公分，體重 45 公斤……依此回答下列第 77 題至第 78 題。
情況題：醫師為孫小姐開列下列醫囑：…③Gentamycin oint. O.U. qid…請依上文回答第 11 題至第 13 題：
```

BMI＝45÷1.5²＝20.0（官方答案 B）、`O.U.`＝雙眼（官方答案 C）。**解析器把這段整個丟了。**

### 🔴 沒喊的比喊的危險

全科掃描：**65 段案例、涵蓋 168 題**，模型只對 **3 題**喊出來。`106030_基本護理`
第 11、13 題吃同一段醫囑卻沒喊，直接寫了看起來合理的詳解——格式完美、lint 全過、
**紅隊也抓不到**，因為紅隊看到的輸入跟生成站一樣缺那段。

推論：**用產物反推缺陷永遠低估**。我先用「人名相同」的正則從題庫反推，只抓到 49 題；
回官方 PDF 數「情況段涵蓋幾題」才是 ground truth（168 題），因為它不受解析結果影響。
**缺陷規模要從來源側量，不要從產物側量。**

### 判準與邊界

```python
CASE = re.compile(r"情況題?[：:].{0,600}?第\s*(\d+)\s*題至第\s*(\d+)\s*題[^\n]{0,10}", re.S)
```

- `re.S` 必要（案例段本來就跨行）；非貪婪 ＋ 600 字上限擋住「孤立的『情況』吃掉半頁」。
- 範圍題號**用 PDF 自己寫的 N–M**，不從題目內容猜。`hi<lo` 或跨度 >10 題＝抓錯，寧可漏不可錯。
- 導覽句（「依此回答下列第 77 題至第 78 題。」）要去掉——單題練習的站上沒有「第 77 題」。
- **併進每一題的 stem，不新開 `case` 欄位**：本站單題隨機出題，使用者看不到前一題；
  併進 stem 則每題自我完備，引擎／lint／mkchunks／mkrt 全部零改動。同組 2–4 題重複
  同一段案例正是單題練習需要的。

### 🔴 CJK 相容表意文字（U+F900–U+FAFF）——PUA 選項標記的近親

修完發現 stem 變成「找護理 師。」，字中多一個空白。原因不是斷行處理錯，是

```
U+8B77 護   U+F9E4 理 ← 相容表意文字，不是 U+7406
```

畫出來一模一樣，但 **`raw.find('護理')` 直接回 -1**，`[　-鿿]` 這種字元類也框不到，
所以「兩側都是 CJK 就不補空白」的規則沒生效。跟 §8 的選項標記 PUA `U+E18C–E190`
是同一類病：**看起來對的字元不代表是對的碼位**。

```python
block = unicodedata.normalize("NFC", block)   # 單例分解 → U+F9E4 映回 U+7406
```

- **不可用 NFKC**：它會把全形標點折成半形，直接違反本站的全形不變式。
- 不要靠「把字元類寫得更寬」解決——那是打地鼠，下一個相容字元又會漏。
- **canary 要在 known-bad 上驗過**：把 NFC 拿掉重跑 selftest，必須失敗。
  不失敗的 canary 是恆真的，它保護不了任何東西。

### 還沒解的近親：人名接續的隱性承上題

`mkchunks.py` 的 `prev` 閘門比對關鍵詞（承上題／承前題／依上題／根據上題／同上題）。
但護理科大量題組是**用人名接續**的——「請問下列何者為最適合治療**李先生**目前症狀的藥物？」
前面第 27、28 題才有李先生的案例。這種題**案例在題庫裡好好的，只是沒被 `prev` 撈出來**，
與本節的「案例根本不在庫裡」是兩種病，修法也不同（一個補資料、一個補上下文）。

### 補：抽案例段的兩個邊界坑（dry-run 各擋下一個）

**1. 邊界訊號是「縮排」，不是「多欄空白」。**
案例在標記之前時要往回收，我原本用「遇到選項橫排（`\s{2,}\S+\s{2,}\S+`）就停」。
實測 `103100_產兒科` 的選項是**一行一個**、沒有多欄空白，這條判準匹配不到就一路往回吃，
把上一題四個選項全吞進案例。`pdftotext -layout` 的版面裡**選項一律有前導空白、
案例段從第 0 欄開始**——這個訊號兩種版型都成立：

```python
if not ln.strip() or ln[:1].isspace() or QLINE.match(ln) or PUA.search(ln):
    break
```

**2. 分組鍵不能想當然用 `round + subject`。**
clinical 的 `round` 欄位是 `'1'`／`'2'`（科目序，不是卷號），卷號藏在 qid 裡。
用 `round+subject` 撈同組會撈到**整科 30 題**，把案例貼到全部 30 題上。改用 qid 前綴：

```python
prefix = anchor["qid"].rsplit("_", 1)[0] + "_"
group = [q for q in qs if q["qid"].startswith(prefix) and lo <= q["no"] <= hi]
if len(group) != hi - lo + 1:      # 🔴 這道閘門是唯一擋下上面那個 bug 的東西
    skip("同組題數不符")
```

**「組員數必須等於範圍題數」這道閘門要先寫**，它才是真正的保險——貼錯科不會有錯誤訊息，
只會有一堆看起來很正常的詳解。

**3. 各科 PDF 檔名格式不同，不要維護對映表。**
`nursing` 是 `<卷號>_<科目簡稱>_試題.pdf`、`clinical` 是 `<卷號>_<科目序>_Q.pdf`、
`social-worker` 是 `<年>_<卷號>_<科目全名>_Q.pdf`。與其為每科寫一份簡稱→全名的表
（寫錯就貼到別科、而且不會報錯），不如**拿案例後面第一題的題幹去題庫比對**，
比中唯一一題才算對上。判準不依賴任何人工維護的表，且比不中會自己喊。

#### 🔴 4. 掛前情不可以對整組一視同仁（2026-08-07）

同一支工具的下一個坑：抓到「依此回答第 N 題至第 M 題」的宣告範圍之後，我把案例段
掛給範圍內**每一題**。結果 22 題裡有 16 題的題幹**本來就完整含著那段病歷敘述**
（解析時就正確吸收了），站上於是把同一段案例**渲染兩次**。回退了 19 題。

> **範圍宣告講的是「這幾題共用同一段前情」，不是「這幾題都缺前情」。**
> 缺陷與非缺陷是兩件事，同一組裡可以並存。

閘門一行：掛之前先問「這一題的 stem 是不是已經含著它」——
用案例段的**前 20 字正規化後 `in stem`** 判定，命中就跳過該題（不是跳過整組）。
另一道同樣重要的：**案例段必須從句首開始**。實測有一則抽出來是
`因，發現用後整個人感到…`（切點落在句中），這種**掛上去比不掛更糟**——
不掛只是缺前情，掛了是給了一段讀不懂的假前情。判準：首字元不得是連接詞／標點。

## §11 選項標記整體位移的第二個病徵：題幹會吸走第一個選項的前半（2026-08-02）

§8.8 記的位移是「選項內容整體挪一格」。實測還有一個**更早、更好認的病徵**：

```
題幹（壞）：… which pairings of action and actor is incorrect?summary judgement
                                                            └─ A 選項的前半跑進題幹了
選項（壞）：A ----judgejudgment notwithstanding the verdict
           B ----- jurycomplaint
           C ---- plaintiffanswer
           D ---- defendant
```

官方原文是雙欄、標記為造字：

```
[A]summary judgement----judge        [B]judgment notwithstanding the verdict----- jury
[C]complaint---- plaintiff           [D]answer---- defendant
```

**判準：題幹在問號／冒號之後還接著一段沒有標點結尾的文字。** 那段幾乎一定是 A 選項的頭。
零 token 可掃。抽出來之後每一項都往後補一格即還原。

⚠️ **這種題的 `parse` 會是 `'ok'`**——四個選項都非空、數量正確、答案有值，
所有結構閘門都過，**引擎不會隔離它，它會被當正常題出給考生**。
「格式合規」與「可作答」是兩件事。

### 🔴 掃這類缺陷時，先看 `figure` 欄再判

「`parse='ok'` 但選項全空」聽起來像必然的缺陷，實測全站 88 題**全部是圖選題的正常設計**
——選項本體在圖上，引擎有專門分支渲染「本題選項為上圖中的 A／B／C／D」。
沒有先排除 `figure` 就會去「修」88 題本來好好的題目。

### 判定式要先在 known-good 上跑（同一輪又犯一次）

想推廣上面那個孤例，我寫了「選項空或短於 3 字元／選項互相包含」當指紋——
**3,287 題命中**，因為「甲／乙／丙／丁」「①②③④」「典範／順從」本來就是合法選項。
恆真的指紋等於沒有指紋。窄指紋（選項以 `----` 之類分隔符**開頭**）掃全庫 0 命中，
才是能用的那個。

### 🔴 §11.1 偵測器回報「0 筆」時，先證明它會叫（2026-08-06；上一節的教訓重犯，故升級成機器閘）

上一節寫的是「指紋恆真＝沒有指紋」。**它的鏡像更難發現：判定式恆假時，什麼都不會發生，
而「什麼都沒發生」讀起來像好消息。**

實測：`fix_span_order_split.py` 在五科一律回報「0 筆可修」，看起來像這類缺陷已經絕跡。
真因是切塊函式寫了 `if len(parts) < 5: continue`——**四選一題只有 4 個標記**，
迴圈吃完 ①②③④ 之後 `parts` 只有 4 段（第四個選項在 `rest` 裡，下一行才補上），
於是**每一道四選一都被擋掉**，而四選一是這批資料的絕大多數。改成 `< 4` 之後：
**67 筆可修**，另有 **16,585 題被官方原卷逐字元確認切法正確**（那批的正確性此前
從未被任何外部錨驗證過，只是「沒人回報有問題」）。

它為什麼能活這麼久：**selftest 有 5 條案例，其中 3 條是「必須不切」的反例，0 條正例**。
一個恆回 `None` 的函式可以全數通過。

**升級成閘門（三條，寫偵測器時逐條對照）：**

1. **每支偵測器的 selftest 必須至少有一條正例**，而且是**真實資料的形狀**
   （造字標記就用真碼位 ``，不要用 ①②③④ 代打——兩者在同一卷會混用）。
2. **正例要能區辨**：把閘門條件改回舊寫法，那條正例**必須失敗**。做法是複製一份到
   temp 目錄、改掉那一行、跑它的 `--selftest`，斷言 exit ≠ 0。做過一次就寫進註解，
   下一個人不必重推。
3. **回報 0 的偵測器不得直接結案**：先手動找一則**已知陽性**（例如另一個管道回報的
   缺陷 qid）餵進去，確認它會叫。叫不出來就是偵測器壞了，不是資料乾淨。

> ⚠️ 派子代理時特別容易中招。本輪的指令裡寫了「找不到原卷就停手並講清楚，
> 那是正確行為，不是 bug」——**這句話本身正確**，它防的是「為了多命中而放寬閘門」。
> 但它同時讓一個壞掉的偵測器的沉默**讀起來像被授權的正確行為**。
> 要求誠實停手的同時，必須一起要求「證明你在已知陽性上會叫」。

#### 🛠 把這條變成一行指令：`scripts/prove_gate.py`（2026-08-06 加）

上面三條規則寫成散文之後**當輪又被違反了兩次**（全形冒號的替換規則、盲審卷宗的
子集斷言）。診斷不是「不知道要做」，是**這個儀式太貴**——複製檔案、還原那一行、
跑 selftest、斷言失敗、刪暫存，每次十幾行。**貴的儀式會被跳過。**

```bash
python3 scripts/prove_gate.py <腳本> '<把這段>' '<改成這段>'
# ✅ 突變後 selftest 失敗（exit 1）→ 這條斷言真的會擋
# ❌ 突變後 selftest 仍然通過 → 這條斷言不會擋，等於沒寫
```

實測四個閘門各一行證完（span 的 off-by-one、卷宗漏傳 passage、全形冒號、
題幹邊界的字元忠實閘）。它自己也有 `--selfprove`：對自己做一次真突變與一次
無害突變，**真的要失敗、無害的不能失敗**——否則這支工具會恆真地說「有效」。

🔴 **突變要打在生產程式碼上，不是打在斷言上。** 改斷言只驗得到「這條斷言是不是
多餘」；要驗它抓不抓得到 bug，得把**當初寫錯的那一行**還原回去。實測差別很大：
把 `assert set(card) == set(BLIND_KEYS)` 改成 `<=` → selftest 照樣過（因為此時
資料是完整的，兩者等價）；把 `blind()` 裡填 `passage` 的那一行拿掉 → 立刻失敗。

⚠️ 自我指涉的靶字串要**執行期拼接**（`"TAR" + "GET_REAL"`），否則它在檔內會出現
兩次（一次是靶、一次是傳給工具的參數），精準性檢查會直接拒收。

### 🔴 §11.4 逐字比對原卷只證明「忠實」，證明不了「可作答」（2026-08-06）

修完一批缺陷後，我用三條件替 18 則資料缺陷工單銷案：
**原卷逐字相符 ＋ 恰 4 個非空選項 ＋ 題幹以問號收尾**。看起來是很硬的證據。
下一步生成時，模型在同一批裡指認出 4 則仍然壞掉——**它是對的**：

| 缺陷 | 為什麼逐字比對看不見 |
| --- | --- |
| 選項 (D) 是「表示『各』」，前面的給藥縮寫不見了 | 那個字在原卷**文字層裡本來就沒有**（造字／符號），兩邊一致地缺 |
| 選項 (D) 尾巴黏著下一組的情境文字 | 原卷文字層也黏著，逐字相符 |
| 題幹寫「承上題」但沒有 passage | 前題的內容不在這一題的區塊裡，比對範圍看不到 |
| (A)(D) 應是圖譜符號，文字欄只剩說明文字 | 圖不在文字層，比對的兩邊都沒有它 |

**逐字比對證明的是「題庫忠實重現了原卷的文字層」**——這是關於**擷取過程**的命題。
「這題可以作答」是關於**題目內容**的命題。**兩者不同**：只要缺陷發生在文字層之前
（造字沒有 ToUnicode、圖不是文字、跨題引用），忠實比對就會一致地錯，而且**兩邊一致
正是它判定「通過」的條件**。

這與 §11 那條「格式合規與可作答是兩件事」同形。危險的是**這次的證據更硬**——
硬證據會讓人跳過「它證的到底是哪個命題」這一步。

**規矩**：
1. **銷案要對著工單原本的指控**逐條否證，不要用一條通用的強證據一次掃掉一批。
2. 只有**讀得懂內容的檢查**（生成器／紅隊判官）能證「可作答」。零 token 的比對永遠
   只能證「忠實」——它是必要條件，不是充分條件。
3. 銷案後若同一批在下游被重新指認，**以下游為準並重開**，不要拿上游的證據去駁它：
   它們證的不是同一件事。

### 🔴 §11.2 提案必須先證明它會改變什麼（空提案）

同一支工具的第二個坑：`--write` 寫入之後重跑，數字**沒有下降**，看起來像寫入失敗。
真因是它每次都重新提出一個**與現況逐字相同**的修改——上游那道「已經正確」的相等檢查
因為 PDF 側仍帶著頁碼而過不了，於是流程往下走到重切，重切結果當然跟已修好的現況一樣。

**修法一行：提案前先比對「重切結果 == 現況」，相同即計入 already-ok。**
更一般的規則：**任何 fix 清單，入列前要證明它會改變狀態**；否則冪等性看不出來，
而「跑了沒效果」與「跑了但寫入失敗」在日誌上長得一模一樣。

### §11.3 兩個假不一致：比對前要先確認兩邊用的是同一把尺（2026-08-06）

同一支工具的第三、四個坑，都是**資料沒問題、是比對的尺不同**：

- **CJK 相容表意文字**（詳見 §13①）：考選部 PDF 文字層大量使用 U+F900–FAFF，
  `列` 是 U+F99C 而非 U+5217。**字形完全相同，`print` 與 `git diff` 都看不出來。**
  比對函式漏了 NFC，clinical 單科 1,202 題卡在假的「字元不相等」——**真缺陷被埋在
  噪音裡看不見**。§13 早就寫了這條，仍重犯：因為它被歸類成「造字問題」，
  而我當時在處理的是「切點問題」。**跨節的教訓要在使用端也留一句。**
- **頁尾**：`頁次：6－2` 印在 `FOOTER_Y` 以內，被當內文接到最後一個選項尾巴，
  恰好 6 個字元，nursing 543 題卡住。**版面座標常數是每一卷各自的經驗值，不是通則**；
  改用**形狀匹配**（整列就是頁次才丟棄）後不隨版面位移失效。
  另有一種只印裸數字、沒有前綴的頁碼——那種靠**自我驗證的窄門**處理：
  只有在「剝掉之後兩邊剛好逐字元相等」時才剝，剝錯就不相等、自動退回人工。
  **不是猜，是解方程式。**

兩者修完：needs-eyes **4,657 → 391**、already-ok **16,585 → 20,978**。
剩下的 391 經查全部是我方擷取端的假警報（`mm³` 上標在內容流排到別處、`HCO3⁻` 的上標
負號 PDF 掉了、題庫 stem 依設計含題組 passage 而 PDF 沒有）——**三類都是題庫版本才是對的**，
再往下修就會拿 PDF 的錯覆蓋題庫的對。**知道何時收手，跟知道怎麼修一樣重要。**

### 🔴 §11.5 「原卷不存在」三次都是工具的問題——宣告資料救不回來之前，先證明你打開過它（2026-08-07）

我在 clinical 上得出「有 31 卷原卷不存在，需要回考選部補抓」，並且**準備讓使用者去跑這趟**。
實際上 **31 卷全部都在硬碟上**，三個各自獨立的工具缺陷讓它們看起來不存在：

| 缺陷 | 症狀 | 修法 |
| --- | --- | --- |
| 掃描器入口 `re.match(r"(\d{6})_")` 只認**開頭** | 檔名是 `111_111100_315_1_Q.pdf`，場次碼在第二段 → 24 卷被 `continue` 掉，**連 open 都沒有** | `re.search` |
| 頁首科目名括號寬度 | 111 年起印半形 `臨床心理學總論(一)`，比對表寫全形 | 比對前 `(`→`（` |
| 7 卷的科目欄在文字層**是空的** | 撈不到科目 ⇒ 對不上題庫 ⇒ 判定「無此卷」 | 現場用該批檔名建 **代號→科目** 表（實測 36 碼全部 1:1）；**現場建表的失敗模式是「補不到」不是「補錯」** |

三個缺陷互不相關，卻收斂到**同一個結論**——因為它們都走同一條「找不到就跳過」的路徑，
而那條路徑**不留痕跡**。這是 §11.1「偵測器回報 0 要先證明它會叫」在**檔案層**的同一條律：
`continue` 掉的檔案沒有計數，於是「掃了 7 卷」讀起來像「總共只有 7 卷」。

**升級成閘門（三條）：**

1. **任何掃描器都要同時報「處理 N／跳過 M＋逐條跳過原因」。** 只報處理數等於沒報。
   本案 M=24，印出來當場就會發現不對。
2. **宣告「無卷可驗／資料救不回來」時，產物必須逐卷附「我試了哪個路徑、失敗原因是什麼」。**
   一個沒有路徑證據的 unrecoverable 清單，不可以進入回報，更不可以變成給使用者的待辦。
3. **「救不回來」是最貴的結論**——它把成本推給人（回源重抓、重掃、甚至跑一趟）。
   所以它的舉證責任最高，而不是最低。實測本輪 39 則送 vision 的缺陷，`stoploss` = **0**：
   **每一個「讀不出來」的字元，紙上都看得見。**

> ⚠️ 附帶一條回報紀律（同一次事故的第二面）：我當時把「**1,240 題無卷可驗**」講成
> 「**30 卷缺檔**」。兩個數字都真，但差 40 倍，而且只有前者是使用者要拿來做決定的那個。
> **回報一個數字之前，先確認它回答的是對方要決定的那件事。**（詳見
> `batching-and-measurement.md` §22。）

### 🔴 §11.6 再驗證用的是同一支偵測器嗎——偵測器的盲點會被洗成「已解決」（2026-08-07）

`fix_option_tail_bleed` 第一版用**形狀**判斷「選項尾巴黏到下一組的導言」：
只認 `情況：`／`情況題：` 開頭。於是漏掉兩則直接從病歷敘述起頭的導言
（`尿比重降低…`、`張小姐因眼疾至眼科診所求診…`）——它們不長那個樣子。

**真正的傷害在下一步**：同一支工具還負責替缺陷佇列的舊工單銷案，而銷案用的是
**另一套（較弱的）判斷**。於是那則工單被標成「已解決」——
**偵測器的盲點變成了『沒問題』**，比漏抓更難發現，因為它留下了一筆通過紀錄。

兩條規矩：

1. **判準要是證據，不是形狀。** 這裡的證據是：把選項尾巴切在第 i 個字元，
   剩下的尾巴與**下一題題幹**有 ≥20 字元的共同前綴 ⇒ 那截確實是下一題的東西。
   不依賴任何關鍵字，換一批卷也不會失效。（形狀 vs 證據這條**本輪重犯三次**，
   與 gates.md「判準要認事實，不要認事實的長相」同形。）
2. **銷案必須呼叫與修復同一支偵測器**，不得另寫一套簡化判斷。
   兩套判準＝兩個盲區，而弱的那套永遠是負責發出「通過」的那套。

## §12 來源 PDF 的 ToUnicode 壞字：判準是**同一份文件內的對照組**（2026-08-02）

`106_106120_刑事法_19` 的「刑法第 339 條之 1」，那個 1 在文字層是 `U+006C`
（LATIN SMALL LETTER L），畫出來與數字 1 難以分辨。

**不要靠外部知識推導「應該是 1」**（那違反「答案從官方來源抄」）。
正確判準是**在同一份 PDF 內找對照**：

```
條之 1   ← 正常
條之 2   ← 正常
條之 3   ← 正常（2 處）
條之 5   ← 正常
條之 l   ← 只有這一處是 U+006C
```

四個正常、一個異常，且同頁就有 PUA `U+E18C`／`E18D` 當選項標記——**同一個字型的同一類毛病**。
這是**還原**不是推導。同類：CJK 相容表意文字（§10）、PUA 選項標記（§8）。

**通則：判斷一個字元是不是壞的，先在同一份來源裡找它的正常兄弟。**
找不到對照組就不要動，改標 review 讓人處理。

## §12.1 🔴 選項數的不變式要**跟同一卷比**，不要跟一個寫死的數字比（2026-08-09 實戰）

專案裡原本有兩條寫死的規則，各自在自己的科目對，跨出去就錯：

  113_分科生物_試題.pdf   (A)37 (B)37 (C)37 (D)37 (E)14
  113_分科物理_試題.pdf   (A)21 (B)21 (C)21 (D)21 (E)21

  等於七成的題使用者看不到，而它們**一個字都沒壞**。

**治法不是再維護一張科目對照表**（那張表下一年加考一科就過期，而且過期時不會有人知道）。
改成**自我校準**：

> **同一卷之內，每個「單選」的選項數必須等於該卷的眾數。**
> 眾數是多少由該卷自己決定；不等於眾數的才是缺陷。
> 多選不設上下限（官方就是 5 到 10 都可能），非選／選填 0 個選項合法。

實測這條規則在同一批草稿上：**635 個單選有 632 個符合本卷眾數，剩下 3 個的選項數是 0
（真的抽取失敗）**。零人工維護、零硬編數字，而且它對「明年多一科」是免疫的。

**推廣**：任何「每題應該有 N 個 X」的不變式，先問「N 是從哪來的」。
如果 N 是從某一科抄來的常數，它就會在下一科靜默地把好資料判成壞資料——
而**降級是靜默的**，沒有人會收到「你剛剛關掉了 553 題」這種通知。
把 N 換成「同一卷的眾數」通常零成本，而且順便把「這一卷本身很怪」也一起量出來了。

## §13 造字與相容表意文字：兩類、兩種判準（2026-08-02）

全站掃出 27 處異常字元。**它們長得一樣，但可信的還原方式完全不同**，混做會出事。

### ① 相容表意文字 U+F900–FAFF → NFC（標準規定，不是猜）

> 🔴 **這條要在「比對兩份文字」的每一個使用端各留一句**——2026-08-06 重犯一次：
> 本節早就寫了，但它被歸類成「造字問題」，而當時處理的是「切點問題」，
> 於是比對函式漏了 NFC，1,202 題卡在假的不相等。使用端的教訓見 §11.3。

Unicode 對這個區段定義了**單例分解**，`unicodedata.normalize("NFC", ch)` 就是權威答案。
實測 12 處全部有對應（論／來／了／理／行／金／切／療／精／神／都）。

🔴 **不可用 NFKC**——它會把全形標點折成半形，打壞全形不變式。
這條要寫成否證 canary：`assert fix("（甲）") == "（甲）"`，
再加 `assert NFKC("（甲）") == "(甲)"` 證明前提沒錯（否則 canary 恆真）。

### ② PUA 造字 U+E000–F8FF → **必須回源目視**

PUA 沒有標準映射。**任何從上下文推出來的答案都是推導**，違反「答案從官方來源抄」。
實測 6 個碼位，逐一把原卷該行渲染出來看字形：

```bash
# 用 -bbox 取該行字框，再裁切渲染（不必 PyMuPDF）
pdftotext -bbox 卷.pdf -            # 拿 <word> 的 xMin/yMin/xMax/yMax（點）
pdftoppm -png -r 900 -f <頁> -l <頁> \
         -x $((x*900/72)) -y $((y*900/72)) -W $((w*900/72)) -H $((h*900/72)) 卷.pdf out
```

上下文有多像也不能省這一步：`屈□長肌（flexor hallucis longus）` 看起來該是「拇」，
**目視是「踇」**（足部，不是手部）；`腔□症候群` 直覺是「腔室」，**目視是「腔隙」**。
兩次直覺都錯。

**同一碼位在不同卷要各看一次**：不同 PDF 可能嵌不同字型子集。
（實測 `U+EEE7` 在醫師卷與護理卷都是「踇」——但那是驗出來的，不是推的。）

### 三個工程細節

1. **`pdftotext -bbox` 會對某些 PDF 回傳 0 個 word**（`-layout` 卻正常）。
   退路是整頁渲染 170 DPI 直接看——比debug bbox 快。
2. **有些 PUA 在畫面上沒有任何字形**（實測 `U+F082` 出現在行尾兩次，原卷該處空無一物）
   → 正確處置是**刪除**，不是替換。
3. **未查證的碼位必須原樣保留並喊出來**，不可預設刪掉。
   這要有 canary：丟一個表上沒有的 PUA 進去，必須觸發「保留原樣」訊息。

### 🔴 掃描器要用碼位範圍，不要用字元類字面

`[豈-﫿]` 這種寫在原始碼裡的字元類，**在編輯與複製過程中容易被正規化掉**（實測整條
regex 被折成無效樣式而拋 `nothing to repeat`）。改用 `0xF900 <= ord(ch) <= 0xFAFF`
明寫範圍——多幾個字，但不會在別人複製貼上時默默失效。

### 🔴 §14 掃描器只掃「你想得到的欄位」，就只驗得到你想得到的欄位

宣告「全庫異常字元 0」之後，發佈前的不變式檢查在 `gsat/bank.json` 又抓到 26 處
造字。兩邊都沒錯：**掃描器掃的是 `stem` 與 `options`，這 26 處在 `table` 欄位**
（表格題的 `headers`／`rows`）。那個欄位存在很久，但沒有任何掃描器看過它。

判準：**掃描資料完整性時，遞迴走訪整個物件，不要列舉欄位名。**

```python
def walk(o, path):
    if isinstance(o, str):
        for i, c in enumerate(o):
            if 0xE000 <= ord(c) <= 0xF8FF or 0xF900 <= ord(c) <= 0xFAFF:
                yield path, f"U+{ord(c):04X}", i
    elif isinstance(o, dict):
        for k, v in o.items(): yield from walk(v, f"{path}.{k}")
    elif isinstance(o, list):
        for i, v in enumerate(o): yield from walk(v, f"{path}[{i}]")
```

列舉欄位名的掃描器**失敗方向是靜默的**——欄位長出來的那天它不會報錯，只會少報。
遞迴版多寫六行，換掉整個類別的盲區。**「全庫 0」這種話，只有在遞迴掃描下才能講。**

### §15 表格題的上下標會整批剝離並移位（與造字是不同的病）

同一批 `table` 欄位裡，`ZnSO₄` 入庫成 `ZnSO 4`、`Na₂S` 成 `Na S 2`、
`10⁻⁶` 成 `106`、`甲（c₁）` 成 `甲（c ） 1`——**下標被抽出來丟到字串尾端**。
造字只是順帶：`U+F06D`／`U+F065` 是 Symbol 字型的 `m`／`e`＝μ／ε，
`U+F02D` 是上標負號（同族的 `U+F0B4`＝×）。

所以看到 `table` 裡有造字時，**不要只換那個字元**——先把整格拿去跟原卷對照，
上下標多半也壞了。修法是重建整格文字，用 Unicode 上下標字元（`₄` `⁻⁶` `²⁺`），
不是塞 `<sub>`（該欄位是純字串，前端直接渲染進 `<table>`）。

### 🔴 §16 「把第一列移進表頭」這種轉換天生不冪等——而且題數斷言看不到

修表格時寫了 `rows[1:]`（把被壓下來的第二層表頭移進 `headers`）。`--write` 跑了
兩次，第二次把**真正的第一筆資料吃掉**，表格從 6 筆變 5 筆。

三件事讓它溜過去：

1. **自檢只測「乾淨輸入跑一次」**，沒測跑兩次。
2. **`assert len(qs) == n_before`（題數不變）通過了**——它數的是題，不是表格列。
   **斷言蓋不到會壞的維度時，它的通過是零資訊。**
3. 兩次 `--write` 都印「✅ 改 7 題、筆數 1258 不變」，訊息一模一樣。

抓到它的是**截圖**：畫面上資料列從「1」開始變成從「2」開始。

判準：**任何「移除／搬移某一列」的修復，都要用資料本身的形狀判斷該不該做，
不能靠「跑過沒」這種外部狀態**；並且自檢必收 `f(f(x)) == f(x)`：

```python
def is_pushed_down_header(row):     # 形狀判準，不是狀態旗標
    return bool(row) and not str(row[0]).strip() and any("ZnSO" in str(c) for c in row)

assert fix(got) == got, "不冪等——重跑會流失資料"
assert is_pushed_down_header(["", "ZnSO 4 …"])      # known-bad
assert not is_pushed_down_header(["1", "200", "50"]) # known-good
```

### §17 同一份資料有兩套渲染器，改一邊不算改完

`q.table` 由**兩處**畫成 HTML：作答引擎 `web/run.js` 的 `buildTable()`（執行期），
與靜態 SEO 頁 `_build_features/gen_deep_pages.py` 的 `render_table()`（建置期，
烤進 `exam/**/index.html`）。只改前者，靜態頁還是舊的；而且**改完資料還要重跑
`gen_static_pages.py`**，否則靜態頁停留在舊 JSON。

順帶：重生成會一併追平**其他 session 已提交但還沒生成靜態頁**的資料改動
（實測一次補了 657 檔，多數是別人的詳解文案）。commit 訊息要講明，否則看起來像自己改的。

### 🔴 §18 §14 的規則我三小時後自己又犯了一次——因為它綁錯了對象

§14 說「掃描資料完整性要遞迴走訪，不要列舉欄位名」。寫完那條、修完造字之後，
同一輪又寫了一支**新的**指紋掃描器找上下標剝離——**又只掃 `stem` 與 `passage`**。
宣告「殘留 0」之後，用肉眼在渲染頁上看到 `options` 裡還有 5 題壞著。

錯在把規則記成「這個專案的掃描器已經改成遞迴了」。**欄位覆蓋是每一支掃描器
各自的屬性，不是專案的屬性。** 新寫一支就要重新套一次，舊的改好不會傳染給新的。

實作上就是把遞迴走訪抽成共用函式，讓「只掃兩個欄位」變成要多寫程式碼才做得到：

```python
def _walk(o):
    if isinstance(o, str): yield o
    elif isinstance(o, dict):
        for v in o.values(): yield from _walk(v)
    elif isinstance(o, list):
        for v in o: yield from _walk(v)
```

### §19 同一個病灶有多種表面形態，一條指紋只蓋一種

上下標剝離在題庫裡至少兩種長相：

```
Fe O 與 Fe O 均不易溶於水 2 3 3 4      ← 元素還連著
F e O 是亞鐵離子經還原反應形成的 2 3    ← 單字母被逐字拆開
[ S ] / [ F e ] 的值小於2 to tal to tal ← 連下標的英文單字都被拆成 to／tal
```

窄指紋 `(?:[A-Z][a-z]?\s+){2,}` 只抓得到第一種——它要求每個 token 以大寫開頭，
`F e O` 的 `e` 是小寫就斷了。放寬成 `(?:[A-Za-z]{1,2}\s+){3,}` 才蓋到第二種；
第三種（`to tal`）連放寬版也漏，因為它旁邊只有一個孤兒數字，過不了數字條件。

判準：**報數字時講清楚指紋蓋到哪一種形態**。「殘留 0」只代表這條指紋抓不到了，
不代表病灶清光了。這輪的實際順序是 14 → 修完宣告 0 → 目視又找到 5 → 再修 →
另一 session 的全庫掃描器說還有 35。

## §20 科學記號與化學式的呈現慣例（Unicode vs KaTeX）

使用者 2026-08-03 裁決「依語意分流」，落成一條**機械判準**——對每一例都給唯一答案，
不必問「這算化學還是物理」：

> **上下標只有數字與電荷 → Unicode；下標含任何字母 → LaTeX。**

```
Fe₂O₃   SO₄²⁻   P₄O₁₀   10⁻⁶   ²⁰⁶Pb   NH₄ClO₄   (NH₄)₂SO₄   8.0×10⁷ m³
                                            ↑ 純數字下標／離子電荷／同位素上標 → Unicode

\( I_{\mathrm{Na}} \)   \( M_{\mathrm{U}} \)   \( R_{\mathrm{N}} \)   \( C_{\mathrm{M}} \)
                                            ↑ 下標含字母 → LaTeX
```

### 為什麼不能全用 Unicode（這是硬限制，不是偏好）

實測 Unicode 的下標覆蓋：

| | 覆蓋 |
| --- | --- |
| 下標數字 `₀₁₂₃₄₅₆₇₈₉` | **完整** |
| 上標數字與 `⁺⁻` | **完整** |
| 下標小寫字母 | 只有 `a e h i j k l m n o p r s t u v x`（17/26），缺 `b c d f g q w y z` |
| **下標大寫字母** | **一個都沒有**——Unicode 從未編過 `SUBSCRIPT CAPITAL LETTER` |

所以 `I_Na` 的 `Na`、`F_B` 的 `B` 用 Unicode **做不出來**。
（`[S_total]` 其實打得出來＝`[Sₜₒₜₐₗ]`，但那幾個冷僻碼位字型覆蓋不穩，能避則避。）

### 為什麼不能全用 LaTeX——依使用情境分流

| 情境 | 選 | 實測理由 |
| --- | --- | --- |
| 表格儲存格（`q.table`） | **Unicode** | KaTeX 在窄欄位會把儲存格撐開，手機橫捲時換行不受控 |
| 需要被搜尋／複製的化學式 | **Unicode** | KaTeX 的 `textContent` 會**重複三份**——實測 `\( n_{\text{內}} \)` 讀出來是 `n內 n_{\text{內} n內​`（MathML＋HTML 兩套並存）。頁內搜尋、純文字擷取、SEO 全部壞掉 |
| 分數／根號／向量／多層上下標 | **LaTeX** | Unicode 做不到。`\dfrac{αT}{e}`、`\overrightarrow{PA_1}`、`\overline{A_3B_3}` |
| 大寫字母下標 | **LaTeX** | 見上表，Unicode 無解 |
| 靜態 SEO 頁 | 兩者皆可 | 站上作答引擎與靜態頁**都**載了 KaTeX，所以不是能不能算繪的問題，是上面那幾條的問題 |

**最強的那條理由是降級行為**：KaTeX 載入失敗時會露出原始 `\( ... \)`；
Unicode 永遠可讀。能用 Unicode 表達的就別交給 KaTeX。

### 三條不可違反的細則

1. **同一題不得混用兩種寫法。** 實測 `114_自然_22` 的選項原本是 `\(10^2\)`
   而同題組的題幹已改 Unicode——即使選項那邊「原本就沒壞」，也一併轉成 Unicode。
   混用不是美感問題：之後沒有人知道哪一種才是「對的」，下一個人會照著錯的抄。
2. **化學式內部一律半形**（`(NH₄)₂SO₄`、`H₂O(l)`）；化學式**之間**的分隔若身處中文句中
   才用全形（`²⁰⁶Pb／²⁰⁷Pb`）。這是 content-writing 那條「數字／代碼半形」的直接推論。
3. **CJK 可以進 LaTeX 下標**：`n_{\text{內}}` 實測算繪正常、零錯誤
   （KaTeX 的 `\text{}` 吃得下中日文）。但既然 textContent 會重複，
   能寫成 `n內` 純文字時就別包。

### 檢查方式

```python
# 純數字上下標不該包進 KaTeX。🔴 這個判定式自己也要驗——
# `[\d\s.,=+\-×÷/^{}\\times]` 這種寫法會把 `\times` 拆成 \ t i m e s 六個字元，
# 於是變數 `e` 被判成「純數字」（實測誤報一次）。
BARE = re.compile(r'^(?:\\times|[\d\s.,=＝+\-×÷/^{}])+$')
assert BARE.fullmatch("40") and BARE.fullmatch("8.0\\times10^{7}")
assert not BARE.fullmatch("e") and not BARE.fullmatch("I = 40")
```

### §22 新指紋的第一版幾乎一定太寬——上語料再收，不要上 canary 再收
