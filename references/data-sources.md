## 0. 核心原則（先讀）

- **官方優先、權威答案鍵**：試題與**標準答案**都取官方 PDF。標準答案是唯一權威
  答案鍵；出版商的答案寫法**不餵進**任何生成 prompt。
- **clean-room**：只重製試題本身（§9 允許），**不抄**出版商的編排、分類、詳解。
  詳解由我們自行生成並標註「AI 整理，需查證」。
- **curl + python 優於 WebFetch**：抓官方列表 HTML 與 PDF，用 `curl -A Mozilla`
  搭配 python 正則直取連結，比 WebFetch 快且準（少一層摘要失真）。
- **逐字忠實**：解析時絕不改寫、摘要、翻譯原文；題組共用素材原文保留。
- **base64 安全鐵則**：圖一律存獨立 PNG，`bank.json` 只存**檔名**（純文字、可 lint）；
  base64 只在 build 階段於腳本內部與輸出 HTML 流動，**絕不進入對話／終端／stdout**。

## 1. 大考中心（學測）：ceec.edu.tw

學測（GSAT）／分科等大學入學考試的歷年試題與標準答案，由**大學入學考試中心**
（ceec.edu.tw）公布。網站是傳統伺服器渲染，`curl` 直接抓得到列表 HTML。

### 1.1 偵察列表頁

各科歷年試題在「歷屆試題」分類頁，網址帶 `xsmsid`（分類節點 id）參數。流程：

1. 用瀏覽器（或 `curl`）打開該科歷屆試題分類頁，記下該科對應的 `xsmsid`。
2. `curl -A Mozilla` 抓該分類頁 HTML（含各年度試題與答案的連結清單）。
3. 用 python 正則從 HTML 直接抓出 `file_pool` 連結（PDF 實體所在）。

```bash
# 範例：抓某科歷屆試題分類頁，找出 file_pool PDF 連結
curl -s -A "Mozilla/5.0" "https://www.ceec.edu.tw/xmfile?xsmsid=<科目分類節點>" \
  | python3 -c "import sys,re; \
    [print(m) for m in re.findall(r'/file_pool/[^\"'\'' ]+\.pdf', sys.stdin.read())]"
```

### 1.2 取試題 PDF + 官方標準答案 PDF

- 試題 PDF 與**標準答案** PDF 都在 `file_pool/` 下，沿 1.1 取到的連結直接 `curl -O`
  下載到 `data/raw/`。
- 命名建議與後續 parser 對齊（多年度），例如國文走 `parse_gsat.py`、英文走
  `parse_eng.py`、社會走 `parse_soc.py`。**每個科目可能需要各自的 parser**
  （題型結構不同），不要假設一支 parser 通吃。
- 標準答案 PDF 多為表格，用 `pymupdf` 的 `find_tables()` 解析出「題號 → 正解」。

### 1.3 為什麼不用 WebFetch

實測 `curl + python` 取 ceec 列表 HTML 與 PDF 連結，比 WebFetch 快且準：WebFetch
會摘要頁面、可能漏掉或改寫連結；直取 HTML 正則命中 `file_pool` PDF 最可靠。

## 2. 心測中心（會考）：cap.rcpet.edu.tw

國中教育會考（CAP）由**國家教育研究院測驗及評量研究中心**（cap.rcpet.edu.tw）
辦理。和 ceec 不同，這個網站**前端 JS 渲染**：直接 `curl` 抓主頁拿不到試題連結。

### 2.1 突破 JS 渲染：走 iframe 頁

關鍵發現：`examination.html` 用 **iframe** 載入靜態頁
`exam/{年}/{年}exam.html`，**該頁才列出各科試題連結**，且連結指向 **Google Drive**
的 file id。流程：

1. `curl -A Mozilla` 抓 iframe 頁 `exam/{年}/{年}exam.html`（這頁是靜態 HTML，
   curl 抓得到）。
2. 用正則抓 `file/d/{id}` 取出各科的 **Google Drive file id**。
3. 把每年各科的 file id 整理成 `data/raw/cap_drive_ids.json`。

### 2.2 cap_drive_ids.json 結構

外層鍵是學年度（字串），內層鍵是科目／用途，值是 Drive file id：

```json
{
  "111": {
    "參考答案": "<file_id>",
    "寫作":     "<file_id>",
    "國文":     "<file_id>",
    "英語閱讀": "<file_id>",
    "社會":     "<file_id>"
  },
  "112": { "...": "..." }
}
```

- 已蒐集 **111–115** 五個學年度的「國文／英語閱讀／社會／參考答案／寫作」file id。
- ⚠️ 目前**缺數學／自然**的 Drive id —— 擴圖式科時需回 cap iframe 頁補抓。

### 2.3 fetch_cap.py：從 Drive 下載（含病毒掃描確認頁）

`scripts/fetch_cap.py` 讀 `cap_drive_ids.json`，逐年逐科從 Drive 下載 PDF 到
`data/raw/{年}_{stem}.pdf`。重點機制：

- **科目對應輸出檔名**：以 `SUBJ_OUT` 字典映射，例如 `國文 → 會考國文_試題`、
  `英語閱讀 → 會考英語_試題`、`社會 → 會考社會_試題`、`參考答案 → 會考_參考答案`。
  只下載文字科 + 參考答案；**寫作（非選）暫不**下載（延後）。
- **Drive 大檔病毒掃描確認頁**：Drive 對大檔回傳的是一頁 HTML（`content-type` 含
  `text/html`）而非 PDF，腳本同時處理兩種版本：
  - **新版確認頁**：HTML 內含 `<form action=...>` 與隱藏的 confirm／uuid 參數
    → 解析 form 的 action 與所有 `name/value`，跟著再送一次 GET。
  - **舊版確認頁**：`download_warning` cookie 帶 confirm token → 補 `confirm=<token>`
    重新請求。
- **合法 PDF 檢查**：`_is_pdf()` 確認檔案 > 1 KB 且前 4 bytes 為 `%PDF`。
- **冪等**：已存在且為合法 PDF 則跳過；下載失敗逐檔回報、不中斷整批。
- **只印安全資訊**：檔名、KB 大小、是否合法 PDF；**不印** bytes／base64。

```bash
uv run --with requests python scripts/fetch_cap.py
```

### 2.4 會考卷的結構特性（解析時要知道）

- 全卷**四選一單選**（無多選、無五選項、無選擇式非選），比學測單純。
- 國文固定 **42 題**、社會 **54 題**；含單題與題組（題組 = 一段選文／圖文 + 數小題）。
- 國文寫作 = 非選（延後）、英聽 = 音檔（延後）。
- markitdown 線性化後，題組標頭以行內樣式辨識（如「請閱讀以下…，並回答 A ～ B 題：」），
  `passage` = 標頭後到第一個子題題號前的原文。各科有專屬 parser
  （`parse_cap_國文.py`／`parse_cap_社會.py`／`parse_cap_英語.py`）。
- 解析時以官方答案表的題號為權威、要求題號嚴格遞增（濾掉注釋的「1.」之類假題號）；
  跳過卷首約 1.5 頁的測驗說明；偵測圖表指涉詞或選項殘缺以標 `needs_figure`。

## 3. 著作權與 clean-room

### 3.1 法律依據：著作權法 §9

> **§9.1.5**：依法令舉行之各類考試**試題及其備用試題**，不得為著作權之標的。

因此**官方試題可自由重製**，不需授權、不付費。標準答案同屬考試試題的一部分，作為
**權威答案鍵**使用。

### 3.2 clean-room 紀律（受保護的不能碰）

§9 解放的是「試題」本身，**不解放**出版商加值的部分：

- ❌ 不抄出版商的**編排**（分類、難度標註、章節對應、選文導讀）。
- ❌ 不抄出版商的**詳解**；**出版商答案／詳解的寫法不餵進生成 prompt**。
- ✅ 詳解由我們**自行生成**，clean-room（只看官方試題與官方答案），全標
  「AI 整理，需查證」並附把握度；經程式 lint + 紅隊抽驗。
- ✅ 作文採**官方分級樣卷**（最高分→低分），不 AI 代寫完整作文；英文短答／中譯英
  近乎有標準答案，可由 AI 整理參考答案並標明須查證。

🔴 **禁的是「一般網頁通道」，不是「所有外部事實」**（2026-08-24 使用者裁決，證據見 §10）：

| | 判斷 |
| --- | --- |
| `WebSearch`／`WebFetch`／任何一般網頁抓取 | ❌ 永久禁。返回內容不受控，實測混進考古題詳解站 |
| 出版商擬答、詳解、考古題解答網站、二手摘要 | ❌ 永久禁 |
| **法條原文專用 API**（`tw_statute_at_date` / `tw_statute_history` / `tw_statute_search_text`） | ✅ 允許，見下 |

分界不在「查不查外部」，在**通道的形狀**：一般搜尋是「給我關於 X 的東西」，回什麼
由外面決定；法條 API 是「給我某法某條某日的原文」，語料只有法條本文、每筆帶
`law_name`／`article`／`source_url`。前者的乾淨性只能靠自律，後者靠通道本身——
而 §10 的實證正是**自律在這裡不成立**。

用它的三條紀律（都是實測出來的，不是推的）：

1. **日期填考試年度，不是今天。** 考古題考的是當時的法。`tw_statute_at_date`
   回傳該日之前最新版本並附 `revision_date`。這也是它勝過直抓 `law.moj.gov.tw`
   條文頁的地方——後者只給現行版。
2. **檢索用法條用語，不是題目的白話詞。** 實測：社工師法查「懲戒」，前三名第
   5／6／31 條全不相干（法條寫的是「停業」「廢止執業執照」「罰鍰」）；改查
   「停業 廢止執業執照」命中第 44／45／39 條。
3. 🔴 **只准引用「回傳原文裡確實有那句話」的內容。** 上面那個零命中的查詢，
   一樣回傳 5 筆、一樣有 BM25 分數——**排名不是正確性**。查到條號但原文沒有那個
   數字，等於沒查到，照樣 `c=low`。

🔴 **語料只有母法，沒有子法——而法規題的數字多半在子法。** 實測 3/3：
`嚴重藥物不良反應通報辦法`、`藥師執業登記及繼續教育辦法` 皆 `not resolvable`；
查「安全監視期」只回得到藥事法第 45 條「得指定期間……應遵行事項，由中央衛生主管
機關定之」，年限本身不在語料裡。護理機構設置標準同樣落在護理人員法第 16／19 條的
「由中央主管機關定之」。

**這個限制有一半是能力**：母法那句「由中央主管機關定之」本身就是可寫的答案——講明
該事項授權子法訂定、指出母法哪一條授權，比杜撰年限好，也比含糊帶過好。剩下一半是
硬限制：子法數字查不到就 `c=low`，**不得拿母法條號去掛一個沒讀到的數字**。

所以這條窄門解掉的是「杜撰」，不是「答不出來」。本輪那 17 段卡住的法規題，預期只有
一部分能真正補上具體數字。**開通道前先報這個上界，不要讓它看起來比實際能幹**。

**條款只能有一份**：全站唯一正本是 `goldens/mkprompt.py` 的 `_CLEANROOM`，由
`build()` 注入每一站（含稽核站）。理由見 `explanations-redteam-lessons.md` §clean-room
條款的 12 分之 2。

### 3.3 授權：三層，各有各的理由

方法與程式碼（scripts、引擎）採 **MIT**；題目資料依著作權法 §9 屬公共所有；
作文範本屬官方機關依其授權提供。

理由（見產物 `docs/DECISIONS.md`）：**norms over laws**——與其用 copyleft 強制衍生開源，
不如把 fork／改作／商用的自由給滿，讓「開放比封閉更好用」自己長出規範。

## 4. 範圍決策（由維護者拍板）

範圍是**對象決策**，不是技術決策 —— 由維護者依服務對象拍板。本專案目前：

- **只收新課綱 111 學年度起**（收 111–115），舊課綱不收。
  - 理由：聚焦範圍、避免課綱落差造成誤導（本專案對象是新課綱第一屆）。
- 學測與會考放在同一平台、用考試選擇器切換，**預設不跨考混題**。
- 國考（專技、不同對象）各自獨立，不併入升學平台。

新維護者要服務不同對象（例如要收舊課綱、或另一個國家的考試）時，自行調整收錄範圍，
其餘流程（偵察→下載→解析→題庫→裁圖→詳解）不變。

### 4.1 年度涵蓋是**開工前的一次決策**，不是逐題判斷（使用者裁定 2026-08-23）

「舊年度要不要做」有一條明確判準，而且它先於任何生成：

1. **該科目／法規有沒有改版？有 → 舊年度不做。**
   不是因為成本，是因為**補了會教錯**——過時的法條、被廢的準則、改制前的程序，
   對考生是負分。這一條凌駕「儘量多收」。
2. **沒改版 → 在既定年度窗內儘量做**，典型是**五年或十年**。不必然全做。
3. 🔴 **要做幾年，開工前就定好並寫進 `meta`。** 不可以邊做邊決定。

第 3 條是整條規則的重點。年度窗一旦變成「做到哪算哪」，就會出現三種後果，
而**三種都不會報錯**：

- **同一科不同年度的深度不一致**，而使用者看到的是同一個科目頁；
- **「還沒做」與「決定不做」在資料上同形**（都是 `ref: null`／沒有詳解），
  於是下一輪沒有人分得出剩下的是待辦還是政策；
- 進度數字失去分母——`204/215` 這種比例，只有在 215 是**事先定下的目標**時才有意義。

⇒ 落地要求：`meta` 裡要能讀出**當初定的年度窗、判準（有無改版）、以及排除項的理由**。
`essays.json` 的 `meta.legacy_note` 是這個欄位的範例：它同時寫了政策與本輪實況，
且把「依政策不做」（作文 11 則）與「做了沒過」（紅隊未過 96 則）
與「做不出來」（生成端 5 則）**分成三個數字**，而不是合併成一句「還缺 112」。

## 5. 題庫 schema：bank.json（每題）

`bank.json` 是純文字題庫，每題一個物件。**圖只存檔名**，build 時才內嵌（見 §6）。
每題欄位：

| 欄位           | 型別        | 說明 |
|----------------|-------------|------|
| `qid`          | string      | 全域唯一題 id；merge 以此為鍵（冪等）。 |
| `exam`         | string      | 考試別：`學測` / `會考`。 |
| `year`         | string／int | 學年度，例如 `111`–`115`。 |
| `subject`      | string      | 科目，例如 國文／英語／社會。 |
| `no`           | int／string | 該卷題號。 |
| `group_id`     | string／null| 題組 id；同一題組的小題共用。非題組為 null。 |
| `passage`      | string／null| 題組**共用素材**（選文／圖文敘述）原文；非題組為 null。 |
| `stem`         | string      | 題幹（逐字忠實，不改寫）。 |
| `options`      | object／array| 選項，如 `{"A": "...", "B": "..."}`；文意選填等以 A–J 詞庫存。 |
| `answer`       | string／array| 正解；**可多選**（多選逐選項，如 `["A","C"]`）。 |
| `type`         | string      | 題型：`單選` / `多選` / `題組` / `非選`。 |
| `needs_figure` | bool        | 是否需要圖（圖表指涉詞或選項殘缺時為 true）。 |
| `figure`       | string／null| 圖檔名（**只存檔名**，如 `C111_社會_g44_45.png`），無圖為 null。 |
| `standalone`   | bool        | 該子題能否**單獨出現**（預設 true）；`承上題`類標 false。見下方「題組欄位與作答政策」。 |
| `locate_anchor`| string／null| 給裁圖定位用的 PDF 忠實錨點，**永不顯示**。凡改寫過 `stem` 就必須有。見下方「轉寫題幹的定位錨點」。 |

補充：實作中部分題另帶 `section`（卷內區段，如 詞彙／綜合測驗／閱讀）等輔助欄位，
但上表為核心契約。

### 題組欄位與作答政策（`group_id`／`passage`／`standalone`）

`group_id` 綁同組，**解析時建、絕不拆散**。`standalone` 是「該子題能否單獨出現」。

分類規則（哪些字樣算承上題、「上述／如圖」怎麼分）正本在 parsing.md §4′；這裡不重述。

🔴 **共用圖與 passage 必須寫進該組「每一個」子題**——每子題都帶自己的 `figure`／
`passage`，即使共用同一張。不然一個 `standalone=true` 的子題被單獨抽出時會缺圖、
缺材料而變廢題。（圖的 group propagation 見 `figures.md`。）

這兩欄落地後，前端引擎怎麼在不同作答表面顯示題組情境（原文完整引入、只引題幹、
鏈式堆疊、各表面分工），見 `frontend-engine-rules.md` §1。

### 轉寫題幹的定位錨點（`locate_anchor`）

`stem` 預設逐字忠實。但數學等科若把題幹轉成 LaTeX 或清洗後顯示，
**轉寫過的 stem 已對不上原卷 PDF 文字層**，裁圖靠 stem 比對定位就會失敗或抓錯區塊。

凡會改寫 `stem`，就另存一條 PDF 忠實的定位錨點：**題號＋第一個數學符號前的純散文前綴**，
要求頁內唯一。**定位走它、永不顯示。**

🔴 **為什麼不能用「把整段 ASCII 化」來救**：PDF 的數學符號文字層本身常是 PUA 造字、
壞 `ToUnicode`、或根本沒編碼——**匹配不到不存在的字**。
詳見 skill `exam-pdf-asset-extractor` 的「Locating the Question」。

### 圖檔命名（由 extract_figures 寫回 figure 欄）

命名規則的正本在 `figures.md` §三「檔名規則」（在「band 邊界怎麼決定」節內）；這裡不再重述
（2026-08-23 發現兩份各寫一套、而且都與實際 bank 不符）。

## 6. 圖的 base64 安全架構（只描述、不貼任何 base64）

為了讓題庫**可 lint、可 diff**，又能做出離線單檔，圖走三段式：

```
原卷 PDF ──extract_figures──► data/figures/{檔名}.png   （獨立二進位 PNG）
                                      │
bank.json 只寫 figure="{檔名}.png"     │  （純文字、可 lint、可 git delta）
                                      ▼
build_app.py 建置時：PNG ──► base64 ──► 內嵌進 window.__FIGS__（輸出 HTML 內）
```

- `data/figures/` 存獨立 PNG（pymupdf 整塊 render，raster+vector 一起點陣化，
  zoom 2.2；**保真不失真壓縮**）。
- `bank.json` 只存**檔名字串**，永不寫 base64 —— 保持題庫純文字、可 lint、git 可 delta。
- `build_app.py` 建置時才把 PNG 讀進來 base64 內嵌成 `window.__FIGS__`；前端
  單檔走 `__FIGS__`、dev 走 `../data/figures/`。
- **鐵則**：base64 全程只在 build 腳本內部與最終 HTML 流動，**絕不進入對話、stdout、
  Read 或任何工具輸出**。萃圖腳本只印張數／位元組大小／檔名／座標／計數，
  驗圖一律用 Read 直接開 PNG，不 cat、不印 bytes。

## 7. 端到端流程速查

```
偵察 ──► 下載 ──► 轉檔 ──► 解析 ──► 答案鍵 ──► 題庫 ──► 裁圖 ──► 詳解 ──► 打包
```

| 階段   | 學測（ceec）                          | 會考（cap）                                |
|--------|---------------------------------------|--------------------------------------------|
| 偵察   | curl 列表 HTML，正則取 `file_pool` PDF | curl iframe `exam/{年}/{年}exam.html`，取 Drive file id |
| 下載   | `curl -O` 試題＋標準答案 PDF           | `fetch_cap.py`（讀 cap_drive_ids.json，處理確認頁） |
| 轉檔   | markitdown PDF → md（解決閱讀序／題組） | 同左 |
| 解析   | `parse_gsat.py` / `parse_eng.py` / `parse_soc.py` | `parse_cap_{國文,社會,英語}.py` |
| 答案鍵 | 標準答案 PDF `find_tables()` → 題號→正解 | 參考答案 PDF（多科一覽表）定位各科欄 |
| 題庫   | merge 進 `bank.json`（qid-keyed 冪等） | 同左 |
| 裁圖   | `extract_figures.py`（S/G 命名）       | `extract_figures_cap.py`（C 命名） |
| 詳解   | 生成 → 抽驗升級（k≥4/40）；**模型配置見 SKILL.md §模型路由，該處標了日期與保鮮期** | 同左 |
| 打包   | `build_app.py` → 單檔 HTML（圖 base64 內嵌） | 同左 |

模型路由：抓資料／轉檔等機械工作用較小模型；文字科解析與詳解用中階模型；題組長文、
難題、圖式、紅隊查核用最強模型。詳解抽驗採統計規則：抽樣錯誤達 k≥4/40
（錯誤率下界 ≥4%）才升級到更強模型重做。

## 8. 國考（考選部）：MCP 拿題 + 官方 PDF 拿答案（雙來源）

國考（高普考／律師／司法官／會計師／醫師／教師等）有別於學測會考——題量極大（考選部
dataset 170565：64,815 卷、320,663 題、2000 至今），且**有現成的開放資料 MCP 鏡像**
（Twinkle Hub 的 exam corpus）。但**答案不在 MCP 裡**，仍要回官方 PDF。雙來源分工：

| 要拿什麼 | 來源 | 工具／做法 |
|---|---|---|
| 整卷題目 | Twinkle Hub MCP | `get_exam_paper(paper_id)` 回整卷題幹＋選項 |
| **跨年挑特定主題題目** | Twinkle Hub MCP | `search_exam_questions(query, stem_contains=, exam_type=, subject=, year_from=)` — 題目層級語意檢索，建新題庫挑題很方便 |
| **選擇題標準答案** | **官方 PDF（非 MCP）** | curl 考選部「測驗式試題標準答案」PDF → `pdftotext` / `pymupdf find_tables()` 解出題號→正解 |
| 申論參考解 | 無官方解 | 自行 AI 生成＋紅隊（見 explanations-redteam.md） |

**關鍵坑（實測）**：MCP 的語意向量**只 embed 題幹，選項與答案不入索引**，所以
①「找答案提到 XX 的題」搜不到 ②MCP **完全沒有答案欄位**——別期待 MCP 給標準答案。
答案唯一權威仍是官方 PDF（同 §0 原則）。所以國考管線＝**MCP 拿題（語意搜尋挑題更靈活）
＋ 官方 PDF 拿答案（逐題全驗）**，兩來源獨立、可交叉對照，不單押一個來源。

> 載入對應的 `tw-opendata-exam` skill 可取得這三個 MCP tool 的完整簽名與 query 範例。

### 8.1 答案 PDF 的「備註」欄有**四種**處置，別混成一類（2026-07-30 實測）

答案 PDF 除了題號→正解的主表，檔尾還有一段「備註：」，處理有爭議的題目。
它有四種措辭，**語意完全不同、詳解寫法也不同**，而且答案表裡對應的格子多半標 `#`：

| 官方措辭 | 意義 | `answer` 該寫什麼 |
|---|---|---|
| 「第 N 題**一律給分**」 | 題目有瑕疵，全員給分 | `#`（送分標記） |
| 「第 N 題**除未作答者不給分外，其餘均給分**」 | 有作答即給分 | `#` |
| 「第 N 題**答Ｄ給分**」 | **官方更正後的單一正解** | `D`——這是正常題，不是送分 |
| 「第 N 題**答Ｂ或Ｃ或BC者均給分**」 | **官方認可多個答案** | 見下方 `accept` 欄 |

🔴 **把四種混成「送分」的代價**：某科 70 題的 `answer` 被寫成字面字串 `'None'`
並全數降 `parse:'review'`，進度文件記成「70 送分題」。實際拆開是
38 多重答案／21 一律給分／7 **官方更正單一答案**／4 有作答即給分。
**那 7 題官方明明白白公布了正解，卻因為被歸進「無答案」而躺著沒人撿**
——最容易修的一類反而最晚被發現。

**單選題官方認可多個答案 → 新增 `accept` 欄，不要寫成 `answer:'BC'`。**
`answer` 保留官方列的第一個（維持既有引擎相容），`accept:['B','C','BC']` 列全部
可接受組合，判分時有 `accept` 就比對它。寫成 `answer:'BC'` 會被既有多選集合評分
讀成「兩個都要選」，把「兩者皆可」誤變成「兩者皆須」，只選 B 的學生（官方認可）被判錯。

🔴 **前端沒接 `accept` 之前，這些題不得升 `parse:'ok'`。** 升了就是拿官方認可的
答案去判學生錯——比維持 `review` 不出題更糟。修復腳本要有這道閘（旗標控制），
別讓「覆蓋率好看」推著資料提前上線。

**解析備註的兩個實作坑**：

1. **逐句切開再比對，不要跨行正則。** `第{no}題[^。]*?(一律給分|均給分)` 這種寫法會
   跨換行吃掉整份答案表（PDF 文字層把題號一行一個垂直排列），hit 回來是垃圾。
   做法：先 `re.search(r"備\s*註\s*[:：](.*)", text, re.S)` 取出備註整段、壓掉空白，
   再 `re.split(r"[，。]", seg)` 逐句、只留 `^第{no}題` 開頭那句。
2. **全形答案字母要正規化**（`ＡＢＣＤ` → `ABCD`），備註裡兩種寬度混用是常態。
3. **題號前綴污染**：`第1題` 的 regex 會命中「第16題」。用 `^第{no}題(?!\d)` 錨住，
   並把「鄰題有註記、本題沒有」與「第16題 vs 第1題」寫成 selftest 的否證 canary。

## 9. 換資料來源：三條實測教訓（2026-08-18，法規正本從 HTML 爬蟲改走官方 bulk dump）

### 9.1 🔴 正規化的差異會偽裝成內容的差異

換來源那天，任何用**全等比對**判斷「有沒有變」的閘都會全紅。實測：法條正本從逐部爬
HTML 改成官方 bulk dump，同一條條文的**字**沒變，但舊來源被 `NFKC` 壓過（全形逗號
`，` U+FF0C → 半形 `,`），官方原檔又用 CRLF 與 U+3000 縮排——**6,989 條裡 6,887 條
（98.5%）在全等比對下不相等**。

要命的是那支比對器的用途：它產出「修法影響清單」，列出引用到異動條文的題號。
換源當天它會把**所有引用過法條的題**都列進去。

> **一份把所有東西都標成受影響的清單，與空清單一樣沒有資訊量**——差別只在
> 它還會消耗信任。而且它會讓人開始不看這份清單，於是下一次真的有修法時也不會有人看。

修法：比對前先取正規形（NFKC ＋ 空白摺疊）。**這不是放寬判準**：字有變才算變，
字寬與行尾不算。反例要兩個方向都寫——「全形半形不算異動」與「字真的變了一定要抓到」。
實測 98.5% → 5.1%，剩下的是真的被清乾淨的污染條文。

判準：**凡是拿「原文全等」當判準的地方，先問「這個原文經過幾層處理」。**
只要答案大於零，那個閘就對來源、編碼、落盤格式的任何改動敏感，而那些改動遲早會發生。

### 9.2 NFKC 的作用範圍要寫死，因為它同時在救與砸

同一個 `unicodedata.normalize("NFKC", …)`：

- **解析考卷時是必要的**——官方 PDF 的文字層會出現 `U+F98E`（CJK 相容表意文字的「年」），
  不還原成 `U+5E74` 就搜不到、比不到。
- **處理法條全文時是破壞性的**——它把 `，；：（）？！` 壓成半形，而 `。、「」` 因為沒有
  相容分解所以活著。產物是個**半形全形混雜的嵌合體**，而它的用途正是「拿來比對官方原文」。

存活與死亡的分界線正好是 NFKC 的分解表——這也是歸因時最硬的一條證據：
如果你懷疑某批文字被 NFKC 動過，去看**哪些標點活著**，那個模式是簽名。

所以：正規化要綁在**欄位**上，不要綁在「整頁文字」上。條號要 ASCII 化就只作用在條號，
內容逐字保留。整頁一次過的寫法看起來乾淨，代價是它會處理到你沒打算處理的東西。

### 9.3 「重建」與「檢查是否過期」不必用同一個來源

它們回答的問題不同：

| 站 | 要的是 | 適合的來源 |
|---|---|---|
| `--build` 重建正本 | **正確的全文** | bulk dump（一次抓完、結構化、沒有版面殘渣） |
| `--check` 是否過期 | **最新** | 即時網頁（dump 有整編截止日，實測落後現行公布 7–14 天） |

拿一份可能落後兩週的資料去回答「新不新」，是把兩個問題混成一個。
附帶好處：留著即時抓取的那一站，等於保留一個**每月實跑一次的探針**——
它會在官方改版打壞解析時出聲；全部改吃 dump 之後，只要 ZIP 下載成功就幾乎恆綠。

### 9.4 附帶：bulk dump 換掉爬蟲時，別把爬蟲的斷言一起丟掉

舊路徑有一條「頁面必須含預期法名」的斷言，它擋下過一次真事故：`pcode` 被填成另一部
法規（名字很像、只有 9 條），導致 34 筆正確引用被判成錯誤。改走 `pcode` 索引之後，
**pcode 填錯一樣會安靜地撈到另一部法**——斷言必須跟著搬過去，不是隨爬蟲一起退役。

同理要補的兩條：來源若含已廢止項目（實測該庫有 322 部），撈到要擋；
識別碼（條號）認不出格式要**大聲失敗**，不要靜默丟棄——擴列時那就是無聲缺條。

## 10. clean-room 禁搜尋不只是原則，是工具限制（2026-08-24 實測）

§3.2 禁 WebSearch 的理由原本只當**原則問題**在理解——法條原文不是誰的加值
內容，似乎可以討論放寬。子代理給了一個沒想到的**實務證據**，改變了結論：

> 「我查眼用軟膏放大倍率時，搜尋結果**直接混進了 yamol.tw（考古題詳解網站）
> 的頁面標題與摘要**——這正是操作卡要防的那種二手內容。就算我的**意圖**是查
> 政府公告，工具回傳的東西已經摻了別人寫的詳解，我事後也**無法乾淨地切割**
> 『這句是法條原文、這句是某網站的解讀』。」

**規則**：意圖乾淨不代表輸入乾淨。「只查政府資料庫」是一個關於**意圖**的承諾，
而 WebSearch 是一個關於**返回內容**的工具——兩者之間沒有任何機制把後者約束成
前者。clean-room 是對**輸入**的保證，所以它只能靠「不接觸該通道」來維持，不能
靠「接觸了但只取乾淨的部分」。

**實測範圍**：本輪 8 塊修復有 6 塊受影響，兩個代理合計查了 24 次；精確清單
9 qid／17 段（另一代理的清單待補），p6 全 20 題 26 段完全乾淨。

**配套（代理提的窄門形狀，尚未實作為機器閘）**：不是開放搜尋，是開放**白名單
網址的直接抓取**——只 fetch `law.moj.gov.tw` 等特定條文頁的**原文全文**，不做
關鍵字搜尋、不看第三方摘要，且每次使用留稽核紀錄，讓事後能逐筆檢查「這段是不
是只碰了條文本文」。差別在於：前者的乾淨性靠自律，後者靠通道本身的形狀，與
§3.2 的既有立場（clean-room 只能靠不碰通道維持）並不衝突——放寬的只是「通道」
從零擴大到一個受控白名單，不是放寬「可以看二手內容」。

✅ **已裁決（2026-08-24，使用者）：開，但通道換了。**

- 禁的理由（§3.2 原文）：搜尋結果把別人寫的詳解拉進來——著作權汙染的顧慮。
- 但政府法規資料庫的條文原文不是任何人的加值內容；不查的代價是模型只能杜撰
  數字或迴避，兩者對學生都更糟。
- 本輪實例：藥師法執業經驗年限、醫療器材安全監視期、不良反應通報期限等 7 項
  法定期限與機關名稱。

最後採用的不是代理提的「白名單直抓 law.moj.gov.tw」，而是**法條原文 API**
（Twinkle Hub 的 `tw_statute_*` 三支 MCP）。兩者的乾淨性論證相同，但 API 多兩件事：
回傳是結構化欄位不是 HTML 頁面（不必自己判斷頁面上哪塊是條文），而且
`tw_statute_at_date` 給得出**考試當年**的版本——直抓條文頁只有現行版，用它解
101 年的題會答錯。落地規則寫在 §3.2，不重複於此。

⚠️ **這條窄門不是「可以查證了」的通行證**：它只回答「某法某條某日寫了什麼」。
藥品仿單、機關公告、教科書共識都不在語料裡，那些仍然只能靠學科知識或 `c=low`。
