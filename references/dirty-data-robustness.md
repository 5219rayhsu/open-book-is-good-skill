## 一、五條通則原則

1. **寬鬆 token 匹配 ＋ 先正規化，再比對。**
   永遠不要用 exact-match 比對檔名或科目名（`*_數學A_試題.pdf`、`s + '科' in t`、`'數學a' in fn`）。政府檔名同一份東西會出現「試題／試卷／試題定稿」「數學A／數a／數學ａ」「會考英語／英文」「自然／自然科」等變體。做法：
   - 進入任何字串比對前，先 `unicodedata.normalize('NFKC', s)`。NFKC 一次把全形英數（`Ａ`→`A`、`１`→`1`）、全形括號（`（）`→`()`）、全形空白（`U+3000`）折回半形，中文與標點不受損（`試題`、`自然科` 等 CJK 字元不變）。注意 NFKC 不會自動轉小寫，仍需另接 `.lower()`。本專案 23 個腳本只有 2 個有做正規化，這是最大的系統性破口。
   - 檔名用寬鬆 glob（`*數學*試題*.pdf`）撈出候選，再用 NFKC + 正則抽年份與科目關鍵字確認，別用 `%d_%s_試題.pdf` 直接拼路徑。
   - 科目／選項字母用「別名集合」而非單一字串：`{'數學A','數a','數學ａ'}`、選項正則同時吃 `[（(]\s*([A-DＡ-Ｄ])\s*[）)]`。
   - **連『年份／類型』判斷也別退回 exact-match。** 年份常只出現在 URL path 而檔名沒有「學測」二字；類型可能是「試題／試卷／定稿」。年份從「檔名 ＋ 連結文字 ＋ URL path」三處任一抽到即可，不要強求單一來源都帶「學測」。

2. **缺檔／0 筆結果，先懷疑「命名變體」，且必須報錯。**
   `glob` 回空、`find_tables()` 回空、`classify()` 全 miss——這些幾乎都是命名或版面漂移，不是「今年真的沒資料」。鐵律：
   - `if not years: raise` 或 `sys.exit(1)`，絕不靜默寫出 `[]` / `{}`。
   - 缺檔不要 `return []` 後繼續，要 log 出「哪年哪科哪個路徑沒找到」並計入失敗清單，最後非零 exit code。
   - **多重命中也要當異常處理。** 別名比對若同一字串同時命中多科（如檔名含「數a」又含「數b」），代表合卷或檔名拼接，不能只取第一個命中——應蒐集全部命中，>1 時 raise 或至少 `logging.warning` 留下完整檔名，否則會「錯分一筆」這種比零筆更難察覺的髒資料。
   - 跨年批次用 `try/except ... continue` 包住單年，讓一年壞掉不會炸掉整批、其他年仍能寫出。

3. **驗證內容，不要只驗 URL / 副檔名。**
   `r.content[:4] == b'%PDF'` 過不了截斷下載；`status_code` 4xx/5xx 也可能被當成功；Google Drive 確認頁／CAPTCHA 頁會被當 PDF 寫進磁碟。做法：下載後 `r.raise_for_status()`、用 `pypdf.PdfReader` 確認 `len(pages) > 0` 或至少驗尾端有 `%%EOF`；解析後驗題數（如會考社會應 54 題、學測自然應 ≥50），不足就 raise 而非只 print 警告。**驗證失敗一定要擋在寫檔之前**，否則髒資料已落盤。

4. **別吞錯，別讓 except 變成資料黑洞。**
   `except Exception: continue` 會把 SSL 憑證錯、DNS 失敗、逾時、PDF 損毀全部變成「安靜跳過」。做法：分類捕捉（可重試的 timeout vs 不可重試的 `SSLCertVerificationError`）；累計失敗頁／年，超過閾值就 `sys.exit(1)`；用 `logging.exception()` 留完整 traceback，連年份／科目／file_id／HTTP status 一起記。

5. **憑證問題用系統 curl 思維，別關掉驗證——但要分清楚兩個信任庫。**
   macOS 常因系統 CA 缺失或程式端 CA bundle 過舊，導致 `urllib`／`requests` SSL 失敗。正解是明確指定 CA bundle（`ssl.create_default_context()`、或統一改用 `requests`／`certifi`），而不是 `check_hostname=False` 把驗證關掉。
   診斷時要先認清：macOS `/usr/bin/curl` 走 **SecureTransport（系統 Keychain）**，而 Python `requests` 走 **certifi 自帶的 `cacert.pem`**——這是兩個獨立的信任庫。所以：
   - `curl -I <url>` 通、程式不通：**多半**是程式端 CA 設定／certifi 過舊，但也可能是該站的 root 只在 Keychain 受信任、certifi 沒收錄（常見於企業或本機自簽 CA）。先 `pip install -U certifi` 或把該 root 餵給 `verify=` 再判斷。
   - `curl` 也不通：問題在站臺憑證本身，不是你的程式。

   **第三種模式：憑證欄位不合規（換 CA bundle 沒用），且它常跟另一個故障疊在一起。**
   2026-08-01 抓全國法規資料庫（`law.moj.gov.tw`）實測：Python 對 45 部法全滅，錯誤是
   `CERTIFICATE_VERIFY_FAILED: Missing Subject Key Identifier`——該站憑證缺 SKI 欄位，
   OpenSSL 3 嚴格拒收，macOS Keychain 卻接受。這不是 CA bundle 過舊，換 certifi 無效。
   同時 `curl` 也逾時，照上一條會判成「站臺憑證問題」而放棄——但真正的原因是**該站
   AAAA 位址無回應**，curl 預設偏好 IPv6 就卡在那裡；`curl -4` 一下就 200。
   兩點通則：
   - **憑證錯 ≠ 連不上**。`CERTIFICATE_VERIFY_FAILED` 代表 TLS 握手已經走到驗證階段，
     也就是**連得到**；真正的連線故障是 timeout／DNS 失敗。把兩者混為一談就會誤判
     「站掛了／資料不存在」——這與 §「缺檔先疑命名變體」是同一種錯：拿環境問題當資料結論。
   - **繞道要挑最小的那個**。這裡的解法是傳輸層換成 `curl -4` ＋瀏覽器 UA、Python 端保留
     為後備，**不加 `-k`**——系統信任鏈本來就接受該憑證，驗證維持開啟。`-k` 是把整條
     信任鏈關掉來換一個欄位的相容性，代價與收益完全不成比例。
   - 把繞道的理由寫成註解＋自我測試釘住（「走 IPv4」「不關驗證」「有逾時上限」三條
     assert），否則下一個人會以為 `-4` 是隨手加的而拿掉。參考實作見
     [`../scripts/anchor_pack.py`](../scripts/anchor_pack.py) 的 `curlArgv`／`fetchHtml`。

6. **寫檔要原子化，並先備份。**
   `open(path, 'w')` / `write_text()` 是「先清空再寫」，寫到一半被 kill（磁碟滿、Ctrl-C、重啟）就留下半截或 0-byte 的損毀檔。做法：
   - 先寫同目錄下的暫存檔（`path.with_suffix('.tmp')`），驗證通過後 `os.replace(tmp, path)`。`os.replace` 只在**同一檔案系統內**才原子；tmp 與目標跨掛載點（如 tmp 在 `/tmp`、目標在 `/Users`）會丟 `OSError: EXDEV`，所以暫存檔務必放在目標的同一目錄。
   - 覆蓋前 `shutil.copy2` 留帶時間戳的 `.bak`。
   - 唯一性／schema 等 `assert` 要排在 `write_text` **之前**：先在記憶體或暫存檔上驗，通過才落盤。本專案 `merge_cap_to_bank.py` 的唯一性 `assert` 排在 `write_text` 之後六行——等於損毀資料已落盤才檢查。正確順序是「組好 dict → 驗唯一性／qid → 寫 tmp → os.replace」。

## 二、教學案例：ceec 113 數A「數a 少一個『學』字」

這是真實踩過的雷，把上面原則具象化。

`scrape_ceec_math.py` 的科目對照表是：

```python
SUBJ = [("數學a", "數學A"), ("數學ａ", "數學A"), ("數學b", "數學B"), ("數學ｂ", "數學B"), ("自然", "自然")]
```

每個 key 都帶「學」字。年份正則是 `r"(11[1-5])學測"`，要求「學測」緊跟年份。問題：大考中心 113 年那批 PDF 的檔名／連結文字，數A 出現了**省略「學」字的「數a」**寫法。於是：

- `classify()` 跑 `next((s for key, s in SUBJ if key in low), None)`——`數學a`、`數學ａ` 都比不到只有「數a」的字串，回 `None`。
- 該年數A 的「試卷」連結整筆被丟掉，但程式照常 exit 0。
- 產出的 `ceec_dl_urls.json` 裡，**113 數學A 只剩「答案」、沒有「試卷」**（可實際打開該檔驗證）。下游解析拿不到題目卷，整科整年靜默缺題，CI 完全無感。

連鎖放大：下游 parse 腳本用 `*_數學A_試題.pdf` exact-match，就算手動補了檔名只要差一個字也照樣 miss；`scrape` 的零筆結果還會寫出空 JSON 覆蓋掉上次成功的表。一個少打的「學」字，串起「exact-match + 不正規化 + 吞錯 + 零筆覆蓋」四個破口。

**正確修法**（多個原則一次到位）。注意修法本身也容易在三個地方重蹈覆轍：**年份不要強求「學測」字面**、**年份正則要有邊界**、**多重命中要當異常**：

```python
import re
import sys
import logging
import unicodedata

YEARS = {"111", "112", "113", "114", "115"}   # 別忘了定義，否則 NameError

def norm(s: str) -> str:
    # NFKC 折全形英數/括號/空白；NFKC 不轉小寫，需另接 .lower()
    return unicodedata.normalize("NFKC", s).lower()

# 別名集合涵蓋省字與全形變體
SUBJ_ALIASES = {
    "數學A": ("數學a", "數學ａ", "數a", "數ａ"),
    "數學B": ("數學b", "數學ｂ", "數b", "數ｂ"),
    "自然":  ("自然", "自然科"),
}

def extract_year(*sources: str):
    # 年份從檔名/連結文字/URL path 任一抽到即可，不強求都帶「學測」。
    # \b 邊界避免 2113→113、1130→130 這類過度匹配。
    for src in sources:
        m = re.search(r"\b(1[0-9]{2})\b", norm(src))
        if m and m.group(1) in YEARS:
            return m.group(1)
    return None

def classify(fn: str, url: str = ""):
    year = extract_year(fn, url)
    if not year:
        return None
    t = norm(fn)
    hits = [std for std, al in SUBJ_ALIASES.items() if any(a in t for a in al)]
    if not hits:
        logging.warning("科目比對失敗，可能是新命名變體: %s", fn)   # 留下可追的訊號
        return None
    if len(hits) > 1:
        # 同時命中多科 = 合卷或檔名拼接，別偷偷取第一個
        logging.error("單一檔名命中多科 %s，疑似合卷/拼接，需人工確認: %s", hits, fn)
        raise ValueError(f"ambiguous subject for {fn!r}: {hits}")
    return (year, hits[0])

# 寫檔前的 guard：零筆一定要擋
if not found:
    logging.error("0 筆符合條件，終止寫入以免覆蓋上次成功結果")
    sys.exit(1)
```

## 三、官方 PDF 文字層本身會壞：ToUnicode 塌縮

前兩節談的是命名／編碼／版面漂移，這節談一種更底層的髒：**PDF 字型的字元對映表本身就是壞的**，任何文字抽取器都會忠實複製那份壞掉的對映。

**症狀**：某些年度的官方試題用「圈號組合」題型（題幹列 ①②③④(⑤⑥…) 敘述，選項是「僅①②」「①③」這類圈號組合）。這類卷抽出來的選項會出現「圈號組合本身重複」——同一選項內同一圈號出現 ≥2 次（①①、僅①①①）、或多個選項去除「僅／空白」後正規化字串相同（①② 與 ①② 撞號）、甚至整題選項看起來一模一樣。另有一支伴生病症：選項開頭殘留「選項標記造字」（PUA 私用區碼），網頁字型下顯示為 tofu／破折號。

**三條文字管線同時中招＝交叉比對失效**：這不是單一抽取器的 bug，是 PDF 內部的字型 ToUnicode 對映表本身壞掉（經實測：③→①、④→② 這類多對一塌縮，且各卷字型互異、塌縮法各不相同）。自製 parser、第三方 API（如 Twinkle）、`pdftotext` 三條獨立管線讀的是同一份壞掉的字型對映，**輸出會是同一種毀損**——「多來源互相校對得出一致結果」在這裡不代表資料是對的，可能是三個人都在抄同一份壞筆記。這一支陷阱因此擋不住依賴「多源交叉比對」的一般查核邏輯，必須另立偵測。

**唯一解＝渲染成圖、用 vision 讀**：映射錯誤發生在 PDF 內部字型表，任何文字抽取都繞不過去；只有把該頁 render 成圖片，用視覺模型逐個圈號重新辨認，才能繞開壞掉的 ToUnicode。

**偵測判準**（先偵測、才決定要不要送 vision 復原；判準寫成零 token 腳本掃全庫，不動用任何模型）：

- `within_dup`：某組合選項內同一圈號出現 ≥2 次。
- `cross_iden`：≥2 個組合選項去除「僅／空白」後正規化字串相同（**有序**比較）。
- `marker_residual`：某選項開頭字元落在「選項標記造字」的 PUA 區段。
- **排序題必須豁免**：選項是同一組圈號的不同排列（如 `①②③④⑤` 與 `①②③⑤④`），本質是排序題、不是毀損。判準：≥2 個含圈號選項、各選項內部無重複圈號、所有選項的圈號多重集合相同、且至少出現 2 種不同排列，才判為排序題；此時只查 `marker_residual`，不觸發 `within_dup`／`cross_iden`——否則正常的排序題會被誤判成塌損。

**復原硬門**（vision 給出候選映射後，promote 前必過，過不了寧可留 review、不猜）：

1. **復原後必須恰為 4 個互異選項**——候選仍有重複或不足 4 個，直接判 fail。
2. **同卷映射一致性交叉驗證**：同一份試卷若有多題出現同一種毀損，該卷的映射函式必須**單一、一致**——用映射反查其他題，能逐字重現該題的壞值才算通過。同卷內若出現「切分點不一樣」「合併邊界不一樣」這類無法統一成一個函式的情形，代表這是逐題各異的擷取瑕疵而非可驗證的映射，**整卷都不 promote**，即使某幾題看起來復原得通。單題卷（同卷只出現一次此病症）沒有其他題可互證，改驗**內部自洽**——同一題內各圈號要解出彼此不衝突、不重複的值。
3. **官方答案語意檢查**：復原後的選項內容要能合理支持官方標準答案（例如季節性症狀對應春秋、疥瘡好發於群聚機構等常識／學理檢查），語意不通也不 promote。
4. **過不了寧可留 review 不猜**：任一道硬門不過，一律保留 `parse=review`，附上真值供人工參考，絕不把猜測值當 `parse=ok` 送出去——寧可少一題能練，不要一題假資料混進正式題庫。

## 四、修題必檢詳解（衍生物一致性）

第三節談的是「題目本身怎麼壞」；這節談另一種容易被忽略的連鎖：**題目修好了，衍生物（詳解）沒有跟著修，資料庫呈現的是「新題文 + 舊詳解」的縫合怪。**

**規則**：題目文本（題幹／選項／答案任一欄）被修正時——不論修正原因是毀損復原、錯字訂正、還是選項重排——都必須立即檢查該 `qid` 是否已有詳解：

1. **有詳解 → 該則詳解一律送檢。** 它是對「舊題文」寫的，題文一變，詳解裡的選項指稱、引用的選項文字、圈號組合都可能已經對不上。最低檢查＝**答案錨重跑**（詳解結論是否仍支持官方答案）＋**詳解內文與新題文逐項對照**（詳解裡提到的每個選項字母／選項文字／圈號組合，是否仍存在於新題文）；任何一項不符，**整則重寫**（走正常生成＋紅隊鏈），不做局部縫補——縫補容易漏改到深埋在句子中間的舊選項文字。
2. **無詳解 → 記入待寫清單。** 該科詳解線排程時涵蓋即可，不需要立刻補。
3. **修復報告（fixlist／recovery report 類產物）必須帶「詳解影響」欄位。** 每筆修復題標記 `had_explanation: true/false` 與處置（送檢重寫／記入待寫清單／無影響）。沒有這個欄位，題目修復完成後不會有人回頭檢查詳解，這條連鎖就會被漏掉。

**案例**：本站曾發生 5 題「僅①①」毀損期所寫的詳解掛在線上——那是圈號塌縮尚未偵測出來時，AI 依照當時（壞的）選項文字生成的詳解。後來題目照第三節的偵測與復原硬門修好了，但因為沒有「修題必檢詳解」這道程序，那 5 則詳解本來會繼續引用不存在的壞選項（例如詳解裡寫「選項 A 僅①①，故…」，但修好後選項 A 已經是正常的圈號組合）——**題目救回來了，詳解卻變成指著空氣說話**。教訓：任何觸及 `bank.json` 題幹／選項／答案欄的修正，都要把「這則詳解是不是也要跟著查」列進收尾清單，而不是修完題目就算結束。

## 全形／半形正規化：NFKC 用來**產生候選集**，不能直接拿來當輸出（2026-08-02）

上面第 1 條講 NFKC 是為了**比對**。要拿它做**輸出**（把詳解正文的全形運算子改成半形）
就會壞——但它仍然是這件事最可靠的第一步，因為：

> **「這個字是不是 ASCII 的全形形式」不要自己列表，問 NFKC：
> `unicodedata.normalize('NFKC', ch) != ch`。**

這一問就把最容易搞錯的一類擋在門外：

```
＋＜＞＆｜．％／：－＝～ → NFKC 會變   ＝ 全形形式，可以考慮轉半形
× ÷ − √ ≈ ≤ ≥ °        → NFKC 不變   ＝ 它們就是正確的數學符號
```

`×`(U+00D7)、`÷`(U+00F7)、`−`(U+2212) 看起來「比較寬」很像全形，**但它們不是**——
換成 `*` `/` `-` 是把正確的排版改成程式碼寫法，越改越錯。憑肉眼分不出來，問 NFKC 就分得出來。

**但 NFKC 的變更集比你想轉的多**，直接套會打壞中文行文。要從候選集裡扣掉三類：

| 扣掉 | 為什麼 |
| --- | --- |
| `：；，（）` 等句讀與括號 | 中文行文本來就該全形；`：` 還是選項段首（`A：`），轉了整批段落結構壞掉 |
| `～` 區間號 | `13:00～16:30` 是中文慣例。本專案實測 596 例全形對 18 例半形——**照少數改多數是逆著慣例走** |
| `［］（）` 等**成對**符號 | 夾心判準（左右都是拉丁／數字）對成對符號不成立：只有一邊命中就會生出 `[（…）]` 這種半邊全形的括號對，比不轉更糟。要處理得改用**配對掃描** |

剩下的才是可轉的，而且還要加**上下文條件**（本專案用「左右都是拉丁或數字」），
否則 `重量＋體積` 這種中文語境也會被轉。

#### 兩個附帶教訓

1. **只轉一半比全不轉更醜。** 本專案原表只有 `／：－＝`，於是 `34.3＋5＝39.3`
   變成 `34.3＋5=39.3`——**同一個算式裡兩種寬度並存**。要嘛整個算式的運算子都收，要嘛都別動。
2. 🔴 **驗收器不可以自己抄一份對照表。** 補收運算子那次，驗收判準
   （「抹平允許變更的字元後必須逐字相同」）自己抄了舊的四字元表，於是把合法改動
   誤判成「動到內容」當場中止。**驗收器要 import 對照表本尊**——抄一份就會分岔，
   而分岔的方向若相反（驗收器先放寬），就從誤擋變成放行漏洞。

#### 成對符號：夾心判準不成立，要改判「整段是不是算式」

上表把 `［］（）` 列為「另案」。做完之後的完整判準是：**抓出算式跨度，整段的全形括號
一起轉**，並用**五道否決**擋偽陽性。每一道都是被實測的偽陽性打出來的，不是想像的：

| # | 否決 | 打出這條的偽陽性 |
| --- | --- | --- |
| ① | 跨度內有 ≥3 連續英文字母 | `（non-coding RNA）`、`（β-lactam antibiotics）`——英文原名夾註 |
| ② | 跨度內括號不配平 | `p=0.043（顯著）` 會被轉成 `p=0.043(顯著）`，**正是要防的半邊括號對** |
| ③ | 運算子只出現在括號**內** | `（Na+）`、`（H+）` 化學式；`（IQ=MA/CA×100）`；`圖 6（1985-2000）` 年份區間。<br>要轉，括號得是**更大算式的一部分**——剝掉所有成對括號後仍看得到運算子 |
| ④ | 跨度開頭是 `（A）` | 那是**選項標號**不是算式括號 |
| ⑤ | **文件級**：轉完新增了寬窄並存 → **整則放棄** | 見下 |

**⑤ 是最重要也最容易漏的一道。** 同一個記號常同時活在兩種語境裡：

```
q（x）＝x³＋7x²＋x+3          ← 在算式裡，會轉
且 r（x）次數嚴格小於 2        ← 在中文行文裡，跨度被中文切斷，不轉
```

轉完就得到 `q(x)` 與 `r（x）` 並存——**把原本要修的病換個位置再犯一次**。
逐段（逐 span）判斷**結構上看不到這件事**，只能在整則文字上檢查
「轉完之後，有沒有同一組括號內容出現兩種寬度」，有就整則放棄。
本專案這道讓 139 → 120 則，**少做 19 則換零並存**——這個交換划算。

#### 修復門彼此會互相影響，門序由冪等測試決定

新增這道門之後，有一則資料**跑第二輪還會變**。原因是既有的標點門其等號規則
右側吃**半形** `(`，所以新門把 `（100x-158）` 轉成半形之後，標點門才咬得到 `42＝(`。
把新門排到標點門**前面**就一輪收斂。

> **不冪等不是美觀問題**：併庫流程會重跑，不冪等會累積。
> 每加一道門就跑一次「全庫套兩次，結果必須相同」——**門序的正確性只有這個測試看得出來**，
> 靠讀程式碼推不出來。

## 三個讓修復工具靜靜失效的寫法（2026-08-06 一輪內各踩一次）

都不會拋錯、不會少檔案，只會讓工具**做的事跟你以為的不一樣**。

1. **備份在變更之後才取**：`items` 在迴圈裡改完，才 `json.dumps(items)` 寫 `.bak`
   ——備份與新檔逐字相同，等於沒有備份。改壞之後無從還原，只能回上游重建。
   → 先讀 `raw` 再改，並斷言 **`備份 != 新檔`**（相同就是取錯時機）。

2. **旗標的值也在 argv 裡**：`--size 15` 只濾掉 `--` 開頭 → `15` 留在檔案清單裡被
   當成生成檔；`--cmd "--selftest"` 的值本身叫 `--selftest` → 掃 argv 找旗標名會
   誤中、跑成自己的 selftest。**症狀都是「看起來通過了」。**
   → 帶值的旗標要**連值一起 `del`**，再判其他旗標。

3. **用黑名單排除已知前綴**：`part not in ("rel", "out", "aprime")` 是一份
   「我當時想得到的前綴」清單，換一批檔名（`gap_…`）就靜靜地回傳錯的科目，
   一路跑到 `_dev/data/gap/bank.json` 才炸。
   → 改成**對照實際存在的目錄（白名單）**，並要求命中恰好一個，否則當場停手。
   **黑名單會隨新用法悄悄失效，白名單不會。**

4. **固定後綴的備份會互蓋**（2026-08-09 實測）：`shutil.copy(path, path + ".bak_optbleed")`
   在同一支工具**跑第二輪**時，把第一輪那份備份覆寫掉了。
   備份的用途是「上一個好狀態」，而固定後綴保證的是「**最近一次**的上一個狀態」——
   跑第二輪時，那正好是你要回去的那一個。
   `shutil.copy` 覆寫既有檔且**不出聲**，所以症狀是零。
   → 備份檔名**帶時間戳**，且**同名已存在即中止、不覆寫**：

   ```python
   dst = p.with_name(f"{p.name}.bak_{tag}_{time.strftime('%Y%m%d%H%M%S')}")
   if dst.exists():
       raise SystemExit(f"備份已存在，拒絕覆寫：{dst}")
   ```

   一般化：**任何「寫到一個推導出來的路徑」的動作，都要問「這個路徑上次也是這個值嗎」。**
   會的話，那不是備份，是一個會被自己覆蓋的暫存檔。

## 修復器的涵蓋範圍：列舉欄位＝漏掉沒想到的欄位（2026-08-02）

一支造字修復腳本跑完宣告「全庫歸零」，實際還剩 **1,210 處**——因為它寫成
「只改 `stem` 與 `options`」。漏掉的是 `table.headers`／`table.rows`，
以及**整個 `essays.json` 從沒被掃過**。

> **修復器要遞迴走訪所有字串值，不要列舉欄位。**
> 列舉是為了「保守、別亂改」，但它保護的是**你想得到的欄位**，
> 代價是**你想不到的欄位完全不設防**——而漏掉的永遠是後者。

保守性改用**後置斷言**取得：走訪全部，但對結構欄位（`qid`／`answer`／`parse`）
斷言「改到就是有 bug」。這比事前列舉強，因為它連「我以為不會被改的欄位真的沒被改」
都證明了，而列舉法只是沒去看。

同一件事的另一面：**「合計 N 處」這種收工數字，必須配一個獨立的全庫重掃**。
腳本自己報的 N 是「它掃到的範圍內有幾處」，不是「全庫還剩幾處」。

#### 🔴 嚴重度只有在呈現層才看得出來

我原本把上面那 1,210 處當「資料整潔問題」。使用者要求**驗上線版**之後：
gsat 某題組的表格表頭在站上顯示成 **「丙（　）丁（　）」**——μ 與 ε 是空白，
**考生根本不知道丙、丁是什麼符號，四道題無法作答**。

> **資料層量到的「幾處異常字元」不等於使用者受到的傷害。**
> 同樣是 26 處：落在詳解內文裡是瑕疵，落在題幹表頭裡是**廢題**。
> 排優先序之前，先去看它在使用者眼前長什麼樣——一次 `fetch` 就知道。

#### 寫回的排版要跟著原檔，不是跟著習慣

同一輪還踩到：把修復擴大到 `essays.json` 時沿用了專案的「單行 JSON」寫法，
於是兩個檔案從 **7,754／13,607 行被壓成單行**。那條不變式只適用另外兩種檔案。

一行防禦：**寫回前先看原檔有沒有換行**，有就照它的縮排與結尾換行寫回。
把「本專案的慣例」套到一個沒宣告過該慣例的檔案上，會製造一個沒人要的巨大 diff，
而且它會蓋掉真正的改動、讓 review 失效。

## 🔴 閘門陣列的兩個系統性盲區：入場篩選器與共用正規化（2026-08-07）

修復工具通常寫成「一排閘門，全過才動手」。這種結構有兩個洞**不是任何單一閘門的責任**，
所以加閘門解決不了——同一輪各踩一次。

#### 一、入場篩選器會遮住閘門的漏洞（篩選器是消音器）

`fix_imgmark_opts` 一開始有一道入場條件（只看某個形狀的候選），我把它當成「便宜的最佳化」
拿掉，想看看閘門擋不擋得住。結果候選從個位數變 **39 筆，其中 35 筆是假陽性**：
純空白差異、選項 D 尾巴多一個 `#` 卻被當成合法前綴……

> **舊的入場券一直順手擋著這些假陽性，於是我以為閘門比實際上強。**
> 篩選器縮小的是**進入閘門的分布**，不是缺陷本身；閘門的真實強度，
> 只有在**沒有篩選器**的全量候選上才量得到。

處置：先在**無篩選器**的全量候選上把閘門調到零假陽性（本案補的是
「切法產生的格數 == 現有格數 ⇒ 沒有東西要修」這道），確認之後才可以為了速度加回篩選器
——而且加回來時要記錄它擋掉幾筆，否則下次又量不到。

#### 二、所有閘門共用同一個正規化 ⇒ 那個正規化丟掉的東西是**全體**的盲區

同一支工具的所有比對都走 `norm()`，而 `norm()` 去掉全部空白（為了容忍 PDF 的字距）。
於是我在切分函式裡用 `"".join(...)` 拼段內文字（而不是依 span 間距補空白的 `row_text()`），
寫出來的是 `Asmalin1（2.5mg）`——**每一道閘門都看不見這個錯**，因為每一道都先把空白丟掉。

> 一個共用的正規化函式，等於在所有閘門上開同一個形狀的洞。
> **它丟掉的每一個維度，都是整排閘門的共同盲區。**

兩條處置：

1. **這類缺陷只能靠「用對的建構方式」避免，不能靠加閘門**——因為新加的閘門也會用同一把尺。
   把正確的建構函式（此處是 `row_text()`）寫成唯一入口，並在原地留一行註解說明為何不可用 `join`。
2. **留一條 canary**：selftest 裡放一則**只差在空白**的案例，斷言輸出等於帶空白的版本。
   它是那排閘門裡唯一不走 `norm()` 的檢查。

## 六、官方 PDF 的文字層自己就缺一個數值——所有「跟原卷比對」的檢查都看不到（2026-08-09）

pharmacist `112_112100_P3_65` 是這樣入庫的：

```
題庫： 某藥物以靜脈注射投與800 mg後，得 mg．h/L，腎排除速率常數為0.12 h-1。…則此藥之絕對可用率約為若干？
原卷： 某藥物以靜脈注射投與800 mg後，得        mg．h/L，腎排除速率常數為0.12 h-1。…
```

那個 AUC 值在**官方 PDF 的文字層裡就是一串空白**（版面上有數字，但它是圖或是抽不出的字），
解析器忠實照抄，於是題庫裡也沒有。**這題無法作答**，而它通過了每一道門：

| 檢查 | 結果 | 為什麼看不到 |
| --- | --- | --- |
| 必跑門 A（答案配對） | ✅ 通過 | 答案鍵是對的，缺的是題幹裡的數值 |
| 必跑門 A2（題數缺號） | ✅ 通過 | 題號完整 |
| 恰 4 選項 | ✅ 通過 | 四個選項齊全 |
| 題幹以問號結尾 | ✅ 通過 | 結尾是「約為若干？」 |
| **與原卷逐字比對** | ✅ 通過 | **原卷也一樣缺**，兩邊完全一致 |

**「跟來源比對」這個方法的天花板，就是來源本身的品質。** 來源缺的東西，
比對永遠是一致的——一致不代表對，只代表兩邊一樣。

### 偵測：找語意殘骸，不要找排版殘骸

第一版偵測器去找「連續多個空白」，**掃出 0 筆**。因為解析器會正規化空白，
`得        mg．h/L` 到題庫時已經變成 `得 mg．h/L`——**排版線索在中間那一步被抹掉了**。

活下來的線索是語意的：**一個沒有數值的單位**。

```python
# 「得」後面一定要接一個量。「t 之單位為 h」「（C 為 µg/mL）」是合法宣告，不是缺值——
# 判準必須把宣告排除，否則假陽性會淹掉真陽性（實測寬版 4 筆裡 3 筆是宣告）。
ORPHAN = re.compile(r"得\s*(?:mg|µg|μg|ug|kg|mL|L|h|hr|min)[．.／/·]")
```

pharmacist 13,050 題掃出 **1 筆**，而那 1 筆當時已經是 `parse:"ok"`、在練習池裡。

**推廣**：只要你的管線中間有任何一個正規化步驟（空白、全半形、Unicode），
**上游的排版線索就不能當偵測依據**。要找的是那個缺陷在正規化之後**還剩下什麼**——
通常是語意上的不完整，不是字元上的異常。

處置：降 `parse:"review"`，理由記 `value_missing_in_pdf_textlayer`，
要救得走 vision（render 該區塊讀數字），不能靠文字層再試一次。

## 七、同一種污染，換一個欄位就活下來（2026-08-09，分科測驗）

清理站清過 **stem** 的版面家具污染（頁眉頁尾、下一題組的引文、章節標題），83 題全清乾淨、
報告漂亮。同一批資料的 **options** 從頭到尾**沒有人看過**——結果 186 題的**末選項**
把下一題整段吞了進去，103 題是 `parse:ok`：

```
選項D： 由不同立場的民眾開會並諮詢專家，形成共識結論後交由政府作為修法重要參考
        \n\n21-23為題組\n\n◎ 某高中提供公民與社會科線上學習教材，引導學生分組…
```

末選項是**每一題的邊界**，抽取器只要少判一次邊界，下一題就會流進來。所以
「污染只發生在 stem」從來不是資料的性質，只是**我們只掃過 stem**。

> **一種污染修好之後，要問的不是「還有沒有」，而是「它還可能停在哪個欄位」。**
> 清理報告只證明它在被掃過的欄位裡不見了。

**發現它的不是我的閘，是生成模型的 `data_defect` 出口**：ast 生成站前 100 則裡 21 則
回報缺陷，逐條寫「D選項後誤接下一題題組文字」。**留一個讓下游講「這筆資料壞了」的出口，
它會回報你沒想到要問的東西**——前提是那個出口不能寫進正文（見 explanations-redteam
的 `data_defect` 欄位設計）。

### 切法：只認明確的家具標記，不可切在第一個換行

直覺解法是「末選項切在第一個 `\n`」。**實測會砍掉正文**：合法選項本來就有換行——
`…有效保障原住民種族平等與身分\n\n 認同` 是同一個選項被折行，圖表型選項整段都是換行。
量過的分布：非末選項 2,478 個無換行、137 個有換行。

所以只認**除了版面家具以外不會出現**的字串：`21-23為題組`、`第貳部分`、`111年分科 第 8 頁`、
`共 11 頁`、`◎`、`說明：本`。認不出來就不要動。

#### 🔴 但這份清單是「我翻到過的版型」，它結構上無法回報自己漏了什麼

同一天稍晚，上面那支清理器**自報 186 題已清乾淨**，而下一站的紅隊用 token 找出
**還有 42 題沒清**（其中 19 題是 `parse:ok`，詳解已經照著被污染的選項寫完了）。
漏掉的四個抬頭是同一份考卷的閱讀題版型：
`閱讀二`、`二、閱讀題(占18分)`、`說明:第20題至第28題`、`第一部分`（國字版，
原清單只有國字大寫的 `第壹部分`）。

**列舉式清單的失效方式跟白名單註冊表完全一樣**（→ `reviewer-input-parity.md` §2.1a）：
它只保護被想到的那些，而「沒想到」正是它要防的事的成因。差別只在於這次的代價
是**在下游用貴的方式付**——紅隊每一則 finding 都要燒 token，而清理器是零成本。

實務上的兩條：

1. **清理器要印「切了幾題／末選項仍超長的還有幾題」**，不要只印切了幾題。
   末選項長度的分布是免費的異常訊號：正常選項十幾到幾十字，被污染的動輒 200～600 字。
   `sum(1 for q in bank if any(len(o) > 200 for o in q["options"]))` 一行，
   它不需要你先知道有哪些抬頭。
2. **紅隊抓到資料層缺陷時，要回頭問「哪一道零成本的閘應該先抓到它」**，
   然後把判準補進那道閘。否則下一科會再用 token 買同一個發現。

### 切完變成空的，是「缺失」不是「污染」

有 6 題切完整個選項變空字串——代表那個選項**整段都是家具，真正的選項文字根本沒被抽出來**。
清理救不了它，切下去只會留一個空選項，比原本那坨雜訊**更難發現**（空字串在前端就是一個
沒有內容的按鈕）。這一類要走降級。

順帶一提，這道守衛還撈出另外 6 題**本來就**有空選項的 `parse:ok`（數學甲／物理，
數學式被 PDF 文字層渲染成造字 ``）。**一道門既然已經知道「空選項＝不可作答」，
就不該只管自己弄出來的那幾個。**

### 🔴 正確性斷言要在寫檔之前

原本的順序是 `json.dump` → 讀回 → 斷言。有一次斷言失敗、終端印出 traceback，
看起來像整批拒絕——**實際上 180 題已經寫進檔案了**。

**讀回斷言只能證明「有沒有存進去」，證明不了「該不該存」，那是兩件事。**
順序固定為：先斷言結果本身合法（不含空值、筆數與欄位數不變）→ 備份 → 寫 → 讀回確認持久化。
