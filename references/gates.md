## §A 答案配對全驗（每題逐一，不抽樣）

> **這是不可略過的步驟，每次都要跑、而且是全跑。**

題庫成形後、進詳解前，**把每一題的 `answer` 逐題對官方標準答案核對**，列出所有對不上的題（mismatch），修到 **0 mismatch** 才往下走。**（只管選擇題；申論／計算題無官方標準答案，不適用此門，改靠紅隊的申論角度。）**

- **為什麼非跑不可**：答案來自官方標準答案 PDF 不代表「對到正確題號」。PDF 解析常見**整體錯位**（某題答案套到下一題），這種錯**結構檢查擋不到**（答案還是落在 A–D 範圍、看起來正常），只有逐題比對抓得出來。
- **全跑、不抽樣**：答案配對是「對或錯」的硬事實，抽樣只能給信心區間、給不出「哪幾題錯」。所以這道門**逐題全驗**，與詳解紅隊的「可抽查」不同。
- **方法**：獨立重新解析官方標準答案來源（PDF `find_tables` / 答案表），與 `bank.json` 的 `answer` 逐題 diff；用官方答案表當權威題號清單對齊。輸出只印**計數與 mismatch 清單**（qid、bank 答案、官方答案）。
- 國考護理師即用此門全驗 600 題、0 mismatch；舊建的考試若未跑過，補跑這道門。

## §A1 §A 的實作坑：靜默 no-op 的檔名推導會拿題目卷當答案卷（2026-08-07）

這道門要先找到「這卷的官方答案 PDF」，而那一步幾乎都寫成從試題檔名推導。
實測寫成一行 `pdf.name.replace("試題", "答案")`：clinical 的檔名是 `…_Q.pdf`，
根本不含「試題」二字 ⇒ **`replace` 回傳原字串、不報錯** ⇒ 拿**題目卷當答案卷**去解，
`find_tables()` 當然抽不到答案 ⇒ 報告寫著「**4,400 題解析失敗**」。

> 🔴 **靜默 no-op 的字串取代，會把「我沒做這件事」偽裝成「這件事做了但失敗」。**
> 前者要修的是我的程式，後者要查的是官方資料——**兩個結論會把人帶去完全不同的地方**，
> 而產物上它們長得一模一樣（都是一個很大的失敗數字）。

三條，寫這一步時逐條對照：

1. **檔名推導寫成規則表，並斷言它真的換掉了東西。**

   ```python
   ANSWER_NAME_RULES = [("試題", "答案"), ("_Q.pdf", "_A.pdf"), ("_Q.PDF", "_A.PDF")]

   def answer_pdf_of(pdf):
       for src, dst in ANSWER_NAME_RULES:
           if src not in pdf.name:            # ← 沒命中就換下一條，不要硬 replace
               continue
           cand = pdf.with_name(pdf.name.replace(src, dst))
           assert cand != pdf, f"規則 {src}→{dst} 沒把檔名換掉：{pdf.name}"
           if cand.exists():
               return cand
       return None                            # ← 「找不到」是自己的值，不是 0 筆
   ```

2. **「找不到答案卷」必須是獨立狀態，不可以流進 mismatch 計數。**
   這是 §A4「讀不出來要有自己的值」在**門的實作層**的同一條律：
   一旦「沒答案卷可比」與「比出來不一致」擠進同一個數字，你就永遠分不出該修誰。
3. **答案字母要 NFKC 正規化再比**（`Ａ`→`A`），但 **`#`（送分）與 `A/B`（多答）要原樣保留**
   ——它們是合法值，不是雜訊。

## §A2 每卷題數與缺號檢查（零成本，擋「整段遺失」）

> **答案配對全驗只驗「入庫的題」對不對，驗不到「該入庫卻沒入庫的題」。** 這道門補那個洞。

對每一卷比對三個數字：**官方宣告題數**（答案 PDF 的「題數：N 題」欄）、**解析出的最大題號**、
**實際入庫筆數**。三者不相等，或 `1..max` 中有缺號，即為缺陷，回源重解。

```python
for (round_, subject), nos in by_paper.items():
    gaps = [n for n in range(1, max(nos) + 1) if n not in nos]
    assert not gaps and len(nos) == official_count, (round_, subject, gaps, len(nos))
```

- **為什麼非跑不可**：解析器可能在中途靜默中斷，把剩餘文字**塞進最後一題的第 5 個選項**。
  該題會被降 `parse:'review'`（因為選項數不對），看起來只是「1 題待校」——
  完全不反映**同一卷還少了 32 題**。實測案例：醫師 110101 醫二只入庫 68 題、官方 100 題，
  第 68 題的選項 E 裝著第 69 題的選項與第 70 題的題幹；`1..68` 無缺號，所以只有
  「拿最大題號比對官方宣告題數」抓得到。
- **官方宣告題數在答案 PDF 裡**（`pdftotext -layout` 抓「題數」欄），不要用自己解析的數量當基準
  ——那正是要被檢查的對象。
- **全庫掃一次很便宜**：doctor 82 卷掃出 1 卷有問題，其餘 81 卷缺號為 0。
  舊建的考試都補跑這道門。

## §A3 圖題掛載雙向檢查（零成本）

裁圖後、進詳解前，對 `figure` 欄跑兩個方向的檢查：

| 方向 | 檢查 | 抓到的錯 |
| --- | --- | --- |
| 題→圖 | 題幹引用圖（`如圖`／`附圖`／`X 光如下`／`心電圖如`…）但無圖檔 | 缺圖；詳解會變成**包裝成推理的猜測**，而 lint、答案錨、文字紅隊全部放行 |
| 圖→題 | 有圖檔但題幹完全不提影像 | **圖掛錯題**（常見 off-by-one：圖被掛給前一題） |
| 圖檔去重 | 同一份 PNG（內容 hash 相同）掛給多題 | 非題組共用時即為錯掛，且**兩題中不引用圖的那題是錯的** |

實測（doctor）：抓出 **5 題圖掛錯**（皆為編號較小的純文字題拿到後一題的圖）、
**2 題該有圖卻掉引用**（且選項退化成 `['A','B','C','D']`／`['甲生',…]`，內容全在圖裡、
根本無法作答）。其中 2 題是**圖題生成模型自己回報**的——它看著圖寫詳解時會發現
「這張圖跟題幹無關」，那是純文字關卡都抓不到的訊號，記成 `data_defect` 交主控裁決。

> 「圖→題」方向的 regex 要**寬鬆**（把 `CXR`、`X 光`（含空格）、`鋇劑攝影`、`家族譜系`、
> `化學結構` 都算引用），否則**合法的圖片選項題**（選項本身是圖）會被大量誤報。
> 誤報清單一律人工看過再動手，不要自動移除。

### §A3.1 掃 stem 不夠：題組的圖掛在**共用 passage** 上（2026-08-09 實測）

裁圖站還沒開工的科目也驗得動的一半是「題幹講了圖，題庫卻沒有附件」。
第一版只掃 `stem`，在**藥師**跑起來完全正常（13,050 題抓出 239 題，數字乾淨），
換到**分科測驗**就靜默漏掉 **137 題**——因為題組的圖引用寫在共用的 `passage` 裡，
小題的 `stem` 一個字都沒提。

> **一個只在某些科目才有的欄位，會讓「只掃一個欄位」在那些科目上永遠是對的。**
> 這種漏抓沒有任何外顯症狀：閘門照跑、報告照印、抓到的數字看起來很合理，
> 而漏掉的那些題長得跟乾淨資料一模一樣。跨科目複用一道門時，
> 要先問「這一科有哪些欄位是我上一科沒有的」，而不是只看它有沒有跑完。

判準：引用掃描範圍＝`stem` ＋ `passage`（＋任何承載共用素材的欄位）。
附件判定則相反，要看**整個題組**：先確認同組其他小題有沒有掛圖，
有就是欄位沒傳下去（修欄位），沒有才是真的缺圖（降級）。
實測那 137 題所屬的題組**沒有任何一個小題掛著圖**，所以是真缺。

另外，強證據與弱證據要分開，只有**指示詞**（下圖／如表／圖如下）能單獨支撐降級；
「在層析圖中 A、B 兩波峰滯留時間分別為 17.1 與 16.2 分鐘」這種把「圖」用在名詞片語裡、
數值全在題幹的，降了就是白白關掉一題答得出來的題。

### §A3.2 🔴 工單旗標有兩個寫者，只有一個會清理（2026-08-17 實測，分科測驗）

閘門把缺圖的題標上 `review_reasons: orphan_figref`。裁圖站補完圖之後，**理由要拔掉**
——藥師版落盤器有做（`extract_pharmacist_figures.py`），操作卡也明令。分科測驗版
`extract_ast_figures.py` 只把 `parse` 升回 `ok`、**理由留著**，而且它自己的越界斷言
`changed <= {figure, table_md, parse}` 讓「拔理由」**在結構上不可能發生**。

結果是 **329 筆殭屍旗標**：題有圖、`parse:ok`、前端完全正常，身上卻掛著
「題幹引用圖表但無附件」。而詳解生成的 in 檔切割器拿這條理由當**排除依據**——
於是 115 題「題文已修、線上詳解已對不上」的重生批，只涵蓋到 50 題，
照那樣 merge 會有 **61 題的錯詳解繼續留在線上**。

**三條可直接照抄：**

1. **凡是「標記 → 處理 → 應該撤銷」的欄位，撤銷要跟標記寫在同一支、同一次提交裡。**
   分兩支寫，就會有一支先寫好、另一支永遠等不到——而缺的那半沒有錯誤訊息。
2. **越界斷言是白名單，白名單漏一個合法欄位，代價不是報錯，是那件事永遠做不成。**
   而且它會偽裝成「規定不准這樣做」：有人補上正確的清理程式碼，斷言會當場爆給他看。
   寫越界斷言時要問「這支**應該**改哪些欄位」，不是「它**現在**改哪些欄位」。
3. **自動撤銷的條件要用客觀事實，不要用「判定式不再命中」。**
   判定式不再命中有兩個成因：事情真的修好了（事實），或規則本身沒收錄這個寫法（判斷）。
   照後者撤，會把「人看出漏網而手動掛上的理由」當成自己的假陽性清掉，且清掉沒有痕跡。
   這裡的客觀事實是 `has_attachment(row)`——附件在不在，跟誰標的無關。

> 這是 §A3 反面推論三（工單要用目標狀態算，不要用狀態轉換算）的**鏡像**。
> 推論三講「別漏掉已經在目標狀態裡的」；這裡講「別留住已經離開壞狀態的」。
> 同一支腳本可以看見其中一半而看不見另一半——兩種漏法在報表上長得一樣：都像做完了。

## §A4 答案狀態必須在入庫時標注（零成本）

> **「我不知道答案」必須有自己的值。** 只要它跟任何一個合法值同形，解析失敗就
> 繼承了合法資料的全部偽裝，而且沒有任何下游分得出來。

考題的答案欄不是只有「字母」與「沒有」兩種狀態，至少有六種，而且**成因完全不同**：

| 狀態 | 意思 | 前端該怎麼判分 |
| --- | --- | --- |
| `official` | 官方答案鍵有明確字母 | 照字母判 |
| `multi` | 官方公告多答皆給分 | 命中 `accept` 任一即算對 |
| `free` | 官方公告一律給分（送分題） | 怎麼答都對 |
| `none_published` | 官方從未公布答案 | **不可作答**，只供閱讀 |
| `not_applicable` | 非選／申論題，本無選擇題答案 | 不進選擇題判分 |
| `unread` | 🔴 **我們沒取得或讀不出來** | **不可上線** |

**把前五種擠進 `answer` 一個欄位，最後兩對會互相偽裝**：`free` 撞 `unread`（都寫 `#`），
`none_published` 撞 `not_applicable`（都寫空字串）。

**實測代價（2026-08-06，nursing）**：官方答案 PDF 的字母寬度**逐卷不一**——同一次考試裡
基礎醫學／內外科用全形 Ａ-Ｅ（U+FF21-），基本護理學用半形。解析器只比對半形，全形卷每題
濾成空字串後落進 `v = "#"` 這個 fallback，於是**兩整卷 100 題被標成送分**，前端據此把
**任何**作答都判對——答錯的學生被告知答對，存活數月。

**為什麼四道門一道都沒攔到**：那 100 題「題幹完整、四選項齊、`parse:'ok'`」，
**逐題檢查永遠正常**。376 卷裡只有這 2 卷的 `#` 比例 >50%，其餘 ≤10%——
**這種缺陷只在「每卷 `#` 比例」這個聚合尺度上可見**，再仔細的逐題人工複核也是零召回。

所以這道門有兩半：

```python
# ① 狀態要標出來，且「不知道」有自己的值（入庫時寫，不是事後回推）
assert q["answer_status"] in
    ("official", "multi", "free", "none_published", "not_applicable", "unread")
# ② 聚合尺度的形狀檢查：主管機關不會在半卷以上送分
assert free_count <= 0.5 * paper_count, "疑似整卷答案表沒讀到，不要當送分題入庫"
```

- **另記 `answer_src`**（官方 PDF／索引 API／由既有欄位回推）。回推出來的 `free` 與
  **經 §A 逐題驗過的** `free` 在畫面上長得一樣，可信度差很多——**狀態與它的來源要一起記**。
  🔴 **而且要一起報**：門的產物列 `unverified_free`（＝`free` 且 `src:'derived'`）。
  只報狀態分佈的話，回推完那批看起來就「處理好了」，欠的那次逐題重驗從報告上消失。
  實測（2026-08-06）全站 457 則送分全數 `derived`，每卷比例最高 16.2%／245 卷
  ——**沒有整卷型偽裝了，但也沒有一則被證實過**，這兩件事要同時說得出口。

- 🔴 **修好病因不等於可以拆掉症狀偵測器。** 把 fallback 從 `#` 換成哨兵之後，
  「半卷以上是 `#`」那道聚合檢查會對它**當初唯一擋到的那一卷**視而不見——
  整卷讀不出來的新形態寫的是哨兵，不是 `#`。**換了失敗的長相就要同步換尺**：
  兩個值都要數。病因只解掉已知的那條路徑，症狀偵測器守的是還沒想到的那些。

- 🔴 **多字母的 `answer` 不等於「多答皆給分」。** `answer:"CDGI"` 有兩種相反的意思：
  **複選題**（四個字母全中才算對）與**官方公告多答皆給分**（中任一個就算對）。
  用「長度 > 1」去推語意，會讓前端只要選中 C 就判對。**語意必須由讀答案鍵的人傳進來**
  （多答走自己的 `accept` 欄位），不能從欄位形狀反推——這與整條 §A4 是同一條律的兩個
  例子：`#` 那次是「兩個意思擠進一個值」，這次是「從形狀猜是哪個意思」。
- **這個設計不必新發明**：教檢（teacher）早就用 `parse:'noanswer'` ＋ 一段說明理由的
  `parse_note` 標「官方只公布第壹部分」。它給了那個狀態自己的值，還附了理由。
  一般化它即可，並補上它沒遇到的 `unread`。
- **合法字母的上界是該題的選項數，不是寫死的 E。** 本規則的第一版把上界寫死成 A–E，
  把學測英文十選五（答案 `I`／`F`／`CDGI`）28 題誤報成 `unread`——**與上面那個事故是
  同一個錯的兩個方向**：都把「我以為資料長什麼樣」寫進判準，而不是去看該題實際幾個選項。

### 🔴 狀態標記會過期：`unread` 帶著一個已經救回來的答案（2026-08-10 實測）

`answer_status` 記的是**當時發生過什麼**（我們讀不出來），不是**現在是什麼**。
兩者在後續有人修好那個問題時就分家了，而**沒有任何東西會通知標記**。

實測：counseling 與 nursing 各 1 題標著 `unread`，欄位卻是 `answer:'D'`、4 選項、
`parse:'ok'`。回官方答案 PDF 逐字核對，兩題官方答案確實是 D——答案早就被重抽救回來，
只是狀態沒跟著升級。後果不是「少一題」，是這兩題**正躺在練習池裡被當成「正解是 D」
判學生對錯**，而那個 D 在資料上宣稱著「不可信」。

閘門形狀（零成本，兩條一起驗，缺一不可）：

1. **值域**：`answer_status` 的值必須恰好等於已知集合，多一個就擋。少了這條，
   一個拼錯的值（`offical`、`none-published`）會讓整批題目安靜地掉進唯讀，
   畫面上沒有任何錯誤訊息。
2. **形狀不變式**：唯讀狀態（`not_applicable`／`none_published`／`unread`）
   **不得帶著看起來合法的答案**。這條才是抓到上面那兩題的那條——值域是乾淨的，
   壞的是「狀態說不知道、欄位卻填了」這個組合。

參考實作：`_build_features/check_answer_status_domain.py`（含 `--selftest`，
known-good 不誤報／拼錯的值抓到／唯讀帶答案抓到三側都驗）。

一般化：**任何記錄「當時失敗過」的欄位，都要有一道驗它是否仍然成立的閘。**
`parse:'review'`、`needs_figure`、`ref_status` 全是同一類；它們共同的失效方式是
「問題修好了，標記沒修」，而標記活得比問題久。

### 🔴 判準要認事實，不要認事實的長相（**已重犯三次，寫閘門時逐條對照**）

同一個錯已經以三種面貌出現過。它們共同的形狀是：**判準寫的是「我印象中這件事
長什麼樣」，而不是「這件事本身」**，於是資料換一種合法長相就被誤判。

| # | 判準寫成 | 該寫的事實 | 代價 |
| --- | --- | --- | --- |
| 1 | 讀不出來就填 `#` | 「讀不出來」自己的值 | 2 卷 100 題被判成怎麼答都對 |
| 2 | 合法字母是 A–E | 上界＝**該題的選項數** | 十選五 28 題被誤報成缺口 |
| 3 | 多字母 ⇒ 多答皆給分 | 語意由**讀答案鍵的人**傳進來 | 複選題只中一個就判對 |
| 4 | 有樣卷 ⇒ `ref` 欄非空 | 「有沒有樣卷」，不管存在哪個欄位名 | 升學 15 則有樣卷的被報成缺口 |

**寫任何分類判準前，先問一句：我寫的是這件事，還是這件事在我看過的那批資料裡的長相？**
兩個方向都要有 canary（誤報成缺口、與誤報成合法各一則），只測一個方向的尺是壞的。

> **這條規則的通用形**：任何解析器的「讀不出來」預設值，都不可以等於某個合法值。
> 一旦相等，**失敗與成功在產物上不可區分**，而所有下游都會把它當成成功。
> 這與本檔末「產物形狀要求」是同一條律的兩個尺度——那條講「沒跑」要看得見，
> 這條講「跑了但沒讀到」要看得見。

## 🔴 產物存續：閘門的證據躺在哪，決定它是不是真的存在（2026-08-07）

「缺產物＝未跑」這條律有個沒寫出來的前提：**產物要活得比它證明的那件事久**。
實測一天之內，同一個判準的三個方向各踩一次：

| 踩法 | 實況 |
| --- | --- |
| 以為「有備份」就安全 | 備份寫進了 `_bak_archive/`，而那個目錄被 gitignore。備份不進版控＝只活在一台機器上 |
| 以為「留在工作樹」才安全 | 58 支腳本 58/58 都在 git 追蹤中，刪掉一個 byte 都沒少。留著只多一份可被複製的舊模板 |
| **以為閘門在跑，證據就存在** | 臂等價帳本 `_arm_parity.json` **一直被 .gitignore 的白名單擋在外面**。閘門天天在跑、發表的數字全靠它舉證，而它只活在一台機器上，而且沒有人發現 |

第三個最貴，因為它**沒有任何症狀**：閘門正常運作、數字正常產出、檔案正常存在，
只有在換一台機器或磁碟壞掉的那一刻才會發現證據從來沒有離開過本機。

### 兩件事要分開，不能互相替代

1. **耐久度**＝它躺在哪（有沒有進版控／有沒有離開這台機器）。
2. **可達性**＝有沒有人寫下路徑（翻案者知不知道去哪找）。

**保留檔案只買到耐久度的錯覺，買不到可達性。** 一份躺在資料夾裡、沒有任何文件
指向它的證據，跟不存在的差別只在於「有人碰巧翻到」。反過來，刪掉檔案而留下
「commit sha ＋路徑＋取回指令」，兩者都有。

### 三條閘門形狀

- **凡是閘門會讀的檔，必須進版控。** 建 repo 時就檢查一次：
  `git check-ignore -v <每個閘門的產物路徑>`，命中就是漏洞。
  用 gitignore **白名單**制的專案特別容易中，因為漏收是靜默的。
- **指標要有兩個入口，人一個、機器一個。** 人讀的寫進 ADR；
  機器讀的寫進閘門自己的帳本，且 **key 的形狀必須讓閘門不可能把它當成一筆證據**
  （例如底線開頭、外加顯式 `parity: "unverified"` 欄位）。
  這是 §A4 那條律在**指標**上的實例：指標不是證明，兩者同形就會被讀成證明。
- **刪除獨立成一個 commit**，指標引用它的父 sha。混在別的變更裡，
  將來 blame 要花十倍時間才能還原「刪之前長什麼樣」。

**代價要寫明**：刪檔＋指標把證據存續綁死在完整 git 歷史上。
所以採用這個做法的專案必須同時登記：主分支不得重寫歷史、遷移不得 shallow clone。
沒有這條配套，這個方案就不成立。

## 🔴 `not_run` 的**理由**是一句待查的主張，不是事實（2026-08-07）

「缺產物＝未跑」那條擋住的是**沒留下痕跡**。還有一種更安靜的失效：**產物在、狀態欄
寫著 `not_run`、旁邊附了一個理由，而那個理由是錯的。**

實測：某科的門 §A 報告寫

```json
{"status": "not_run", "reason": "本 repo 未留該科官方答案 PDF（找不到 <路徑> 下的答案檔）"}
```

那些答案 PDF 一直都在，只是不在理由裡寫的那個路徑下。門的程式本身讀得好好的——當場跑，
3945 題一致、15 題不一致（15 題全是官方送分而題庫存 null）。也就是說：**該科全部答案
在此之前都是回推的、從未對過官方鍵**，而報告看起來是一份「已知情、已記錄」的待辦。

#### 為什麼這比「沒跑」更難發現

`not_run` ＋ 一個具體的理由，讀起來像**已經有人查過而且查清楚了**。它把「還沒做」
包裝成「做不到」，於是每一個後來的人都會跳過它——理由愈具體，跳過得愈心安。
「找不到檔案」這種理由尤其危險，因為它**看起來可驗證所以沒有人去驗**。

#### 閘門形狀

1. **`not_run` 的理由裡若提到路徑、檔案、缺料，就必須附一條當場可跑的驗證指令**
   （`ls <路徑>`／`test -f`），讓下一個人一秒鐘就能證偽它。寫不出這條指令的理由不准寫。
2. **`not_run` 要帶 `checked_at` 日期。** 沒有日期的 `not_run` 一律當作未查證，
   下一輪碰到就重跑一次，不要讀理由。
3. **重跑的成本若低於讀懂理由的成本，就直接重跑。** 本例整科重跑約四分鐘，
   而爭論理由對不對要更久。

> 一般化：**擋路的告示牌也要定期驗。** 一條寫錯的理由和一個真的阻塞，對後來者的
> 觀測效果完全相同，但前者不會自己消失。

## 🔴 修復腳本的成功訊息，必須由**讀回檔案**產生，不能由計畫產生（2026-08-07）

實測：一支回源修復腳本印出「✅ 已修 4 題」並逐題列出改動，**而檔案一個位元組都沒變**。
成因是 `plan()` 內部自己 load 了一份題庫、`apply()` 又 load 了一份，改的是前者、
寫出去的是後者。訊息是從**計畫**推出來的，所以計畫對，訊息就對。

這與「用內容驗、不用狀態碼驗」是同一條，只是發生在自己家裡：**工具回報自己成功，
和工具真的成功，是兩件事。**

#### 閘門形狀

- 寫檔後**重新讀一次那個檔**，對每一筆改動斷言新值（選項、題幹、答案字母都要），
  斷言過了才印成功訊息。
- 順帶一提：**寫回時要保持原檔的排版**。單行 JSON 用 `indent=1` 寫回去，
  4 筆改動會變成 7 萬行 diff，等於把改動藏起來，review 時沒有人看得見。

## 🔴 一道閘讀錯欄位不會報錯，它只會一直說沒事（2026-08-09，同一天兩次）

同一個形狀在一天之內出現兩次，依教訓畢業律升級為硬規則。

| 閘 | 讀了哪個欄位 | 該讀哪個 | 後果 |
| --- | --- | --- | --- |
| 孤兒圖引用 | 只有 `stem` | `stem` ＋ `passage` | 靜默漏抓 137 題（題組的圖引用寫在共用 passage） |
| 教訓寫回 | commit 的 `%s`（標題） | `%B`（整則訊息） | 誤放一個真的沒寫回的 commit（標題寫做了什麼，學習痕跡永遠在內文） |

兩次都不是判準錯，是**判準套在錯的欄位上**。這種失效沒有任何外顯症狀：
閘照跑、報告照印、抓到的數字看起來很合理，漏掉的那些長得跟乾淨資料一模一樣。
**能報錯的錯誤便宜，不能報錯的錯誤才貴。**

### 硬規則：新閘門的 selftest 必須有一個「payload 放在錯欄位」的反例

known-bad 樣本不可以全部把訊號放在最順手的那個欄位。至少要有一則，
它的訊號**只**出現在次要欄位（passage 而非 stem、body 而非 subject、
巢狀結構而非頂層），而該樣本必須被抓到。

這條的價值在於它逼你回答「這個訊號還可能停在哪裡」——那個問題如果不在寫
selftest 的當下問，之後就不會有人問了，因為閘門會一直回報通過。

### 推論：一道可以被**無關動作**滿足的閘，等於沒有閘

教訓寫回閘 v2 的判準是「skill repo 的最新 commit 晚於所有帶標記的專案 commit」。
在 skill 改一個錯字就會特赦當天全部債務——判準看的是**時間先後**，
而時間先後不承載「這則教訓有沒有被寫下來」的任何資訊。

改成**逐筆對帳**：每一筆債要嘛被一則 skill commit 以 `lesson-of: <sha>` 明確認領，
要嘛被一則 `no-lesson-for: <sha> <理由>` 明確豁免。判準問的是「這一筆結清了嗎」，
不是「有沒有人在那之後做過事」。

> 設計閘門時要問的第三個問題（前兩個是「讀不到怎麼辦」「錯誤值會落在哪個方向」）：
> **有沒有一個與這件事無關的動作，可以讓它通過？**

### 推論二：工單要用**目標狀態**算，不要用**狀態轉換**算（2026-08-09，一天內兩科都中）

孤兒圖引用那道門的 `--apply` 只把 `orphan_figref` 這條理由標給**這一輪從 `ok` 降下來**
的題。下游裁圖站照這條理由取件，於是「早就因別的理由待審、但同樣缺圖」的題
**永遠不會進工單**——它們已經在目標狀態裡了，所以不再發生狀態轉換。

| 科目 | 照「這一輪降了幾題」派工 | 實際「現在還缺附件幾題」 | 漏掉 |
| --- | --- | --- | --- |
| 藥師 | 239 | 263 | 24 |
| 分科測驗 | 186 | 401 | 215 |

分科測驗漏掉的比派出去的還多。而漏掉的那些**在驗收報表上完全看不見**：
代理把 239 題做完、雙向檢查自報 0/0/0、涵蓋率 100%——因為它的雙向檢查
也只掃它自己的工單。**一道範圍等於自己工單的雙向閘，數學上只能回傳零。**

兩條硬規則：

1. **工單的定義句必須是狀態，不是動詞。** 寫「現在仍缺附件的強證據題」，
   不要寫「本輪降級的題」。前者可以重跑到收斂，後者只在第一次跑對。
2. **雙向檢查的掃描範圍必須是整個題庫，不是這一輪的工單。**
   驗收時主控要自己重跑一次，代理自報的 0 只證明它的工單做完了。
   實測就是這樣抓到藥師那 24 題的：代理報 `ref_no_fig: []`，主控重跑得到 24。

> 設計工單時要問的問題：**如果這件事昨天做過一半，今天這份工單會不會漏掉那一半？**

### 推論三：跨紀錄的**引用**，要夾帶一段冗餘的自證（2026-08-09）

教訓寫回閘允許事後豁免：在任一個後續 commit 的內文寫 `no-lesson-for: <sha> <理由>`。
判準只認那個 sha。

實測翻車：作者想豁免**正在建立的這一筆**，於是在 commit 訊息裡寫
`no-lesson-for: $(git log -1 --format=%h)`——而 `git log -1` 在 commit **之前**求值，
回的是**上一筆**。那一筆是真的教訓，就這樣被靜靜豁免掉，閘門回報全綠。

這個 sha **格式正確、長度正確、確實存在於歷史裡**，只是指向錯的東西。
與「配額讀數回 0.0」是同一族：**wrong-but-legal 的值比讀不出來的值危險得多**，
因為每一道健全性檢查都會放它過。

治法是讓引用**帶著它自己的證明**：豁免格式改成

```
no-lesson-for: <sha> ~<被豁免 commit 的主旨片段>~ <理由>
```

閘門拿 sha 去查主旨，對不上就拒認。一段冗餘資訊，把「寫錯」從**合法**變成**可偵測**。

> 一般化：**任何用識別碼指向另一筆紀錄的地方（sha、qid、檔名、外鍵），
> 都要問「寫錯一個仍然合法的識別碼，會發生什麼」。**
> 答案若是「安靜地做錯事」，就補一段冗餘欄位讓它自證。

#### 但先問一句：這裡真的需要識別碼嗎？（2026-08-09 第二次修正）

上面那條是對的，卻不是最省的。**這個事故的真形不是「sha 抄錯」，
是「想指涉一個還不存在的紀錄」**——作者要豁免的是**正在建立的那一筆 commit**，
而它在寫訊息的當下還沒有 sha。不存在的東西沒有名字，於是他用
`$(git log -1)` 去猜，猜到上一筆。

所以更好的形是把指涉整個拿掉：**讓豁免長在被豁免者身上，身分由包含關係決定。**

```
# 常態：豁免這一筆 → 寫進它自己的內文，不寫 sha
no-lesson: 純派工與環境安裝，無可推廣判準

# 罕見：豁免已推送的舊 commit → 才需要識別碼，且錨詞兩個字就夠
no-lesson-for: d0d3b24 ~多選~ 這條已由 lint 的 canary 覆蓋
```

**沒有名字，就沒有名字可以寫錯。** 冗餘自證退居第二軌，只服務真正需要跨紀錄指涉的少數情況，
而那時錨詞只要有鑑別度即可，不必複述整段主旨。

> 順序固定為三問：
> 1. **能不能不用識別碼**（把資訊放進被指涉者本身、用包含或鄰接關係定位）？
> 2. 不行的話，**寫錯一個合法識別碼會怎樣**？
> 3. 會安靜出錯的話，才補冗餘自證，而且**只補到夠鑑別為止**。
>
> 先做第 1 步的價值不只是省字：它讓那一整類錯誤**沒有語法可以表達**，
> 而第 3 步只是讓錯誤變得看得見。

#### 同一晚的第三次：`git add <被忽略的路徑>` 是靜默 no-op

`.gitignore` 寫成**白名單**（先 `*` 全擋、再逐一放行 `*.py`／`*.sh`⋯）是對的設計——
黑名單漏一種是靜默進庫，白名單漏一種只是少收一個檔、看得見。

但它有個副作用：**`git add path/to/ignored.json` 會成功返回、什麼也不做**，
不警告、不非零退出。於是 commit 訊息可以理直氣壯地宣稱「同時落盤了題庫」，
而那個檔從頭到尾不在版本控制裡。實測 2026-08-09 一晚犯三次。

這與 §A1 那個 `pdf.name.replace("試題","答案")` 是**同一個東西**：
**靜默 no-op 讓「我沒做這件事」偽裝成「這件事做了」。**

判準：**凡是「把東西加進某個集合」的操作，都要回頭確認它真的進去了。**

```bash
git add "$f" && git diff --cached --name-only | grep -qF -- "$f"   || { echo "add 是 no-op（多半被 .gitignore 擋了）：$f" >&2; exit 1; }
```

順帶一條紀律：**跑批中的 staging 題庫本來就不該進 git**（它每小時都在變、且是產物）。
它的保命方式是**盡快併進 `_dev/data/`**（那條路徑才在白名單裡），
不是 `git add -f` 硬塞。看到自己想 `-f`，通常表示該做的是併庫。

##### 更正：訊號本來就在，是我自己把它靜音的

追下去才發現 `git` **本來就會**印「The following paths are ignored by one of your
.gitignore files」，`git add` 與 `git add -A` 都會印。三次沒看到的真因是——
指令尾巴被加了 `2>/dev/null`，用意是消掉「路徑不存在」的雜訊，順手把安全警告一起蓋掉。

**所以這一類失敗有兩個來源，而第二個更常見**：不是工具沒警告，是執行者為了讓輸出乾淨
把警告關掉了。`2>/dev/null`、`|| true`、`-q`、`--quiet` 都是同一個動作。

> 判準：**消雜訊的重導向，只能加在你已經逐條看過那些雜訊之後。**
> 還沒看過就先加 `2>/dev/null`，等於預先同意所有你還不知道的錯誤。
> 真的很吵，就過濾**已知的那幾行**（`grep -v 'known noise'`），不要整條 stderr 丟掉。

這也改變了守衛該放在哪：**放進一個執行者蓋不掉的通道**。專案的作法是 PostToolUse hook
獨立重探（`git check-ignore` ＋ `git ls-files`），不解析指令輸出，所以 `2>/dev/null`
對它無效。

#### 什麼時候該用 hook，什麼時候不該（三條全真才裝）

hook 便宜但會累積，累積到一定量就開始干擾連續工作。判準（2026-08-09，fable 裁決）：

1. **訊號可被執行者在同一次呼叫內抑制**（重導向、旗標、改路徑就能消掉）。
2. **沒有更晚的單一必經入口**能攔到同類失敗（沒有 fail-closed 的 dispatch／publish／
   `--apply` 可以掛）。
3. **零 token 機械判定**（exit code、regex、檔案系統事實就夠，不需語意理解）。

附加規則：**自己擁有的程式碼出的錯，修程式，不包閘。**

拿這三條篩今晚七個實測失敗，只有 `git add` 那一項三條全真；其餘不是有更晚的必經入口
（派工閘、紅隊入口），就是本來就該修在自己的程式裡。**結論是零個新 hook。**

數量上界：**每個工具事件至多一支會擋的 hook，全專案會擋的 hook ≤ 3**；
新裝必須引用至少一次實測失敗，禁止「以防萬一」型；`/loop` 連續運行中誤擋超過每週一次
即降級為入口閘或移除。

> 「模型變聰明就不需要 hook」對一半：會隨智力歸零的是**判斷型** hook
> （官方明列的反模式就是「用 hook 複製模型的決策邏輯」）；不會歸零的是**觀測保證型**——
> **再聰明的模型也讀不到被 `2>/dev/null` 消掉的訊號。智力修不了觀測通道的洞。**

### 推論四：閘門把自己的補救說明吞掉，比擋不下來更難查（2026-08-09）

新寫的 fail-closed 閘門長這樣：

```zsh
echo "✗ 靜態頁落後於題庫，共 $total 個檔：" >&2
printf '%s\n' "$dirty" | head -5 >&2          # ← 這一行
echo "   先 commit 這些檔案再發佈——發佈取的是 HEAD:_dev" >&2
return 1
```

實測擋下來了，但使用者看到的是**一句沒有下文的錯誤**，腳本退出碼 **141**。

成因：`set -eo pipefail` 之下，`head` 讀滿五行就關掉管線 → `printf` 收到 `SIGPIPE`
→ 整條管線回 141 → `set -e` 當場中止函式。**第三行的補救指示根本沒有機會印出來**，
`return 1` 也沒有執行到。閘門擋對了，但它把「接下來該做什麼」連同自己的退出碼一起吞了。

這是靜默 no-op 家族的另一員（前面幾位：`pdf.name.replace()`、
`git add <ignored>`、把 `2>/dev/null` 接在會警告的指令後面）。共同形狀是
**執行者親手消掉了自己需要的訊號**，而消掉之後的畫面跟正常一模一樣。

修法：不要在 `set -eo pipefail` 的閘門裡用 `… | head -n`。用 here-string 迴圈，
順便滿足「不得靜默截斷」——列了幾筆、還有幾筆沒列，都要說出來：

```zsh
local line shown=0 total
total="$(wc -l <<< "$dirty" | tr -d ' ')"
while IFS= read -r line; do
  echo "   $line" >&2; shown=$((shown + 1))
  [ "$shown" -ge 5 ] && { [ "$total" -gt 5 ] && echo "   …另有 $((total - 5)) 個未列出" >&2; break; }
done <<< "$dirty"
```

**驗收要看退出碼，不要只看有沒有擋下來。** `./gate; echo $?` 應該是 1；
是 141／143 就代表中止點不在你以為的那一行。

### 推論五：閘門的樣式若比對得到自己的解釋註解，它就是恆真／恆假的（2026-08-09）

那道跨檔一致性斷言的第一版是：

```python
assert "Disallow: /data/" not in render_robots()
```

它**立刻紅了**——而 `render_robots()` 產出的檔案裡根本沒有那條指令。
命中的是我為了說明「這裡刻意沒有 Disallow」而寫的那段註解。

反過來想更危險：如果當時那段註解沒寫，這道斷言會一路綠燈，而它綠的理由
與它想驗的事情無關。**一道會被自己的說明文字觸發的樣式，也會被別的無關文字放過。**

修法是**先把格式解析乾淨，再比對語意**——robots.txt 的 `#` 之後對爬蟲無效：

```python
rb_rules = [ln.split("#")[0].strip() for ln in rb.splitlines()]
assert not any(r.lower().startswith("disallow") and "/data/" in r for r in rb_rules)
```

**硬規則（與 §A3.1 的兩側驗證同一條）**：新寫的判定式必須在 **known-good 與
known-bad 兩種輸入各跑一次**，兩次結果不同才算數。

```
known-bad（真的有指令）    → True
known-good（只在註解裡提到）→ False
```

兩次跑出同一個答案的判定式，不管答案是什麼，它驗到的都不是你要的東西。

## §G 門查不到東西時，三種原因長得一模一樣（2026-08-13 實測，藥師上線那輪）

一道門回報「這批我驗不到」，底下可能是三件完全不同的事，而**它們的輸出字串常常
是同一句**。分不開的代價不對稱：判成「資料真的缺」會把成本推給人（回源重抓、
甚至跑一趟公部門），判成「工具沒找到」則只要改幾行程式。

| 真實原因 | 該做什麼 | 那天實際發生的 |
| --- | --- | --- |
| 資料真的不在 | 回源重抓 | —— |
| 工具的定位假設壞了 | 改工具 | `qid.split("_")[1]` 取場次碼。6 科的 qid 是 `113_113030_…` 所以成立，藥師多一段考試名前綴 `pharmacist_101_101030_…`，split[1] 拿到年份 → **整科 13,050 題回報「無答案 PDF」**，而 174 份答案 PDF 就躺在 `_raw/` 裡 |
| 命名隨時間改過 | 補對照表 | 舊卷科目寫「藥劑學（包括生物藥劑學）」、現行寫「藥劑學與生物藥劑學」。**改寫過的名字沒有任何寬鬆比對救得回來**（加後綴的那些反而自己就中了），只能列表 |

三條可操作的規則：

1. **識別碼靠形狀定位，不靠位置。** 場次碼的識別特徵是「六位數」，不是「第二段」。
   位置假設會在下一個命名慣例出現時安靜地錯。
2. **每一種「驗不到」都要有自己的計數欄。** 把「查無試題 PDF」與「無答案 PDF」
   合成一個數字，就是把「改工具」與「回源重抓」合成一個結論。
3. 🔴 **`unverified` 這類欄位要逐一列進 `status` 的判定裡。** 少列一種，
   那種未驗就會被算成通過。

## §H 彙整器不可以把量過的結果降級成「沒跑」

同一輪實測：`verify_answer_key.py` 剛把門 A 驗成「13,050 題全一致」，
接著跑彙整腳本 `gate_report.py`，整筆被覆寫成 `status: "not_run"`——
理由是**彙整腳本自己跑不了門 A**。

一個彙整器用「我沒跑」蓋掉「別人跑過了」，比不寫還糟：它銷毀證據，
而且**銷毀後的樣子與從來沒人跑過完全相同**。

判準：**彙整器對每道門的權威性是有限的，越權的方向只能是保守。**
合併規則寫成「新的是 not_run 而舊的不是 → 保留舊的」，並在保留時留一個
`kept_by` 欄位讓人看得出發生過什麼。否證測試要驗**雙向**：
量測不可被降級、而 not_run 可以被後來的量測取代。

（這與 §缺產物＝未跑 是一體兩面：那條講「沒跑要留得下痕跡」，
這條講「跑過的痕跡不可以被別人擦掉」。）

## §I 衍生物的「新舊」要用內容指紋判，不要用檔案的 commit 判（2026-08-18 實測）

詳解、關聯、裁切圖這類**衍生物**都有同一個問題：它比它所依賴的來源舊了沒有？
最順手的判準是「來源檔的最後 commit 晚於衍生檔的最後 commit」。**那個判準是錯的，
而且它的錯法特別難看見**——它不是漏抓，是**在你做對事的那一刻把帳一起銷掉**。

### 形狀

一個檔的 commit 是**全檔共用的一個時間點**。`explanations.json` 裡有 981 則詳解，
其中 115 則今天重寫過、866 則沒有。只要 commit 這個檔一次，**全部 981 則的時鐘一起歸零**。
於是：

```
merge 115 則   → 閘門：44 則過期   ✅ 誠實
commit         → 閘門：0 則過期    ❌ 那 44 則一個字都沒動
```

第二行不是 bug 造成的，是**判準的定義**造成的。而它出現的時機恰好是「你剛完成一批
修復、心情最好、最不會去質疑綠燈」的那一刻。

### 判準

**每一則衍生物,在生成當下,蓋一枚它所依賴那筆來源的內容指紋**
（只取衍生物真正依賴的欄位，見 §A3 的欄位清單紀律）。驗證時只跟現況比：

```python
stale = [qid for qid, stamp in stamps.items() if stamp != fingerprint(current[qid])]
```

與任何 commit 無關 ⇒ commit、搬檔、改路徑、rebase 都洗不掉。

**未蓋章的要單獨計數並印出來，不得計入通過**——不知道 ≠ 沒問題（§A4 同一條）。
指紋會隨著每一批 merge 累積，未蓋章數只會往下走；把它印在報表上，
它就自己變成一條進度條。

### 🔴 蓋章工具的「來歷」參數不可以有預設值

同一輪內踩到的第二個坑，比第一個更值得記：蓋章工具需要知道「未蓋章那些是對著哪一版
來源寫的」。第一版把它預設成「來源檔的最後一個 commit」——**那個值在第一次
merge+commit 之後就變成現況**，於是第二次跑會拿現況幫所有舊則子蓋章，
把時鐘全部歸零。**用這道門的預設值，重建了這道門要擋的病。**

> **一般形式：從可變狀態算出來的預設值不是預設值，是藏起來的參數。**
> 它只在工具還沒被用過的那一刻是對的，而那正是最不需要它的時候。
> 改成必填，並在錯誤訊息裡寫明該怎麼查、以及「要取那批實際生成當時的 commit，
> 不是最新的那個」——錯誤訊息是這條規則唯一會被讀到的地方。

### 它第一次跑就抓到什麼

換成指紋之後第一次跑，數字比預期多一則。那一則被排除在重生成清單之外，理由是
「上一批有它的可用產出」；而上一批整批決定不 merge。**兩個各自正確的決定之間掉出一題**，
舊錨點永遠看不見它——因為它從來不是「某個檔比較舊」，它是「沒有任何一批負責它」。

## §J 判定用一組輸入、動手用另一組，等於那道閘不存在（2026-08-18 實測）

數學重建器裡最貴的一個 bug：`classify()` 用**過濾過**的取字窗判「這條線上方有一個
乾淨的分子」，`resolve()` 卻用另一個 16pt 的**原始窗**去**消耗**字元。

判定說「是分數」，消耗把 16pt 內的整行散文塞進去，於是合成出
`\dfrac{12-14題為題組}{a,b}`；而且那些字被吃掉之後，**下一行的散文從此殘缺**——
一個錯誤同時製造了兩處毀損，其中一處還在別的題目上。

實測規模：19 卷 531 帶裡，「拒收理由為空、會被寫入」的 229 帶有 **78 帶（34%）**
含機檢看得見的毀損，而毀損長相全是「讀起來幾乎像對的」。

> **一般形式：一道閘的防護力，等於它與實際動作之間的距離。**
> 判斷用 A、動手用 B 的時候，A 上的每一道過濾在 B 上都等於沒寫。
> 修法不是把 B 的窗也調成 A 的（那只是把兩份說明書調成一致，下次改一邊照樣分岔），
> 而是**讓判定回傳它所依據的那組東西，動作只能用那一組**。
>
> 這條與 §398「一道閘讀錯欄位不會報錯」是同一個病的兩面：
> 前者是閘讀了不存在的東西，後者是閘讀對了、但動手的人讀的是別的東西。
> 兩者都不會報錯，都只會一直說沒事。

**自檢要走實際路徑**：若自檢自己組出 up／dn 再餵給 `classify()`，它就檢不到這一類
bug——那正是本案的自檢通過、資料卻毀損 34% 的原因。自檢必須呼叫與生產同一支
「取字 → 判定」的函式。

## §K 硬失敗要挑對例外型別，否則失敗半徑會擴散到整批（2026-08-18 實測）

「未登錄的 PUA 一律中止，不預設不略過」是對的規則，但它原本丟的是 `SystemExit`
——那繼承自 `BaseException`，**穿過呼叫端的 `except Exception`**，於是一顆字殺掉
整個跑批（實測 19 卷有 30 帶因此連跑都沒跑到）。

改成 `ValueError` 之後，仍然是硬失敗、仍然不預設不略過，只是**失敗的半徑從
「整批」縮回「這一題」**，而那一題會帶著具名理由進拒收清單、被人看到。

> 一般形式：「要不要吞掉錯誤」與「這個錯誤會炸掉多大範圍」是**兩個獨立的決定**。
> 前者的答案通常是「不吞」，但那不蘊含後者要選最大值。

## §L 守恆閘擋不住「字還在，但沒人看得懂」（2026-08-18 實測）

重建器的 dry-run 畫面上，`|x-a|≤b` 印成 `x-ab`。看起來像掉了三個字。

實際上一個字都沒掉：`≤`（U+F0A3）、`α`（U+F061）、`β`（U+F062）不在造字譯碼表裡，
於是**原封不動穿過去**——而終端機沒有那些字形，所以它們是**隱形的**。
字元多重集守恆閘當然全過，因為守恆得好好的。

補一道閘就抓出來了：**輸出不得殘留 U+E000–U+F8FF 的任何字元**。

> 一般形式：守恆類的閘門守的是「量」，不是「意義」。一個沒被翻譯的符號、
> 一個掛錯位置的字、一個被誤讀成別的字的造字——這些在多重集上全部合法。
> 每一道守量的閘，都要配一道**守值域**的閘：輸出裡不准出現「我們自己都
> 還沒定義它是什麼」的東西。

這一道也是把不可見變可見的標準手法：**失敗如果沒有外觀，就給它一個外觀。**
未登錄造字在畫面上是空白，在閘門上是一個具名的拒收理由與一串碼位——
後者才有人會去處理。

## §M 渲染器設成「不要拋錯」，就等於把它的錯誤回報關掉（2026-08-18 實測）

前端用 KaTeX 的 auto-render 渲染題幹裡的 `\( … \)`，設定是 `throwOnError: false`
——那是對的選擇：一條壞公式不該讓整頁作答介面爆掉。**但它的代價是：
壞公式會安靜地渲染成一行紅字留在題目裡，而「上線沒出事」與「公式是對的」
在觀測上完全一樣。**

補法是把渲染器**拿到 build 期再跑一次，這次設 `throwOnError: true`**：

```bash
node _build_features/katex_lint.js <exam…>   # 逐條編譯題幹／選項／passage／詳解
```

全站首跑就抓到 5 處正在線上壞掉的公式（`\overparen`、`array` 的 `@{}`／`\cline`／
`\multicolumn`——都是這一版 KaTeX 不支援的巨集）。它們存在多久沒人知道，因為
沒有任何東西會叫。

兩個實作紀律，兩個都踩過：

- **必須用上線的那一份渲染器**（`_dev/web/katex/katex.min.js`），不是另外裝一個。
  版本不同支援的巨集就不同——拿別的版本驗過，證明的是別的網站不會出事。
- UMD 打包的函式庫在 CommonJS 底下走 `module.exports`、**不會掛到 global**。
  只讀 global 的話拿到 `undefined`，而它的症狀是「每一條公式都失敗」——
  看起來像資料全壞，其實是載入方式錯了。兩條路都接住。

> 一般形式：**凡是為了健壯性而吞掉錯誤的地方，都要在別處補一個會出聲的版本。**
> 執行期吞錯是對的（使用者不該因為一條公式看不到題目），但**吞錯的那一刻，
> 你也失去了「這裡有錯」這個訊號**——它必須在別的時間點、用別的設定重新取得。

### 推論：`Array.isArray(x)` 這種型別判斷，false 的意思是「跳過」，不是「有問題」（2026-08-18 實測）

同一個形狀的另一半，而且更難發現，因為這裡連 `throwOnError` 這種可疑的設定都沒有。

前端畫「答題架構」的條件是 `if (Array.isArray(ref.frame) && ref.frame.length)`。
資料有兩種 schema：一科寫成陣列（292 列），四科寫成字串（329 列）。
`Array.isArray` 對字串回傳 false → **整個區塊不被建立**。不是空白、不是報錯，是不存在。
於是 329 列的答題架構在線上消失了好幾個月，而且：

- 沒有 console 錯誤（沒有東西出錯，只是沒有東西發生）。
- 沒有版面破洞（區塊本來就是選擇性的，缺了看起來像「這題沒有」）。
- 資料層全綠（欄位在、內容對、JSON 合法）。

**「沒有顯示」與「沒有資料」在畫面上同形**——這是本檔反覆出現的那個病，換了一件衣服。

判準：**凡是用型別／存在性判斷決定「畫不畫」的地方，都要有一份「渲染器認得哪些形狀」
的清單，並用一道閘檢查「資料的形狀 ⊆ 清單」。** 渲染器多認一種就回來改清單；
資料多出一種而清單沒有，閘門要擋。範例實作：`check_essay_ref.py`。

### 推論二：閘門要窄到「亮起來就代表真的有事」（同日，寫上面那道閘時當場踩到）

那道閘第一版把「渲染器不認得的欄位」一律報出來，結果 `confidence` 與
`needs_verification` 這兩個**刻意不顯示的稽核欄位**讓 621 列各噴兩筆，共 1,242 筆紅燈。

一道永遠紅的閘，兩天內就會被無視——**它的訊號值是零，但它的維護成本不是零**，
而且它會讓「真的出事」那一天長得跟前 30 天一模一樣。
**寬到會誤報的閘比沒有閘更糟。** 新閘上線前先在真實資料上跑一次：
不是為了看它抓到什麼，是為了看它**不該抓的有沒有安靜**。

## §N 不變式帶著它的適用範圍；範圍掉了，規則看起來還是規則（2026-08-18 實測）

專案文件寫著資料檔的不變式：「單行 JSON、無縮排、無尾換行」。我照做，把 `essays.json`
寫回去——**內容全對、格式全錯**：一個改 10 個字串的修正變成 **14,191 行刪除的 diff**。

那條不變式的原文點名的是 `bank.json` 與 `explanations.json`。`essays.json` 不在其中，
而且它**根本沒有統一格式**（實測：四科 `indent=1`、三科單行）。我讀到規則、記住規則、
執行規則，唯一漏掉的是它句子裡的主詞。

同形的前例就在同一個專案裡：「恰 4 選項」是**四選一考科**的不變式，不是全站的——
把它套到五選一的學測卷上，486 題正常題被降級、162 題的 `options[0]` 被併進題幹。

- **寫規則時**：主詞寫進句子裡，不要寫「資料檔一律…」這種省略主詞的句型。
  能列舉就列舉；不能列舉就寫判準（「凡 X 者」）。
- **讀規則時**：套用前先問「這條的主詞包含我手上這個檔嗎」，**去量，不要推定**。
- **機器閘**：真正該擋的不是「用了哪一種格式」，是「**順手把整份檔案重新排版**」。
  所以閘門跟 `git HEAD` 那一版比格式，不挑一種正確格式。反例要雙向都測
  （A→B 與 B→A），否則你只證明了閘門討厭其中一種。

> 一般形式：**一條規則的適用範圍，跟規則本身一樣是規則的一部分。**
> 範圍是最容易在轉述中掉的部分，因為它讀起來像背景，不像指令。

## §O 只報 `fail` 數的閘門，分不出「都對」與「都沒看到」（2026-08-18 實測）

§M 講的是渲染器把錯誤回報關掉；這一則是同一根因的**分母版**：閘門看得見的
樣本數自己會縮，而報表只印分子。

實測：法條錨定包的 `--verify` 三科都印「0 fail」——因為註冊表寫官方全名
「中華民國刑法」、詳解寫俗名「刑法」，**21% 的引用（1,741 筆）從來沒被檢查過**。
補上俗名解析與缺的法規後，看得見的引用 7,205 → 9,292，並立刻冒出 1 筆真 fail
（而且那是解析器的 bug，不是資料的）。

- **閘門的 summary 一定要同時印分母**（看了幾筆），不能只印 fail 數。
- 分母掉下去比 fail 冒出來**更難察覺**，因為它長得像「這批資料很乾淨」。
- 比對法則：把分母跟上一次的數字比，**數字變小要跟 fail 變大一樣醒目**。

完整判準（含冒名者守衛、需求量該往哪一層量、否證怎麼做）在
`reviewer-input-parity.md` §「字面比對的查核器」。

## §P 閘門的回傳值被丟掉，畫面是紅的、行程是綠的（2026-08-19 實測）

「缺產物＝未跑」講的是**產物不存在**；這一則是它的另一個形狀：**產物存在、
判斷正確、訊息也印出來了，只是沒有人接**。

實測（`anchor_pack.py --check`）：延後施行的條文在生效當天，修正日期一個字都不會動，
所以另有一道 `checkCommencement()` 專門看 `effective_date`。它寫好了、邏輯對、
會印 `🔴 延後施行已生效但包更舊，須重建`。接線是這一行：

```python
commencement = reportCommencement(pack, today)   # 回傳值再也沒被用到
...
print("all ... are up to date")
return 0                                          # ← 修正日期全對就回 0
```

**月維護是看 exit code 決定要不要重建的**，所以那道檢查對呼叫它的流程等於沒跑。
人在終端機前會看到紅字，CI／排程不會。

- **判準**：一道閘門的存在證明不是「它會不會印」，是「它的結論走到哪裡」。
  寫完就往上追一層：**誰讀這個回傳值？沒有人讀＝這道閘不存在。**
- 這種洞**不會被 `--selftest` 抓到**，除非測的是接線本身。所以自測要有一條
  斷言回傳值（`report(...) == 2`／`== 0`），而不是只斷言內部分類正確。
- 靜態檢查抓得到的形狀：**被指派卻從未被讀取的區域變數**。凡是變數名叫
  `result`／`status`／`errors` 而後續沒出現，都要當成閘門斷線的候選。
